# Proposal

## Why

mpb 已恢复 Android/Windows CS 握手，但服务器改枪编号后，客户端库存与枪表仍可脱节，表现为新枪不扣弹、最后取出的皮肤枪错误以及换弹回到旧弹量/耐久。玲兰共享库存与堆叠进一步暴露同一套实例身份契约的边界，需要从事务和同步修复，而非逐个遮住显示症状。

## What Changes

- 服务器成功提交枪械事务后，发布协调的枪记录与槽位身份变化；普通移动不改号，真正复制的改号必须同步。
- 客户端预测与权威镜像分离，并按会话、枪身份及选择版本清理/核对；完善缺失更新恢复与迟到消息处理。
- 开火、换弹等输入关联预期枪身份；短时断流不无限沿用旧按住状态。
- 修复客户端下包时房主漏播世界声音，保留拥有者预测与观察者各一次播放。
- 建立我们侧第三方库存能力检查，保留已有代理去重，处理 CS 独立实例的堆叠风险，验证整理/补位/死亡保物和共享频道。
- 记录需要玲兰/平台处理的个人箱归属、频道保存及网络桥边界，提供可审核复现，不擅改第三方包。
- **BREAKING（网络，条件性）**：若消息结构变化，应提升并协商协议/能力，旧客户端明确拒绝或采用被验证的兼容方案；不能让双方按不同结构解析。保存布局 6、记录 schema 7 和历史编号语义保持不变。

## Capabilities

### New Capabilities

- `weapon-state`: 枪械实例身份、库存、记录、预测与操作的一致性。
- `world-audio`: 下包等世界声音在拥有者、房主和其他观察者上的一次性呈现。
- `inventory-compatibility`: 自定义实例枪与共享/个人/机器库存的保真移动、堆叠约束和能力边界。
- `neutral-bandits`: 自然/召唤匪默认中立，局部受击后共同攻击同一攻击者。
- `subworld-travel`: 跨子世界携带完整枪记录与稳定身份，安全重映射和往返。
- `platform-notices`: 正常平台兼容诊断仅入日志，玩家仍收到真正不可用提示。

### Modified Capabilities

无既有 OpenSpec 基线。将现有约束和新增要求共同形式化，保留现有正确行为，不以 ADDED 为理由重写成熟功能。

## Impact

2026-10-02 mpc3实测增补：实际包ACK/Hit同号已复现，属于本change未通过验收的回归；新增共同报复规则、子世界迁移覆盖和玩家正常提示移除，详见当前规划§10与最新诊断。角色AI及旅行提供方生命周期属于新增影响面；不以修改全局枪表或放松完整性校验代替修复。

主要入口：`ScGunMutation`、`ScGunInventoryJournal`、`ScInventoryTransaction`、`ScNetMirror`、`ScNetGuns`、网络适配器、`SubsystemScC4`、库存/玲兰兼容层。跨消息协议可能影响所有联机玩家；Full/Lite/Agents 的可通信身份需一致。

实现和验收规划见 design/tasks/verification。用户此次授权为规划；交给 VPS 的实施指令决定执行范围。实际未来联机玲兰包尚未提供，不能承诺未测试版本兼容。
