- `DeathmatchRulesCheck`：状态转换、计时、权限、公式/数据转换；使用生产函数，不能在断言里复制同一算法算 expected。
- `DeathmatchLifecycleCheck`：实际引擎伤害/死亡钩子、禁操作、库存持有者/原生序列化、两轮存读和故障注入。伪死亡必须验证钩子真实先后，不只纯状态枚举。

### 9.2 引擎钩子顺序（任务 1.1）

依据：平台 1.9.3.2 程序集的反编译（`Attackment`、`ComponentHealth.Injure`、`Injury.Process`、`Project` 构造）。**这是读代码得到的结论，没有在运行的游戏里打点确认。**

1. CS 攻击对象（`BulletAttack` / `KnifeAttack` / `AreaAttack`）→ `DisableFriendlyFire()`：有模式时问 `ScMode.MayHurt`，无模式走世界原规则。
2. `CalculateInjuryAmount()`：目标由模式结算时返回原始威力（不叠加 CS 护甲、衣物、抗性）。
3. `ComponentHealth.Injure` → `Injury.Process()`：先调用模组钩子 `CalculateCreatureInjuryAmount(injury)`，**之后**才判断 `Amount > 0 && (IgnoreInvulnerability || !IsInvulnerable)` 并扣血；再之后才是 `OnCreatureDying`、`Die()`、掉落。
4. 附属包在第 3 步的钩子里做唯一结算：非致命 → 把 `Amount` 改成“引擎血量应减少的量”并置 `IgnoreInvulnerability`（创造世界也生效）；致命 → `Amount = 0`，引擎血量不到 0，`OnCreatureDying`/`Die`/掉落都不会发生，死亡由模式处理。
5. 没有攻击对象的伤害（坠落、世界火、溺水、虚空）走同一钩子，按“只扣血、不计甲”结算。
6. 存档：`Project` 构造只实例化有数据库模板的子系统组；没有模板的组被当作普通值保留、不建子系统（L 检查的“引擎解析器”一项直接调用了 `ProjectData`）。
