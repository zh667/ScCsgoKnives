# 详细设计：专用世界个人死亡竞赛

## 0. 文档性质与优先级

这是一份待实施设计，不是已实现能力。优先级：用户已确认要求 → AGENTS.md 当前规范 → 本设计/specs → 历史参考。用户已确认的问题不再提问；工程默认值见 §2，遇到实际证据需要改工程细节时记录原因，不能削减覆盖范围。阶段交付不等于将爆头/穿烟、手机 HUD 或 CS2 武器行为推到“以后再做”。

## 1. 目标、边界与仓库决定

安装独立 DM 附属包，在玩家专门创建/导入的竞技地图中运行个人混战。地图搭建与比赛是两种权限/状态。安装包本身不把任意生存世界改成竞技世界，不自动迁移生存装备；竞技世界之间也不共享背包。

推荐先在现有仓库新增 `src/ScCsgoDeathmatch`，发行独立 `.scmod`。依赖核心的稳定接口，不反射私有字段、不复制完整枪械控制器，不硬依赖探员 DLL。Full 内置探员和 Lite 可选探员的模型/外观差异通过能力接口解决。

新 GitHub 仓库不能消除核心伤害/存档接口依赖。只有独立维护团队、独立发行周期、接口已可独立构建，或实际文件所有权冲突无法隔离时才拆仓。届时保留核心通用接口于原仓库，附属玩法/测试在新仓库，使用有版本的契约引用和验证矩阵；不双向复制同一源码、不建立源码同步目录中的嵌套 Git。公开范围、名称、许可/资源分发清单在发布前具体核对。用户允许必要时另开仓库，本轮尚无该必要，仅规划，不创建远端仓库。

## 2. 已定体验与工程默认值

下列“建议默认”是实现可采用的初值，不声称用户给了这些数字，也不声称来自 CS2。

| 项目 | 决定/默认 | 归属 |
|---|---|---|
| 模式与范围 | 专用竞技世界，个人混战 | 用户确认 |
| 枪与外观 | 所有现有支持的型号/皮肤/刀型开放，免费；外观不增伤 | 用户确认 |
| 配装 | 初次购买；存活交战改下一命；死亡镜头/准备区可改；保护期可立即改 | 用户确认 |
| 血甲 | 每次复活 100 HP / 100 AP / 头盔 | 用户确认 |

| 死亡镜头 | 约 2 秒，准备好后复活；不会把网络加载时间算进 3 秒 | 体验已确认，时长为建议默认 |

| 自杀/环境死 | 死亡 +1，无人击杀加分；越界按自杀处理 | 工程默认 |
| 人数 | 建议 2–16，受实际平台上限约束；1 人可进练习但不产生正式局成绩；不补机器人 | 个人赛已定，其余默认 |
| 投掷物 | 默认关闭，房主可开放现有六类竞技投掷物，建议每命合计≤3、闪光≤2、其他各≤1 | 沿用用户接受的可选装备建议；数量为默认 |

| 排名/StatTrak | 击杀分决定名次；计数器显示本局该玩家该型号确认击杀数，复活/换皮肤不清零，下局清零 | 用户接受建议 |

初次未选装备不强发手枪/刀。准备页可空选后等待，也可明确确认空装练习/参赛，不把缺选静默换成默认套装。选过的完整配装跨命重买，包含主副武器、刀型/皮肤、计数器外观、Zeus、可选投掷物、消音/开火模式等支持选项；消耗状态按新命规则恢复，上一命半途换弹/连发/蓄击不得继承。

## 4. 专用世界与竞技区域

### 4.1 地图作者流程

1. 玩家新建竞技地图世界，或导入其自己准备的竞技地图；房主显式在设置中启用 DM。启用前展示该世界将按竞技规则运行，不自动选择已有生存世界。
2. 在“地图编辑”状态设置两个区域角点（XYZ），以及准备区/观战位置。比赛期间禁止修改几何区域、枪械规则和局长，修改草稿下局生效。
3. 放置/删除候选复活标记：位置、朝向、可选标签；标记只在编辑预览中可见，不需要永久占用地图方块。
4. 验证边界、可站立空间、地面、危险区、点位数量和加载预算。重复点/所有点挤在一处提示作者改善；至少要有两个不同合法点才能开始多人比赛。
5. 保存地图配置。导出地图时保留其点位/规则，新的比赛生成新的会话/局标识，不继承连接编号。

一世界一活动竞技区域足够，暂不引入多房间服务器框架。房主权限从平台会话身份取得，客户端传入“我是房主”无效。所有参赛者互为敌人，与 CT/T 外观无关，观战者/编辑者不参与攻击和计分。

### 4.2 隔离

竞技库存走模式管理，不走生存制作、开局赠品、材料消耗或升级；禁止参赛者丢弃、拾取外来装备、放入容器、复制、死亡掉落和跨世界携带。进入普通世界必须解除模式规则/监听/HUD/输入，不能把全局静态枪表改了再“切回”。

地图编辑保留房主搭建能力，比赛参与者不获得创造飞行/原版无敌/方块破坏。专用地图禁用比赛期间地形破坏、随机生物/匪刷新及非竞技增益，避免火/爆炸拆图；不要为了关闭这些功能去改第三方包。对绕过接口直接改血或强制传送的第三方模组，只对实际验证的组合承诺兼容；已知不兼容组合阻止开始竞技，允许世界安全加载和编辑。

准备/观战不得无限拖住全局比赛或占无敌肉盾位置；这些玩家不可伤害、无阻挡战斗碰撞且不作为选点敌人。全部离开时结束/中止本局并标记原因，不能让重连领取上一局重放的奖励。

## 5. 配装与轮盘交互

### 5.1 轮盘结构

采用用户所说的 **CS 风格轮盘**，不强行改成 CS2 矩形购买页，也不声称 CS 1.6 的界面就是轮盘。建议六个大扇区：手枪 / 冲锋枪 / 步枪与狙击 / 重型（霰弹、机枪）/ 刀具 / 装备（Zeus、允许的投掷物）。中心返回/关闭，必要时第二级按型号分页。每层建议最多 6–8 项，手机不能塞 35 把在一圈。

确认型号后打开外观抽屉：缩略图分页、原皮选项、皮肤搜索/筛选、收藏、计数器开关；刀具先型号再涂装。计数器是属性，不生成额外“商品”。只有支持该型号的皮肤可选；真实资源没有的计数器显示能力置灰说明，不伪造贴图/功能。全部已有支持外观默认可选，无生存拥有条件。

电脑用鼠标/数字快捷键，可自定义 B；触屏先点类别再点型号，外观页滑动，不依赖悬停或多指才能购买。点按作为必备操作，滑动轮盘可选；手指离开面板、取消触点、系统返回不误购。面板消费触摸/鼠标，不能透传成开枪或镜头转动。确认按钮同时显示“立即装备”或“下次复活装备”。免费，无余额/价格门槛。

### 5.2 更换事务与保护窗口

服务端维护 `DesiredLoadoutRevision`（下次）和 `ActiveLoadoutRevision`（当前），客户端提交“想要什么”，不能自行赋值武器、皮肤或弹量。

- Preparing：可自由选择，明确确认入场后才进入复活流程。
- DeathView/AwaitingSpawn：可编辑下一命；复活准备开始时冻结一个版本。后来修改自动排入下个合法提交，不能混装两个版本。
- SpawnProtected：请求在服务端接收时仍满足保护条件才可立即应用。修改不刷新 3 秒计时，不补当前同枪消耗资源；攻击已解除保护后不能换满弹枪。
- Alive：只更新下一命计划，即使面板在保护期内打开、按钮很晚才点也不能越过截止。

同型号同外观重复请求幂等；完整配装作为整体校验，空间/记录配额/皮肤不合法则保留旧配装并告知，不静默少发某把枪。投掷物按批准配装恢复，不无限购买绕过每命配额。

## 6. 装备身份与枪池（不增加可回收编号）

必须先纠正旧初稿：Zeus 是有记录/充能状态的枪；“每人两把所以只占几十条”在每人轮流选 35 型枪时不成立。

推荐使用世界内的 **按型号固定的竞技借用记录池**，所有权属于军械库，不属于生存玩家。记录一旦分配其 Id/Variant 永久不变；没有枪号删除、回收或把旧 AK 编号改为 M4。按需增长到某型号历史最大同时租出数，加有界事务准备容量；上界按 `支持的有记录型号数 × 最大活动参赛人数 + 准备容量` 计算。16 人×35 型为 560 条量级，真实上界须在实现中明确，不能承诺永远几十条。

每次借用以 `(WorldId, MatchId, SessionEpoch, PlayerKey, LifeId, LeaseGeneration, RecordId)` 定位；归还后同一把军械库枪可再次借出，这是同一实例的转移，不复用消失的身份。记录只在无活跃引用/无未结算消息时允许调整皮肤、满弹、耐久/充能；换型号取另一条固定型号记录。可在死亡阶段冻结/归还旧租约，准备新配装，避免额外按每次死亡无限分配。

军械库的未借出记录纳入 `ScGunHolders`，已借出的只认唯一库存持有者，不能让完整性扫描把租约账本和背包误认成两把真枪。保存恢复时复核池、库存和租约引用，失败原样保留、隔离本次租约，不猜枪或重置整个注册表。

计数器显示通过竞技只读提供者取得 `(MatchId, PlayerKey, WeaponType)` 的次数，不修改 `ScGunRecord.KillCount` 来驱动生存成长；竞技计数器样式可以借用原资源，数据源独立。换皮肤/借到其他记录不转移别人的计数。

容量满时拒绝新分配并保留旧装备，不清表。比赛停止后记录停放于军械库以便下一局复用。存读、重连和连续多局之后容量应趋于配置上界，而不是随生命次数增长。

## 7. 竞技战斗配置与 CS2 对照

### 7.1 数据来源和可证明范围

旧调查读到的 CS2 构建为 PatchVersion `1.41.8.8`，路径 `E:/SteamLibrary/steamapps/common/Counter-Strike Global Offensive`。实施时重新锁定 steam.inf、weapons.vdata、相关资源/配置哈希；不把不同更新版本的数据混在一起。

按每个字段保存 `来源成员/哈希、原值/单位、转换、行为证据、未证实项`。35 枪和刀/允许投掷物都有覆盖清单。只读二进制字符串不能证明算法；未核实规则不得用直觉数字填上后称“照搬”。本版要求不因难度被降成“伤害大致类似”。尚缺的行为验证作为明确的发布验收缺口。

### 7.2 独立规则提供者

核心默认返回生存规则，DM 只在活动竞技世界/参与者上返回不可变的 `CompetitiveWeaponProfile`，客户端使用同一规则指纹做预测。包括伤害、射速/射击模式、弹容量、装填步骤、移动速度影响、开镜/消音变体、散布、后坐力及恢复、距离衰减/穿透/护甲比率。逐项审计现有 `ScGunGrowth`、Zeus 恢复参数、玩家攻击加成、生存护甲、原版衣物护甲和第三方属性，避免重复修正。

HP=100 的显示和真实结算一致，可用 `hp/100` 映射原版归一生命，但只能有一个权威血量与一个提交路径，不能竞技扣一次、原版再扣一次。创造成员必须绕开原版创造无敌而不改变编辑者权限。竞技里按用户要求使用 CS2 规则；生存 Zeus 和其他已接受玩法不变。

全甲为 AP=100+头盔标志，按部位、穿甲率、护甲不足和剩余护甲消费计算。当前 `ScArmorRules` 的 60%/50% 不直接沿用，旧护甲预算与竞技 AP 不混写。刀/Zeus/投掷物走各自核实的伤害/护甲规则，不套统一子弹公式。

### 7.3 弹道、身体与手感

枪弹应复刻其实际命中/射线行为，不因“弹道”一词给步枪额外加重力飞行。明确 Source 单位到方块/米/角度/时间转换，按站立、移动、蹲伏、跳跃、落地、开镜、连续射击和停火恢复检验；区分镜头抬升、视角反馈和实际子弹方向，不能两次叠加后坐力。

穿透需要材质、厚度、伤害衰减和多次穿透限制；SC 方块不是 CS 材质，必须形成版本化材质映射。未知方块采用记录在案的保守默认，不能保证所有第三方材质与 CS2 相同。Trace 记录穿透和烟雾区间供击杀事件使用。

竞技命中体积必须统一且与可见人物大致一致。T/CT/原版男女及可选第三方外观不能通过极小模型获得优势；未知模型无法验证时竞技外观回退/限制为受支持外观，生存外观不受影响。若标准化命中体积与玩家想要的自定义模型发生实质冲突，再给具体证据与选项，不提前泛化成禁用所有外观模组。

无限备弹只免耗弹匣材料，有限弹匣/换弹时序仍在；无磨损不等于无限射速。保留已有服务端射速校验、输入租期、预测确认，不能新增更宽松的竞技旁路。

## 8. 会话、生命与死亡镜头

全局状态：`Editing -> Lobby -> Countdown -> Running -> Results -> Lobby`。异常停服/平台断开转 `Interrupted`，保存最后确认的统计和未完成状态，下次世界先回 Lobby，不自动重放击杀/复活。

个人状态：`Preparing -> SpawnPending -> SpawnProtected -> Alive -> DeathView -> SpawnPending`；任何阶段可转 Spectating/Disconnected。`Alive` 和 `SpawnProtected` 才可被战斗目标系统考虑，保护是否允许承伤另判。

### 8.1 致命处理

伤害解析在引擎删除实体/掉落之前决定是否致命，按当前 `LifeId` 只接受一次 `Alive -> DeathView`。先生成包含攻击事实的结果，再禁止死者攻击/移动/碰撞/受击，清除换弹、蓄击、连发、投掷准备和旧预测，驱动计分及镜头。不要通过把真实血扣到 0 再回满来赌引擎没有处理死亡。

可将实体保留并关闭可交互状态，但镜头/可见尸体必须与活体分离；若引擎钩子实际无法覆盖，记录真实调用证据后选择受控重建实体方案，保证身份、库存和统计不变。不能只取消掉落就宣称“不真死”完成。第三方直接移除实体单独检测和恢复，不自动补击杀。

死亡镜头约 2 秒，参考 CS2 的定格/击杀者信息/姿态；不承诺逐帧回放系统。服务器发确认时刻和必要信息，客户端先显示立即反馈再校正。资源能复用，镜头位置、遮挡、插值和输入锁定须适配 SC；没有杀手（环境死）不锁定一个猜测的人。

### 8.2 复活提交与客户端就绪

死亡镜头期间以分离状态准备批准配装与下一命租约，预加载必要外观。不把装备先发进死者仍可操作的槽位。

服务端决定点位并短时预留，发 `PrepareSpawn`（下一 LifeId、目标、配装/库存版本）。客户端确认地形/资源/快照就绪期间保持不可战斗/不可被打且不阻挡其他人。就绪有界超时（建议 10 秒）则转观战/连接故障，不留无期限无敌靶子。房主本地走同样状态机。

`CommitSpawn` 协调提交位置、朝向、零速度、100 血/甲/头盔、完整库存、当前武器、规则指纹、保护截止。客户端完整收到该版本才切换到活体和输入；3 秒从服务端接受就绪并提交可操作状态的时刻计时，显示做时钟对齐。传输耗时与端到端剩余保护差异须实测，不能把资源等待算进保护时间。

未完整应用提交的客户端不发送有效攻击。旧生命发出的包/延迟伤害/库存结果不能作用于新生命；同一复活提交重试不重复补弹。准备失败保留待复活/观战，不能先扣池再留下半套装备。

## 9. 安全复活点算法

输入为已验证的三维竞技区域、固定点列表、活动敌人位置/眼位、动态危险体和近期点位使用记录。禁止世界随机 XZ、无限搜索或者跳到原版世界出生点作为无提示回退。

1. 硬过滤：在区域内、地形已加载、身体包围盒与头顶净空、可站立地面、无火/危险液体/即将生效爆炸体积、无实体/其他复活预留占用。房主编辑后点位作废须重新过滤。
2. 安全评级：最小敌人距离、是否处于敌人直接视线/火线、近几次使用、同帧待复活者。距离/视线可分级放宽；硬过滤不能放宽。最近可见敌人更危险，不能只看平均距离。
3. 在最高安全档前若干点加权随机，避免总选同一点。建议最小距离初值 12 格，实际按地图测试；不是全地图必须满足的固定设计要求。
4. 同帧死亡按稳定顺序保留点位，后续重新过滤被占用点；准备时间过长或点位新起火时提交前再验证/重选。
5. 全无硬安全点：短时重试并告知房主，不生成在墙里/空中/地图外。玩家保持待复活，可观战；不奖励对方额外击杀。

算法用限定候选和缓存避免每帧遍历无限区块。出界建议 3 秒提示后按一次环境死亡处理，回到正常复活链；不把越界传送当免费补弹功能，服务器去重。

## 10. 保护与资源表现

服务端保存保护截止，发 HUD 剩余提示和其他玩家可见的保护效果。有效射击/刀击/投掷先关闭保护，再允许攻击命令执行；空弹匣按火键而未接受动作不解除，策略写入测试。受到攻击不延长保护，打开菜单/换装/客户端重连不能刷新同一生命保护。

复活音效、白色人物保护效果、计分板/击杀图标、死亡面板分别调查本地资源，记录准确成员/哈希/引用。白色效果可能为运行时 shader 参数而非独立图片，不能凭记忆宣布“找到原资源”。Source 的 UI/粒子/材质不能直接运行在 SC，转换需对应 Android GLES 和 Windows 路径。

允许设备降低装饰效果质量，但不允许隐藏对手的无敌信息或改变结束时间；选择何种降级效果须能辨认保护状态。音效不重复广播、不每帧触发，服从已有并发/音量设置；保护结束清除材质覆盖，不把人物永久染白。

## 11. 计分、助攻与击杀方式

服务端产生 `KillEventId=(MatchId, VictimKey, VictimLifeId)`，一个生命最多一次终结。另记攻击 `ShotId/AttackId`、攻击者生命、受害者、武器、最后伤害部位、服务器时刻、是否有效得分、自杀/环境类型、助攻者列表。伤害账本只保存当前受害者生命的有界记录，复活/换局即失效。

击杀 +1 分；助攻仅计数；自杀/环境死只加死亡。比赛截止以服务器伤害提交时刻为准；截止后弹着不能追加上一局分数。断线不清本人当局死亡/分数，同一稳定身份重连恢复统计，不允许按连接槽编号继承陌生人成绩。UI 排序可按分数/击杀/死亡/稳定键排列，但相同分数的名次并列，不伪造胜负规则。

方式是独立布尔事实，可组合：Headshot、NoScope（仅适用狙击武器且发射时未开镜）、ThroughSmoke（本发有效命中段穿过当时有效烟体）、Penetration、AttackerBlinded 等。爆头击杀不能用现有“非致命爆头 Outcome=3”替代；霰弹以导致致命结果的经核实命中归因，不因某颗擦头就把身体致死算爆头。没有可靠数据时不显示该标记。

广播、榜单、StatTrak 读取同一事件，只处理一次。事件序列有界缓存，迟加入先同步榜单快照和序号，再收增量；不播放此前整局旧播报。最终 Results 有独立版本和确认，断线/重放不得二次结算；本版无生存奖励。

## 12. 双端 HUD 与输入

新增可注册元素：购物按钮/轮盘入口、榜单按钮/面板、右侧装备组、血甲、弹药、剩余时间、保护提示、击杀播报、死亡面板/结算入口。每项支持位置/缩放/旋转/透明度/开关；数据判定不依赖可见性。皮肤抽屉/轮盘内容在面板内部重排，不要求每个商品图标成为一个 HUD 编辑项。

所有配置按设备/用户的竞技命名空间保存，Windows/Android 分别有默认布局，不从一台电脑向整个房间广播坐标。标准化锚点+安全边距+最低触摸目标；全屏/窗口、不同 UI 缩放、刘海/长宽比变化后仍可找回。旋转必须同时用于绘制、裁剪和命中测试。

右侧列表只显示持有项，刀独立；没有投掷物不留空行，多种投掷物可展开。点击等同于请求切换现有实际槽位，服务器批准后高亮确认；丢包/延迟时不能高亮成不存在的武器。

Windows 榜单默认按住 Tab，也可切换；Android 点击开/关并可滚动。移动与开火等多指输入不被未命中的 HUD 捕获，轮盘打开时消费其覆盖区域输入，关闭后清理旧触摸所有权，避免同次抬手射击。键绑定显示冲突并允许更改，不强占已有原版背包/蹲伏。

提供编辑模式、恢复单项/整套默认、隐藏项预览，以及始终能从菜单进入的恢复入口。普通按钮旋转字段需扩展，不冒称现成。房间计时/计分/保护始终由服务器控制，玩家调整 UI 不影响规则。

## 13. 接口与网络契约（名字为建议，不是现有 API）

核心扩展建议按职责拆为：`IScModeRules`（有效武器/消耗/伤害）、`IScCombatObserver`（提交事实/致命接管）、`IScInventoryOwner`（持有者/租约）、`IScHudExtension`（布局元素）、`IScAddonCapabilities`（握手能力）。禁止“全局竞技开关”泄漏到其他世界；注册和释放以 Project 生命周期为界，重复 Load/Dispose 幂等。

握手携带附属包标识/版本/构建、模式契约版本、战斗配置哈希、要求的资源能力。只有影响当前活动模式的必需能力不匹配才禁止参赛；普通生存连接保持已有政策，不因可选 UI 设置不同拒连。不能依据文件名或版本字符串相同就信任同构建。

所有客户端命令关联 SessionEpoch/MatchId/PlayerKey/LifeId/RequestId 和必要版本；服务端从连接映射验证玩家身份，不信任包内任意 PlayerKey。房主设置、选枪、切换、就绪 ACK 都做权限与大小校验。旧命令不能影响新局/新生命。重试保持 RequestId，不制造重复装备和击杀。

消息号必须查全体正式注册表后分配并增加重复注册检查；旧提案“92 以上空闲”不是长期保证。优先复用已修复的 transport、槽位/记录同步，不假设两个有序包必定同一帧可见。复活和换装有 CommitRevision/完整性屏障，缺包有界请求快照。

时钟以服务端为准，客户端显示可插值。没有服务端确认不得自行得分、复活解除限制或补弹。网络抖动被拒绝的射击允许纠正，但不引入原先弹量多减回补的重复确认缺陷。

## 14. 保存、退出、降级与 1.4.0 基线

持久字段建议包括 WorldModeMarker、WorldId、ArenaDefinition/Revision、RuleProfileId/hash、LastMatchResult、配装偏好、竞技枪池/租约账本、稳定玩家映射和恢复标记。活跃网络会话、按住输入、渲染对象、平台连接号不直接作为持久身份。世界导出应避免携带敏感连接凭据。

准备/提交状态与库存/记录通过同一世界保存生命周期协调；阶段故障可重放到唯一结果。不要单独异步写一个“已提交”标记而库存还没保存，也不为此自动给玩家世界建快照。突然停服下次先回 Lobby，清除运行时租约权限、保留数据和上一局中止说明，既不复活到危险位置也不重新累计比分。

从正式 1.4.0 起任意正式发行版本必须读写往返，不因本模组拒载/丢数据。1.4.0 尚未正式发布，应在发布前安排 **可保存未知模式载荷的封套与休眠入口**：旧核心/无 DM 的环境可以加载世界、看见模式不可用提示并处于安全编辑/非比赛状态；保留竞技数据和军械库引用，不能把比赛物品带到普通生存或自动运行错误战斗规则。未知附属 .xdb/实体类型是否会导致引擎先拒载也要测试，优先通过核心认识的通用容器存放 DM 数据。

未来版本不得随意改变该基础封套或写入旧版无法保留的结构。新增模式能力可以在旧版休眠，数据必须换回恢复。此承诺与网络必须匹配版本不同：能加载存档不表示可以混用协议联机。

发布前建立正式发行清单，记录真实包哈希。如果实施时 1.4.0 已正式发布且不具备所需封套，不能偷换同名 1.4.0 包假称历史测试通过；需报告具体不兼容点并重新选择可被原发行字节保留的表示。1.4.0 前历史包不纳入本次强制矩阵，遵循 AGENTS.md 对旧指南的覆盖。

## 16. 主要风险、替代方案和实施顺序

最高风险是：生存规则被全局修改、伪死亡遗漏引擎副作用、复活跨包半状态、永久记录无限增长、旧版丢附属载荷，以及把 CS2 参数相同误当行为相同。对应验收见 verification。

拒绝的替代：任意世界自动启用、从生存读取皮肤、自动寄存、每次复活创建新枪、取消格式保护、用创造无敌模拟保护、固定减伤冒充 CS2、靠客户端申报爆头计分、把 3 秒全部给手机选枪、把全目录挤一个轮盘、只做 Windows UI。

执行顺序：锁定基线/核心与平台边界 → 实现安全扩展/持久封套 → 世界与地图 → 配装池/交换事务 → 战斗配置/伤害事实 → 死亡/复活 → 计分播报 → 完整轮盘/HUD/资源 → 全矩阵候选与实机。UI 结构和资源盘点可与独立工作错开，但不同时编辑相同文件。不开多个 agent，除非用户另行授权。

阶段拆分只为可复核，不删本版功能。平台缺陷阻塞相关实机验证时继续完成独立工作，标出准确阻塞；不能宣称所有功能验收完成。详细操作见 vps-guide，所有实现任务初始未勾选。
