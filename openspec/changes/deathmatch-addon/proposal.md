# 死亡竞赛附属包

## Why

玩家希望在自建竞技地图中反复随机复活并进行 CS 风格个人枪战。现有核心面向生存：武器有永久记录、成长、磨损、皮肤增伤，死亡和背包由原版生命周期处理，不能通过简单传送和清空背包安全地变成死亡竞赛。需要独立模式、明确的核心接口、双端 UI 和服务端一致性。

本变更落实用户在 2026-10-02 确认的 DM-01–12，当前只授权规划；详见 [当前决策入口](../../../docs/tasks/deathmatch-addon-design-20261002.md)。初稿的生存寄存、收藏带入、10 秒保护、四格默认发放和待选团队模式不再适用。

## What Changes

- 新增独立附属项目/包，在专用竞技世界启用；普通生存维持当前行为。
- 新增房主地图设置、个人混战局长/计分、三维区域与安全候选复活点。
- 新增免费 CS 风格购物轮盘、分层枪型/外观选择、完整配装重买、独立竞技计数器。
- 新增死亡镜头、服务端控制的复活事务、3 秒保护、音效/第三人称保护效果。
- 新增固定 CS2 构建的竞技武器规则：100 血/100 甲/头盔、无皮肤或成长优势、无限备弹但正常换弹，数值/散布/后坐力/穿透需逐项还原验证。
- 新增仅显示已拥有装备的 HUD、可触切枪、计分板与全场击杀方式播报，所有新按钮/HUD 可编辑。
- 扩展核心的模式规则、攻击结果、库存发布、HUD 注册和附属能力握手；竞技行为由附属包所有。
- **BREAKING（联机）**：握手/消息结构变化需协商新协议，双方兼容后才参赛；具体版本从实施时基线分配，不预占“协议 7”。网络版本不等于存档版本。
- 不改变永久枪号与 layout 6/schema 7；新增竞技数据须满足从正式 1.4.0 起的双向存档契约。缺失模式时世界可安全休眠加载，不能丢弃竞技数据或作为普通生存自动运行。

## Capabilities

### New Capabilities

- `dm-arena-session`: 专用竞技世界、地图编辑、房主规则、个人混战生命周期及隔离。
- `dm-loadout-armory`: 免费轮盘购物、外观全开放、配装时机及永久记录安全复用。
- `dm-combat-profile`: CS2 竞技规则、血甲、武器弹道及公平伤害。
- `dm-respawn`: 地图候选选点、死亡镜头、原子复活、3 秒保护。
- `dm-match-events`: 唯一计分事件、助攻、竞技计数器、击杀方式与结算。
- `dm-hud-input`: Windows/Android 操作、轮盘、装备栏、计分板与布局编辑。
- `dm-addon-contract`: 核心扩展接口、网络能力协商、会话隔离及可往返持久化。

### Modified Capabilities

现有 `weapon-state-consistency` 仍为未归档 change。不得重写或吞并其任务；本 change 为其接口消费者，回归须继续保证枪记录/槽位同步、消息号唯一、输入确认等既有契约。

## Impact

新增路径拟为 `src/ScCsgoDeathmatch/`、针对性测试和资源描述；核心受影响入口见 design §3。同仓独立项目是当前决定，新仓库仅在版本/协作边界确需独立时使用，不能以复制整个核心来“隔离冲突”。本轮不创建/发布 GitHub 仓库、不派发 VPS、不改游戏代码。

支持组合：现行 Full + DM、Lite + DM、Lite + 匹配 Agents + DM；所有双方均需匹配玩法协议。Mini 不纳入本次承诺。Android/Windows 的加入与实际操作分别验收，已提供 APK 的临时目录故障阻塞安卓客户端端到端验证，独立实现/离线验证仍可继续。

不包含生存物品寄存、账号库存、付费经济、团队赛、奖励武器、治疗针、机器人补位、CS2 网络协议移植或第三方 APK 修补。
