# 0.40.8 — 布局编辑器、玲兰触控兼容分析、附魔误判与夜间光照

## 证据范围

- 用户截图：布局面板只剩上半截，黑底，收起后按钮出现叠影/抖动。
- 用户日志 `加了MC附魔模组后生物被枪械击中会着火.log` 实际来自 Android API **1.9.3.1**，使用的枪械模组是公开版 **0.28.2**，不是当前 0.40.7；设备 Redmi/Adreno 730。不能把这份日志当作当前 Windows 版本运行记录。
- 只读分析用户提供的 Minecraft_附魔 1.3.5 和玲兰触控 2.1；未修改、重打或发布这两个模组。
- 附魔原包 SHA256 `0696ef460af4ec427d1c817e4e0a8f6818ab2ed3b58d718e08816512e1f13e07`；玲兰触控原包 SHA256 `e1352c114f421ff8257b95e138096d0d3551cf5fa8f954a3f89b7ae55fed29a0`。

## 1. 布局编辑器

### 根因

原先 ScGunLayoutScreen 的预览 Canvas 没有指定 Infinity 大小，按子按钮及 Margin 测量自身大小；按钮位置又按 preview.ActualSize 计算。于是“容器尺寸→归一化按钮位置→容器尺寸”构成反馈循环，收起面板后剩余布局变化尤其明显。独立 Screen 还没有绘制游戏画面，黑背景使旧帧残影更显眼。

此外所有九种按钮都同时显示，而强投、轻投、重刀、换弹等原本就是互斥共位；错误地堆在一起会像闪烁。仅把按钮本身 IsHitTestVisible 设 false 不会自动关闭它的子控件。

### 修复

- 预览区和面板宿主明确占满屏幕，按钮布局不再影响预览尺寸。
- 在 Measure 阶段按逻辑尺寸选择窄屏布局，不再按上一帧 ActualSize 设置截断面板。
- 设置内容独立滚动，保存/取消固定在底部。面板仍支持换边与收起。
- 预览仅显示当前选中操作所属的一组并发按钮；其它操作通过“下一个按键”访问，互斥按钮不再重叠显示。关闭的按钮仍可在本组内淡显并重新启用。
- 预览按钮及所有子控件都不参与命中测试，禁用其 Update；只有编辑器自己的拖动代码处理位置，不会开火、投掷或换弹。
- CS 设置与编辑器添加 ScGunWorldBackground：已有世界时只绘制当前 GameScreen 内的 ViewWidget，不调用 GameScreen.Update/GameManager.UpdateProject，不重新挂接游戏 UI，也不将编辑输入转发给游戏。背景是当前暂停世界视角，不是样板图。
- 未进入世界时没有可显示的游戏画面，使用实色背景并提示先进入世界。不偷偷加载世界或写入存档。

## 2. 玲兰触控 2.1 能接管什么

实际 DLL 为 SushiTouch。SushiVirtualButtonWidget 使用 Keyboard.ProcessKeyDown/Up 和 Mouse.Process… 模拟输入；UpdateInput 接管摇杆移动和拖拽视角，而不是反射调用我们的 ScGunFunctions 九个功能。它不会直接改写我们保存的按钮布局。

| 操作 | 可用路线 | 边界与建议 |
| --- | --- | --- |
| 移动、视角、跳跃、蹲下、背包、快捷栏 | 玲兰原生摇杆/触控板/虚拟按键、游戏原版键位映射 | 可交给玲兰控制；本模组原本就不替代这些操作 |
| 枪械开火、轻刀 | 左键 / 原版 Dig、Hit | 可替代原版开火输入；仍由我们执行武器战斗 |
| 换弹 | 虚拟键 R | 我们直接读取 R；映射好后可在 CS 设置中只关闭“换弹”按钮 |
| 检视 | 原版 EditItem，默认 G | 按玩家实际键位映射；可在 CS 设置中只关闭“检视”按钮 |
| 开镜、消音器、切连发、左轮副射 | 桌面鼠标右键会走 RequestSecondary | 手机 IsControlledByTouch 状态下，原生触屏 Hold 同时产生 Dig/Aim，我们故意过滤这条 Aim 防止长按开火误开镜。玲兰模拟右键不保证改变该标志，故不能宣称手机已可靠接管；暂保留对应 CS 按钮 |
| 重刀、轻投 | 桌面右键 / 显式 CS 按钮 | 同上手机触屏过滤；保留专用按钮最可靠 |
| 强投 | 左键可请求普通强投；CS 按钮支持明确的按住/松开时序 | 可以测试玲兰左键，但多指取消/后台恢复尚未实机验收，建议保留强投/轻投按钮 |
| 准星 | 双方都可绘制 | 玲兰的 SnipeAlwaysShow 可单独显示瞄准组件。若出现双层准星，应选其中一方；本轮不修改玩家的玲兰设置 |

没有自动关闭全部 CS 自定义按钮，也没有给不可靠的触摸 Aim 强行开后门。特别是禁用总开关会同时移除手机上仍必需的副操作/强轻投按钮。未声称完成玲兰 2.1 与当前模组在手机上的完整适配。

## 3. Minecraft_附魔导致枪击着火

Enchantment.Patches.EnchantmentPatches.AttackBodyFireAspectPatch 在所有 ComponentMiner.AttackBody(Attackment) 之后执行：读取攻击者当前 ActiveBlockValue，检查 IsWeaponBlock 和 WeaponHasFireAspect，然后给目标 SetOnFire(…, 3f)。它没有先确认这是原版附魔物品，且不限近战攻击。

EnchantmentManager.WeaponHasFireAspect(data) 的实现就是 `(data & 8) != 0`。用户日志 P90 data=67785 满足该条件。我们的低位是型号（P90 型号 9，自带 bit 3），旧版弹量与新版实例 ID 也占用自己的数据布局，绝非附魔标志。对方按 GetMeleePower 等属性兜底识别武器，因而误判普通 CS 枪为带火焰附加的武器。类似误判还能影响名称、耐久或附魔着色；不能通过清掉 bit 3 修复，否则直接改坏枪型。

该附魔版本已有 s_blacklistedAssemblies / s_pbrAssemblies 排除机制，原本只自动发现 Polycombat。我们在 OnLoadingFinished（各模组初始化之后）反射确认这两个字段的确切类型，只加入自己的程序集，保留其已有集合成员。未改变物品值、伤害回调、其它模组的附魔标志或原版武器。

效果是本模组自定义位编码物品不参与这套通用附魔（包括火焰附加）；原版武器照常附魔。若其它附魔版本的排除结构不同，只记告警，不盲目修改未知字段或静默跳过所有攻击回调。运行日志 `[COMPAT] Enchantment…` 可确认。

## 4. 夜间武器与手更亮

同一套 cs2_arm/cs2_glove 的渲染竟然沿用了当前手持武器的 GunEnvFactor：普通枪默认 .25（AK 还有 .8 系数，得到 .2），刀/投掷物是 1。因此切武器会让**环境光系数**变化约四至五倍；不是说最终像素亮度线性增加四倍，因为还有 BRDF、色调映射与直接光。

- cs2_arm/cs2_glove 改成固定使用 PbrGunEnvIntensity（默认 .25），不看当前武器型号，手与手套切换不再跳变。AK 手臂相对原先 .2 会略提升至一致基准，而非给刀手继续加亮。
- 刀和投掷物的棚拍 IBL 在低场景光（<=.15）限制到同一 .25 基准，.15～.7 平滑恢复原来的日间标定，>=.7 保留原材质系数。所有环境光和直接光仍乘以实际场景光照。
- 不修改 CS2 贴图、几何和日间枪皮肤色彩；不把真实火焰/燃烧瓶粒子或枪口闪光变暗。这些本来就可以发光。
- 物品/world mesh 使用普通非 emissive 顶点，未发现统一“全亮”标志需要移除。本轮针对确定存在的手持 PBR 系数差异；其它第三方光照/附魔着色效果仍需现场区分。

## 5. 验证与限制

- 4 种逻辑尺寸、4 组操作、反复收起/展开，每个组合连续 12 次 Update/Measure/Arrange，检验预览大小固定、按钮边界不振荡、只有 2～3 个并发按钮、保存可见、底部设置可以滚动到达（96 项）。
- 手臂/手套在刀、AK、M4、投掷物及五档光照下系数相同；刀/手雷低光上限、日间武器系数保留（12 项）。
- 加载用户给的实际 Enchantment.dll，但不执行其 ModInitialize/PatchAll：验证 P90 原始 data 被误读为火焰、注册排除后五类 CS 物品的实际第三方分类器返回 false、原版铁刀仍可附魔（7 项）。这是实际第三方判定分支测试，不是手机上看过火焰消失的录像。
- 工作区普通检查（含此附魔 DLL）7583 项、0 失败；用用户 Windows 游戏目录实际引擎 DLL 复核同样 7583 项、0 失败。最终 Full/Lite 包检查另含 0.28.2 发布包与真实备份检查，报告 `output/ScCsgoKnives-0.40.8[-Lite]-check.json`。
- GPU 世界背景、夜间视觉、手机多指拖动、玲兰控件交叉输入仍需实机验收。离线不调用 Draw，不启动玩家世界，不能把布局计算通过当成游戏截图。
- 物品布局仍 v5、记录 schema 仍 3，无存档迁移，不修改第三方模组文件、原始日志或玩家世界。保留用户已有的未提交属性文案/UI 断点与未跟踪皮肤规划。
