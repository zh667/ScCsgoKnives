# 0.38.2：创造涂装目录与持枪颜色贴图

2026-09-08，基线 47bb05d / 0.38.1。用户要求创造模式直接在武器分类取涂装枪，并反馈图标变了而第一人称仍原厂；随后补充第三人称似乎已显示，只是有局部问题。

## 已改

- 创造武器分类追加 11 款涂装枪，DisplayOrder 222，位于原枪 221 后。创造模式装配台去掉换肤入口；生存模式收费换肤保留。
- 装配台的换肤/维修候选只扫描创造背包的 OpenSlotsCount 可写槽。第 1585 等格是引擎的只读目录，不是玩家实际库存。报价入口也拒绝只读目录槽。
- 第一人称 AK/M4A1-S/AWP 的 OBJ 路径原来读 `s_cs2Base[gun]` 原厂颜色，仅 PBR 辅助贴图切换。现在颜色和 ORM/法线使用同一个选中材质；OBJ 和刚性模型路径统一。
- 第一人称、第三人称、物品模型共用材质解析器。缺图回退时颜色与 PBR 材质一起回退；日志记录 `gun skin material loaded` 或 `gun skin texture unavailable`，避免无证据地把回退当成皮肤正常。

## 创造物品与存档

创建设计使用新增、动态分配方块编号的 `ScGunSkinTemplateBlock` 表示无状态目录条目，data 是稳定 CS2 Paint ID。它属于独立物品类型，**不是扩充枪型或复用 ScGunBlock 的物品位**。目录枚举不创建世界记录。条目不可堆叠，可以像未使用的新枪一样存放/丢弃并保存；取到玩家手中时在枪械 Update 中、进入枪械操作之前，通过 ScGunMutation 原子转换为带皮肤的普通枪实例。

转换同时替换内容编号和 data，保留光照位；型号、满弹、满耐久和皮肤从目录定义取值。失败时原模板保留并提示，不能把裸 data 写成完整物品。每次独立取用分别分配记录，持有者扫描/复制隔离继续作用于转换后的普通枪。表满时安全拒绝；不会因为浏览创造目录而用尽 1022 个 ID。

普通枪布局仍为 v5、记录 schema 仍为 2，已有枪/皮肤/充能/补偿记录不迁移、不重置。仅新增一种物品类型；动态方块映射由引擎持久化。不承诺把含新物品的世界降级到不含该类型的旧 DLL 仍可正常使用。0.28.2 专用迁移与 0.38.1 未知格式保护保留。

## 验证与边界

新增 `creative-skins/*`：重复目录枚举不占 ID、11 款逐一取用、两次取用独立且两轮存读档保持、只读目录拒绝/候选过滤、表满、发布后失败回滚、容器中的模板存读与之后转换、颜色/PBR 材质一致和缺图回退。PackageCheck 加入新物品在两种动态编号顺序下的检查。

无头测试使用实际 ComponentCreativeInventory/ComponentInventory 和包内 DLL；最终 PackageCheck **6270/6270** 通过，含新增 18 项运行时回归和 2 项动态编号检查；Full/Lite 均为 746 条目、使用相同 DLL，结果见 `output/creative-skins-final.json`。实机仍需确认创造分类位置、直接取用、三把 OBJ 枪皮肤、换弹/拆消音器等操作。第三人称局部问题尚缺具体画面，本版没有把它宣称为已定位的 UV/姿态缺陷。

九款配色近似、旧版 UV/珠光等资源限制仍存在。本修复解决运行时取用和贴图选择，不等于重做 CS2 原版皮肤图案。其它暂停批次不恢复。
