# 武器装配台操作与反馈修正（0.41.2）

## 问题和证据

用户反馈生存模式的功能项点“下一步”只闪一下，没有反馈，并要求改为双击进入。

读取了 `E:/EdgeDownload/[Windows]SurvivalcraftAPI_1.9.2.1/Bugs/Game.log`（本轮读取时末条为
2026-09-09 15:31:52）。该日志有生存世界加载记录，但没有装配台点击诊断或对应异常，不能据此
断言玩家当时背包里的具体物品及触发的分支。

源码确认的问题：维修/涂装/计数器无候选时，先调用 HUD `DisplaySmallMessage`，随即重开装配台。
原版 `DialogsManager.ShowDialog` 把遮罩和对话框放在玩家 GUI 上层，HUD 提示可能被遮住。
属性页也曾在空背包时走此路径。报价拒绝和扣料操作结果同样使用了容易被遮住的小提示。
这解释了一条明确存在的“闪回主列表、没有可见原因”的路径，而不是从日志确认所有点击均属此原因。

## 实现

- 所有装配台选择列表：单击预览，同一行 0.45 秒内双击/双点进入；移除“下一步”。
- 首行的默认高亮不是第一次点击。不同条目、超时、滚动位置改变和类别切换不能拼成双击。
- 从原版 `ListPanelWidget.ItemClicked` 接入鼠标和触屏共用的点击事件；在对话框 Update 中执行跳转，
  不在列表子控件更新到一半时换页面。待执行标记与完成标记防止连点重复进入。
- 保留最终报价确认；双击浏览绝不直接扣材料、组装、维修、安装计数器或改涂装。
- 无候选、记录不可读、已是当前外观、安装条件不满足等显示持久的居中窗口，按“返回”才离开。
  明确说明维修只列受损枪、涂装只列有可用皮肤的型号、计数器不重复安装，只扫描玩家背包/快捷栏。
- 组装/维修/换肤/安装的实际结果也改为窗口，避免成功或失败提示被重新打开的菜单遮住。
- 属性目录不再要求背包拥有枪；有枪优先选对应枪，没有枪打开默认目录，可浏览原厂与涂装条目。
- 选择入口检测到距离/角色/装配台状态不可用时显示原因，不再无声关闭。
- 增加按操作触发的 `workbench select:` 和 `workbench notice:` 日志，包含模式、页面、选项、背包类型、
  槽数、可用性或提示原因；不逐帧刷日志、不记录玩家坐标和名字。
