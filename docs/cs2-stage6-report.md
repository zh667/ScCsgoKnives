## 3. 三处换算（都写明了依据，没有猜 CS 的内部实现）

1. **伤害衰减** `damage × RangeModifier^(距离单位/500)`。
   `/500` 这条来自社区对该公式的文档（[Counter-Strike Wiki](https://counterstrike.fandom.com/wiki/Damage_dropoff)
   与 [Steam 指南 2599082552](https://steamcommunity.com/sharedfiles/filedetails/?id=2599082552) 说法一致），
   **不是 SDK 源码本身**——报告里按这个层级记。
2. **散布**：`m_flSpread` 和 `m_flInaccuracy*` 都是无量纲的方向扰动量，所以锥半角 = `atan(spread + inaccuracy)`。
   这是对单位的解读，不是对 CS 子弹代码的解读。站立与移动两端都是读的，**按速度线性插值是本移植的选择**
   （CS 自己的曲线在导出件没有的代码里）。
3. **后坐**：`m_flRecoilMagnitude` 是 CS 自己的单位，逐发弹道由带种子的生成器给出，那个生成器我没有。
   所以**只用枪与枪之间的比例**，绝对尺度沿用原来给 AK 手调的 1.6°。**这是估计值**，
   要定死得在 CS2 里对墙连射实测弹着图反推（见 §6）。

## 4. 验收数字

`python3 tools/cs2_weapons_selftest.py`，输出 `docs/cs2-stage6-selftest.json`。

- **A**：24 个字面值逐个对 vdata，**0 处不符**；重跑 `cs2_weapons.py` 产出与包内文件逐字节相同。
- **B**：三个换算量在自检里独立重算一遍，最大误差 2.6e-05（就是 JSON 的 5 位小数取整）。

## 5. 未解决项

1. **后坐的绝对尺度是估计值**（§3.3）。比例是 CS2 的，尺度不是。
2. **逐发弹道（喷射图案）没做**：CS 的 `m_nRecoilSeed`（AK 223 / M4 38965 / AWP 4100）驱动一个确定的
   后坐表，我们仍然是每发随机 ±。种子记在 `cs2_weapons.json` 里，等哪天拿到生成器再说。
3. **护甲比与穿透没进游戏**：生存战争没有护甲穿透模型。数值已读出并记录。
4. **爆头倍率没进游戏**：SC 的 `AttackBody` 不分部位。
5. **`m_flRange` 8192 单位（208 m）没有采用**：仍用 `RangeBlocks = 64`，因为 SC 的视距和实体范围到不了 208 m。
   衰减曲线按真实距离算，所以 64 m 内的伤害是对的。
6. **移动散布的插值方式**是本移植的选择（§3.2）。

## 6. 需要你做的事（可选，用来去掉 §5.1 那个估计值）

1920×1080，尽量正对墙面、距离固定（比如 10 m）。我可以从弹孔的像素分布反推每发的角度增量，
把后坐的绝对尺度定死。这一项和之前那份录屏是两回事，不急。
