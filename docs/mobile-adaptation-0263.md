# 0.26.3 手机端适配审查

## 启用规则

按用户要求，手机功能由设备平台统一控制。`ScMobileControls` 优先读取 SCAPI 的 `VersionsManager.CurrentPlatform`，识别 Android / IOS，并用 .NET 的 Android / iOS 系统判断兼容平台标识为 Other 的构建。不根据窗口宽度、屏幕 DPI 或是否装有触摸屏猜测设备。

- 桌面平台不创建模组操作按钮，保留左键主攻击、右键副功能、R 换弹和编辑物品检视。触屏电脑也不启用手机界面。
- 手机平台显示按钮。只有当前使用触屏时，才隔离原版触屏长按产生的 Aim；手机连接键鼠后仍能使用原有键鼠输入。
- 平台识别包含 iOS 枚举，不代表本轮已验证 iOS 的游戏/API 安装或运行兼容性。

## 已修复

1. 原版 `ComponentInput.UpdateInputFromTouch` 在长按/长按后移动时同时写入 Dig 和 Aim。此前手机长按优先走 Aim，刀变成重击、投掷物变成轻投；枪械长按结束还有机会触发开镜、连发模式、消音器等副功能。手机触屏现在用屏幕主攻击和明确的副功能按钮分开处理。
2. 投掷按钮此前依赖共享 `WidgetInput.Press`；它只有一个 `m_touchId`，第二根手指会覆盖。现在每个按钮捕获自己的触点 ID，移出按钮仍保持按住，移动/瞄准手指的按下和抬起不影响准备；只有投掷手指抬起才出手。
3. 触点消失、菜单隐藏按钮或游戏失去焦点时，取消未出手的投掷准备；不把系统中断当作一次正常松手。
4. 按钮加入原版 ControlsContainer，跟随睡眠、相机控制和界面可见性。触摸尺寸为 104×60 个 UI 单位，两行之间留 8 单位间距，跟随原版 UI 缩放和左手布局镜像。
5. 手机操作提示使用触屏文字；投掷物描述根据设备切换。桌面端不再提示不存在的“轻投”按钮。

## 手机操作

| 持有物 | 主操作 | 专用按钮 |
| --- | --- | --- |
| 刀 | 点按/长按屏幕轻刀 | 重刀 |
| 枪 | 点按开火，自动枪可长按 | 换弹；有对应能力时显示开镜、连发、消音器或速射 |
| 投掷物 | 长按屏幕准备强投，松开出手 | 强投、轻投，均为按住准备、松开投出 |

准备投掷期间继续允许瞄准，引信从实际出手事件开始。按钮强投/轻投使用屏幕准星方向。检视继续使用原版“编辑物品”。

## 仍需要手机实测的适配

### 布局与交互

- 16:9、20:9、平板 4:3，原版不同 UI 缩放，刘海/挖孔和边缘适配设置；确认按钮不与用户自定义移动/视角区重叠。目前提供默认位置和左手镜像，尚无模组按钮拖动配置。
- 分屏触摸、全屏视角、视角触控板等原版控制模式；同时移动、转向、长按投掷再松手，开关背包、切槽、切后台返回。
- 枪械开镜后转向速度、霰弹换弹中断、R8 速射、检视入口；手机接键鼠后的输入切换。

### 性能与兼容

- 烟火已有距离降级，投掷物/效果每人最多 4 个、全场 16 个，80 米外不绘制。但近处多层透明烟火仍可能受手机 GPU 填充率限制；需测帧时间和持续运行发热，不能只看单帧截图。
- 真实手和部分武器每帧在 CPU 上做骨骼蒙皮，再提交网格。保留 CS2 真实手，后续应以低端/中端 Android 的 CPU 帧时间决定是否优化计算或缓存。
- 素材中有 177 张 1024×1024 PNG，纹理按需加载且存在缓存。1024 RGBA 无 mip 的估算为每张 4 MiB；这不是实际常驻内存测量。应测试反复切换大量枪刀后的内存峰值，再决定缓存回收或手机专用纹理档位。
- Android OpenGL ES 材质、镜片和闪光效果必须在真实设备验证。Windows 编译与离线 DLL 检查不能证明手机 GPU 着色器正常。

本轮不自动降低画质、不删除资源、不改伤害或物品索引。后续新增手机专用档位、布局和触屏功能应继续使用同一设备判断，避免影响桌面端。
