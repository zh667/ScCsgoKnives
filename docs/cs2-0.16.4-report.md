## 1. 两处对既有说法的更正（先说这个）

### 1.1 我的说法撤回：`Drawable already added` 不是曳光重复增亮

Windows 已反编译确认 `SubsystemDrawing.AddDrawable` 用 `Dictionary.TryAdd`，
重复项记日志后返回，`Draw` 只遍历一次。我原来的判断建立在“如果重复注册”的假设上，
没有验证实现，撤回。

本次另外查到：**mod 里只有一处 `AddDrawable`**（`SubsystemScGunBlockBehavior.cs` 的 `Load()`），
没有手工重复注册可删。日志那行说明引擎侧已经先收录了这个 `IDrawable`。
**本次不动这段代码**——盲删有风险（若引擎并不自动收集，开镜遮罩和曳光会整个不画）。
要清日志的话，正确做法是 Windows 侧做一次实验：删掉显式注册后确认开镜遮罩仍然绘制。

### 1.2 Windows 的说法要修正：`Weapon_M4A1.AddAmmo` 有源音频

它不是“无 WAV 所以无源”，是**整个 m4a1 目录只解码出 `.mp3`**：

```
Weapon_M4A1.AddAmmo  resources = sounds/weapons/m4a1/m4a1_addammo_01.vsnd
                     decoded   = m4a1_addammo_01.mp3        <- 存在
Weapon_M4A1.Clipin   decoded   = m4a1_clipin.mp3            <- 同样
```

我的 `cs2_sound_timings.py` 只认 `.wav`，所以把它报成无源。
**34 条 cue 全部补齐，不需要任何书面豁免**，详见 §4。

### 1.3 规范里 M4 inspect 的例子也要修正（我在实施中实测发现）

Windows 指出的**机制完全正确**（`pose.Time` 被 CS:MC 时长截断后又拿去采 CS2 rig），
但举的例子不成立：`GetDuration` 返回的是 CS:MC json 的 **`Duration` 字段**（5.3），
不是它 `Times` 数组的末值（5.0）。151 vs 160 是曲线采样被截断，不是 `Duration` 被截断。
所以控制器本来就跑到 5.3，`Cs2Rig.Sample` 再夹到 5.2999——**M4 inspect 没有冻结**。

实测真正受影响的是四条（`ArmPreview durations`）：

| 枪 | clip | CS:MC | CS2 | 差 | 症状 |
|---|---|---:|---:|---:|---|
| ak47 | reload | 2.4667 | 2.4333 | −0.0334 s（−1 帧） | 动画先结束，状态机多跑 1 帧 |
| m4a1s | **deploy** | 1.1000 | 1.1332 | **+0.0332 s（+1 帧）** | **CS2 拔枪的最后一帧被切掉** |
| m4a1s | shootSilenced | 0.4000 | 0.3999 | −0.0001 s | 可忽略 |
| awp | shoot1 | 1.6667 | 1.5999 | −0.0668 s（−2 帧） | 动画先结束，状态机多跑 2 帧 |

量级是 1–2 帧，不是 9 帧。**修法不变、仍然必要**（两边必须用同一个时长），收益按实测说。

## 2. 开关拆分（已实施）

| 开关 | 管什么 | 默认 |
|---|---|---|
| `GunProfile` | CS2 网格、材质、动画、摆放、手臂、特效 | 0 |
| `GunNumbers` | CS2 伤害、距离衰减、散布、后坐 | **0** |
| `GunSoundProfile` | 独立 A/B：只换声音时间表 | 0 |

- `Cs2Weapons.Active` 的判据由 `GunProfile` 改为 `GunNumbers` → **视觉翻默认不再连带改玩法**
  （CS2 的 AWP 不开镜散布 4.63° 只在 `GunNumbers = 1` 时生效）。
- 声音条件不变：`GunProfile >= 0.5 || GunSoundProfile >= 0.5`，
  即 `GunProfile = 1` 仍自动采用 CS2 事件表，`GunSoundProfile` 仍可独立 A/B。
- 三个开关互不隐含。

## 3. 时长仲裁（已实施）

新增单一仲裁者 `CsmcKnifeRig.GetProfileDuration(variant, clipAlias)`，
控制器、`BusyUntil`、`Cs2Rig` 采样三处共用。`Cs2Placement.Active` 已含 `IsGun` 与 `GunProfile`，
所以刀与 `GunProfile = 0` 逐位不变。

`KnifeRigPose` 新增 `RequestedTime`（未截断）与 `Looping`，
`DrawCs2` 用它们按 **CS2 clip 自身长度**重新算采样时刻（循环取模、非循环截断）。

替换的 6 个调用点：控制器 3 处（clip 结束判据、`IsAttaching`、`IsBusy`）、
枪行为 3 处（deploy / reload / 消音器装拆的 `BusyUntil`）。
**未替换** `MeasureHolds`（刀专用离线测量）。

副作用（可接受，已记录）：`GunProfile = 1` 时 CS:MC 那份姿态在自己的时长处冻结——
cs2 路径只从它取 `ClipAlias` / `RequestedTime` / `Looping`，姿态本身不画。
CS2 的 idle 时长是 0（单帧静态），所以 cs2 profile 下待机完全静止，这是 CS2 的真实行为。

## 5. 验收工具（已实施）

### 5.1 `tools/cs2_capture_probe.py`（新）—— 已用它定案

先探针、后定规格：不再未经验证地写 1920×1080。

**Windows 探针结果（2026-09-05）**：Game Bar 输出**原生 1400×1050、4:3、RGBA 无损 PNG、
alpha 全不透明、sRGB gamma 0.45455**，无 pillarbox、无拉伸。

因此以下三项已**写死**进 `cs2_reference_check.py`，成为 INPUT 项的硬校验：

```
comparison_size   = [1400, 1050]
capture_transform = 单位矩阵            （参考图永不重采样）
color             = sRGB, gamma 0.45455
```

四个负例都实测会 FAIL：尺寸写成 1920×1080、变换写成 ×1.3333、gamma 写成 1.0、
以及 RGBA 图 alpha 非全不透明（说明不是原始截图）。
`--template` 可直接生成一份把这些值填好的起始 manifest。

从图像本身判定 PNG 尺寸、pillarbox 黑边、内容矩形、内容宽高比，
与声明的渲染宽高比（1400:1050）比对，给出三种结论之一并写出建议的比较空间。
用合成图自测过三种情况：

| 情况 | 判定 | 比较空间 |
|---|---|---|
| 1400×1050 原生 | unstretched | 1400×1050，不重采样 |
| 1920×1080 带 240 px 黑边 | unstretched | 1440×1080，不重采样 |
| 1920×1080 无黑边 | **horizontally stretched ×1.3333** | 1440×1080，**唯一一次横向 Lanczos** |

另有 `--arm-tone X0,Y0,X1,Y1`：取一块裸露小臂，与 `bare_arm_133` 的色比对照（§6）。

### 5.2 `tools/cs2_reference_check.py`（新，唯一验收入口）

manifest 驱动，六个独立项，**没有总 PASS 字段**：

| 项 | 规则 |
|---|---|
| INPUT | 尺寸/色彩模式/哈希/cvar/mask 与 manifest 一致；**任一缺失即 FAIL** |
| PLACE | 预测出自 `ArmPreview cs2`（出厂 C#）；**offset 固定为读回值，禁止拟合**；每个武器地标 < 10 px |
| PHOTO | 命名为“**固定场景下三枪相对光度一致性**”；一枪拟合唯一全局倍率，另两枪验证：均值 < 5%、形状比 < 10% |
| HAND | 只在**握持/接触 ROI** 内比左手：IoU ≥ 0.85、质心 < 10 px、三个边地标 < 10 px |
| HAND-R | 只报告，不 gate |
| SOUND | 已打包 cue 覆盖率；触发时间记 source-verified |

`--fit-fov` 只打印诊断，不进任何判定。

**HAND 在 `cs2.arms_verified` 为真之前直接 FAIL（`agent_unverified`）**——
“默认探员、无手套皮肤”不算证明。

已测两条路径：

- **缺输入**：只给图不给 mask → INPUT FAIL，PLACE/PHOTO/HAND 全部
  “INPUT failed; nothing downstream can be trusted”，退出码 1。**没有虚假 PASS。**
- **管路连通**（用我们自己的渲染当占位参考，只验管路不是验收）：
  六项全跑通，PLACE 0.1 px、PHOTO 倍率 1.0000、HAND IoU 1.000、SOUND 69/69。
- **`--fit-fov` 逻辑**：23 个 fov 值扫描，最小值正确落在 68。
  顺带印证了 offset 钉死后的鉴别力：fov 66 → 27.2 px、fov 70 → 25.9 px，
  远在 10 px 门槛之外。

**删除** `tools/cs2_videocheck.py`（它那张手填 `LANDMARKS` 表已被 manifest 取代）。

### 5.3 `tools/pbr_emulate.py` + `tools/cs2_render_check.py`

`pbr_emulate` 新增 `mask=<path>` 输出光栅器真实覆盖掩码；
`cs2_render_check` 改读它，删掉“出现次数最多的单一颜色”那段启发式。
离线渲染侧不再有任何背景猜测。

## 6. 手臂对应的 team / agent / loadout

### 导出件能证明的

- 12 套 `glove_*` **全部**用 `bare_arm_133` 当手臂材质；整个导出件里**只有这一种**手臂贴图。
- `glove_fingerless` 本身就是 12 套之一，而 `weapon_arms.vmdl`（每把枪引用的手臂模型）
  把 `bare_arm_133` + `glove_fingerless` 烘成两个 primitive。

→ 手臂网格与材质在导出件里不随 agent 变，`glove_fingerless` 是“无手套皮肤”的默认。

### 导出件不能证明的

某个具体 agent 是否覆盖手臂材质。导出是按武器抓的，没有 agent 侧证据。
**Windows 的判断正确：“默认探员、无手套皮肤”不足以证明匹配。**

### 可测量的判据（替代猜测）

`bare_arm_133` 底色统计（1024×2048，仅不透明纹素）：

```
mean RGB   (178.1, 135.3, 108.1)      median RGB (181, 138, 110)
R/G = 1.316                            G/B = 1.252
```

Windows 步骤：同位置同 cvar，用 2–3 个候选 loadout 各拍一张 idle PNG，
VPS 用 `cs2_capture_probe.py --arm-tone` 取小臂样本比色比（对光照不敏感）。
一致 → 与 agent 无关，任选并记录；不一致 → 取最接近者，把 team/agent/gloves 写进 manifest
并置 `arms_verified: true`。**在此之前 HAND 项不出 PASS。**
