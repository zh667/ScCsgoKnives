## 1. 数据格式：记录 schema 2 → 3

物品布局仍是 **v5，未改**：低 6 位型号、10 位实例 ID、第 16 位仍不被本版设置。型号顺序、实例 ID 分配与回收规则一个字都没动。

记录 schema 升到 **3**，并从"逗号位置"改为**具名字段**，这样以后再加字段是加一个名字而不是加一个没人能校验的逗号位：

```
v=型号,r=弹量,s=消音器拆除,d=当前耐久,m=最大耐久,n=修订号,c=剩余充能秒(-1=未充能),p=CS2涂装ID,
ct=已装计数器,k=有效击杀,gl=已应用等级,gp=待应用等级(-1=无),gv=成长规则版本,rc=本次充能原周期,ov=本枪超额实弹储备
```

- **schema 1（7 字段）与 schema 2（8 字段）的转换器都保留**，跳版本升级按链逐级转换，无需装中间版本。
  转换只补新字段的默认值（无计数器、0 击杀、0 级、规则版本 0、无超额储备），
  **原有的型号、弹量、消音器、当前/最大耐久、修订号、充能剩余、涂装一律原样带过**。
- 未知 schema（含未来的 4）仍在正常加载与自动保存**之前**被拒绝，原文件、原戳、原记录一字不改。
  `GunRegistry.GrowthMode` 出现本版不认识的取值同样拒绝加载，不猜规则。
- 单条记录解析仍是全字段严格校验：字段缺失、多出未知字段、越界、计数器未安装却带击杀或等级、
  等级超过 10、涂装未知或属于别的枪，都整条进隔离区并**原文写回**，不补默认值。
- 弹量上限改为按**这把枪自己的有效容量**校验（`ScGunGrowth.Capacity(型号, 已应用等级)`），
  所以合法满级内格夫的 225 发不再被 150 的原始容量误隔离；同一处校验在事务里也改了。
- `GunDataLayout` 仍是 5。模组版本、物品布局、记录 schema 三者继续分开。

**升级前自动备份：** 读到 schema 1 或 2 的世界，会在**第一次以新格式保存之前**做一次完整世界快照：
写入临时名 → 关闭 → 重新打开逐项核对文件数并解析 `Project.xml` → 才改成最终名。
文件名含来源／目标格式、UTC 时间和唯一后缀（`ScCsgoKnives-gunschema-<从>-to-<到>-<UTC>-<后缀>.snapshot`），
备份内不含其他快照，也不覆盖已有快照。**备份失败即拒绝加载**，不会"没有退路地"升级；
备份路径写进世界记录，日志里也有一条。已备份过的世界不会重复备份；
若升级后未保存就退出，下次进入会重新备份一份独立文件（规范允许）。

**降级后果（必须写进发布说明）：** 0.40.0 保存过的世界是 schema 3；用 0.39.1 及更早的包再打开会被
未知格式保护挡在加载之前（这正是规范要求的行为），不是损坏。回退用上面这份自动备份加对应版本。

## 2. 击杀计数器（首期仅枪械）

### 2.1 安装

装配台新增"安装击杀计数器"。**在原枪上原地安装**：实例 ID、弹量、涂装、消音器、当前/最大耐久、
充能剩余与就绪状态全部保持，不销毁重造，不新增占用物品编码的"计数器版枪型"。

- 费用：金属坯件 ×1 + 精密机构 ×1 + 玻璃 ×1 + 锗块 ×1，制作等级 3。
- 计数从 0 开始。没有任何一版留下过可靠的逐枪历史，因此**不从开火数、耐久消耗、HUD 或玩家总击杀补算**。
- 重复安装在报价阶段就被拒绝，不进事务、不扣料。表满、材料不足、扣料中途异常都整体回滚。
- 仍是可堆叠新枪模板的枪在安装时才登记实例 ID。
- 没有 CS2 官方安装位的型号会被拒绝安装（本轮 35 把全部有，见第 6 节）。

### 2.2 世界规则

世界第一次安装计数器前弹出一次性选择：**计数 + 成长** 或 **仅计数**。存进世界记录，游戏中不提供切换开关——
切换会造成回溯成长或等级回收。未知取值按第 1 节拒绝加载。

### 2.3 归属与去重

- 开火事务提交后立刻冻结凭据（记录 ID、型号、本次射击序号），**致死回调按凭据归属**，
  不读 `ActiveBlockValue`。换枪、丢枪、赠送都不会把最后一击记到别的枪上。
- 一次扣扳机的所有弹丸先按目标合并再结算，霰弹不会重复计数；
  另有按 `ComponentHealth` 的一次性表兜底，尸体补枪不计。
- 不计：创造模式开火、玩家目标（首版不做 PvP 刷成长）、自己、被骑乘的坐骑、非生物、以及测试标记目标。
  原版生存没有驯服系统，"驯养"在此对应"正在被骑乘的坐骑"，这一点如实标注。
- 凭据先入**待写入队列**并随世界保存，再由后续更新通过唯一那套枪械事务写进记录：
  击杀与保存之间退出既不丢计也不重复计。掉落中的枪、尚未拆分的共享记录会保留凭据下轮重试。
  队列上限 1024 条，超过时丢弃最旧的一条并记 error（正常游玩到不了）。
- **写入会推高记录修订号，并推高持有背包的事务版本**，而进行中的换弹把版本变化读作"枪被换走"。
  因此凭据在该背包有换弹、装卸消音器、三连发、R8 蓄力或任何第一人称动作进行时**不写入**，
  等动作结束再写，既不打断换弹也不丢计（自检 `growth/a-reload-in-progress-survives-a-kill-credit`）。
  维修与换肤对话框的报价会因修订号变化而作废并提示重新选择——这是既有的安全路径，不扣料、不换枪。
- 本模组是插件版单机／分屏实现，**没有任何网络提交路径**：计数只由本机权威侧的伤害回调派生，
  不存在"接受客户端提交的增量"这回事。联机版另有代码库，未在本轮范围内。
- **复制品不继承成长**：同一条记录被两处持有（创造复制或异常）时，动作的那一方会分到新记录，
  且新记录不带计数器、击杀与等级；型号、涂装、消音器、弹量、充能照常带过，
  因等级取消而缩小的容量与耐久按第 3 节的守恒与比例规则处理，不清空枪械状态。

## 3. 十级成长

安装为 Lv0，每级 100 次有效击杀，累计 1000 满级。**没有独立经验系统**，等级直接由本枪击杀数解锁。
满级后计数继续累计，等级停在 10。

| 项目 | 公式（L = 已应用等级，全部从**基础值**一次算出，不叠乘） |
|---|---|
| 伤害 | `P0 × (1 + 0.05L)`，满级 +50% |
| 容量 | `C0 + floor(C0×L/20)`，电击枪恒 1 |
| 最大耐久 | `roundHalfUp(M0 × (1 + 0.05L))`，满级 +50% |
| 充能周期 | `T0 × (1 − 0.05L)`，10 秒 → 5 秒 |
| 散布 / 后坐力 | 最终角度 × `(1 − 0.10L)`，Lv10 显式为 0 |
| 射程 | 普通子弹枪 `R0 × (1 + 0.25L)`，Lv10 取消武器自身上限；电击枪 `3.05 × (1 + 0.05L)` |

容量核对：AK 30→45、M4A1-S 20→30、AWP 5→7、新星 8→12、内格夫 150→225、电击枪 1→1，
Lv2/4/6/8 逐格与规划表一致（自检 `growth/capacity-table`）。

**满级射程**用 `RangeMode = 已加载区域`：沿射击方向按区块连续遍历，遇到第一处未加载或未生成的区块列就停，
**不强制加载地形、不穿墙、不自动瞄准、不追踪**；最近的墙体与目标照常先挡住。
序列化、向量与日志里都是有限值（上限常量 512 格），不会出现 Infinity 或 NaN。
Lv9 的栓狙已达 208 格，射线、诊断范围校验与追踪长度都按这一次开火实际算出的距离走，没有残留的 64/128 格硬校验。

### 升级时原枪状态

在同一次事务里完成，且只在等级真正改变时算一次：

- **耐久按比例**：`旧D=0→0`；`旧D=旧M→新M`；其余 `clamp(floor(旧D×新M/旧M), 1, 新M−1)`。
  750/1500 → 1125/2250，0/1500 → 0/2250。报废枪不会复活，可用枪不会被取整成 0。
- **弹量不动**：升级不补弹。容量变大只是之后能装更多。
- **充能按剩余比例**：`剩余新 = 剩余旧 × 新周期 / 旧周期`，10 秒周期剩 5 秒 → 5 秒周期剩 2.5 秒；
  已就绪仍就绪，不会立刻充满。为此记录里新增了"本次充能的原周期"，不靠新周期倒猜。
- **容量缩小不截断弹药**：差额移入本枪绑定的 `ReserveOverflowRounds`，总实弹严格守恒。
  之后换弹先用这份储备补缺口：够补满时不扣外部弹匣；不够时按原费用扣一个弹匣，储备并入枪内。
  管式霰弹逐颗优先用储备。平时这个值恒为 0。
- **升级时机**：换弹、装卸消音器、三连发、R8 蓄力与任何第一人称动作进行中都不应用，
  待动作结束后再应用；待升级等级持久化保存，读档后只应用一次。
- MAG-7 的整匣霰弹费用改为按**当前容量**计（5 发→7 发时空仓换匣扣 7 颗）；
  P90/野牛 ×2、M249 ×3、内格夫 ×5 等按枪型的固定费用不变——这正是容量成长的实际收益。

## 4. 电击枪加强

| 项目 | 0.39.1 | 0.40.0 |
|---|---:|---:|
| 普通/爆头攻击力 | 27 / 27 | **150 / 150**（满级 225 / 225，无额外爆头倍率） |
| 充能容量 | 1 | 1（不变） |
| 充能周期 | 10 秒 | Lv0 10 秒，每级 −0.5 秒，Lv10 5 秒 |
| 满耐久开火次数 | 100 | 100（满级 150） |
| 射程 | 3.05 格 | 3.05 格（满级 4.575 格，保留近距例外） |
| 制作等级 | 3 | **6** |
| 组装组件 | 坯2 + 机3 + 握1 + 锗2 | **坯6 + 机6 + 握1 + 锗4 + 钻石2** |

新配方逐项展开经自检核对：**铁锭 48、煤 12、铜锭 12、锗块 10、皮革 2、木板 1、钻石 2**
（精密机构内部消耗的 6 个坯件已计入）。

**旧枪处理：** 已有电击枪直接使用新基础伤害，**不追缴差价、不换 ID、不删枪重做、不重置任何状态**，
弹量/剩余充能/耐久/涂装/计数原样保留。基础伤害提高不改变耐久上限，只有真正升级才按比例调整。

**维修例外：** 电击枪全损修满仍是 **坯 ×1 + 机 ×1**，部分维修按缺损比例向上取整。
`ScWeaponRepair.FixedFullCost` 把这条从"按组装配方推导"的路径里显式固定下来，
新配方不会间接抬高旧枪的维修价（自检 `growth/zeus-repair-price-ignores-the-new-recipe`）。

## 5. 武器属性界面（P1b）

`ScGunAttributesScreen`，从物品帮助/配方入口与装配台"查看武器属性"进入；`ScAssemblyRecipesScreen`
上新增"武器属性"按钮，两页互通。布局按参考图的信息层次，不复制其配色、字体与图标。

- 左栏枪械列表（图标 + 名称，独立滚动，选中高亮），列表下方最多三行定位描述。
- 右上枪械预览与身份行：名称、型号、涂装、消音器状态、计数器与已应用等级。
- 右下两列各四项属性条：标签 + 十段条 + 精确数值 + 单位。窄屏（可用宽 < 720 逻辑单位）自动收成一列。
- 八项默认：普通伤害（霰弹显示"单次总伤害"，展开写单颗与颗数）、爆头伤害、射程、射速、
  弹匣容量、换弹时间、散布、后坐力。**电击枪把"换弹时间"换成"充能时间"**。
- **属性卡不显示当前/最大耐久，也不显示制作原材料展开表**，自检对全部 35 枪逐行做了字符串核查
  （`growth/attribute-card-has-no-durability-or-materials`）。稀有度、重量、穿甲、附件这些模组没有的属性一律不编造。
  **口径说明：** 这条排除针对的是属性页本身。物品说明（`GetDescription`，帮助里的"说明"页与物品悬浮说明）
  仍保留原有的耐久行和装配配方行——前者属于规范里明确不在排除范围的"原战斗耐久提示"，
  后者去掉会让物品帮助里再也看不到配方，是本轮没被要求的功能回退。若这条理解不对，改回只需删两处拼接。
  物品说明这一版新增一行"击杀计数器：N 次 · LvX"。
- 数值来自战斗真正使用的 `EffectiveGunStats`，不是 CS2 参考表。属性条量程按 35 枪基础表加本规则的成长上限**固定**，
  换枪不重新标定；满级射程显示"无限*"并给出连续已加载区域的说明，不参与归一化；零散布/零后坐力显示 0。
  后坐力、散布、换弹/充能时间标注"越低越好"，不只靠颜色。
- 成长行显示有效击杀、已应用等级、距下一级还差多少、以及待升级提示；满级追加一行收益摘要。
- 由背包实例进入时可在"基础 Lv0 / 当前 LvN / 下一级"之间切换，**预览不分配 ID、不扣料、不触发任何转换**。

## 6. 计数器外观：已就位与仍缺

`tools/extract_stattrak_attachments.py` 从本机 CS2 模型导出取出 Valve 自己的 `stattrak` 与 `stattrak_legacy`
附件变换，35/35 有高清安装位、34/35 有旧版安装位（电击枪本来就没有旧版枪体），同一模型多网格逐字段比对一致。
运行时按当前实际绘制的枪体选择对应附件，**不为装计数器切换枪体年代或 UV**，安装位没有一处是目测的。

**但计数器模块的网格与数字图集本机没有**（无 CS2 VPK），因此本版**不在枪身上画计数器**，
也**不画任何替代品**；计数显示在属性页与物品说明中，安装确认窗口明确写明这一点。
所缺文件的确切 VPK 路径与落地位置见 [StatTrak 资源清单](gun-stattrak-attachments-2026-09-09.md)。

## 7. 手机模组设置与触控布局（P2）

入口：**游戏设置界面 → "CS 枪械"**（`OnSettingsScreenCreated`），暂停菜单在所有平台都能打开设置，
所以这是一条手机直接点得到的路径，**不需要编辑任何 JSON**，也不依赖某个可以被隐藏的战斗按钮。
不再参考、查找或依赖玲兰触控，实现全部是本模组自己的。

配置文件 `app:/ScCsgoUi.json`，独立版本号，与世界 schema 和既有 `ScCsgoKnivesTuning.txt` 完全分离，
不写进世界、不跨设备同步。读不懂时**保留原文件**并以默认值运行本次会话，不覆写。

按九个**稳定功能 ID** 保存：`reload`、`scope`、`silencer`、`burst`、`revolver_alt`、`inspect`、
`knife_heavy`、`throw_strong`、`throw_weak`。不再只存 Main/Secondary 两个共享位，
M4 的消音器按钮不会再把投掷按钮拖走。左右手各存一套，切换不覆盖另一套。

- 每键：显示开关、位置（**归一化到控件区**，不存裸像素）、大小 50%–200%、背景透明度 10%–100%、
  文字透明度 40%–100%。触摸有效边长永远不低于 48 逻辑单位。
- 总开关关闭：模组新增战斗按钮全部隐藏并释放触摸捕获，布局数据保留；
  原版移动、视角、开火与设置入口不受影响（空弹匣扣扳机仍会自动换弹，投掷仍走原版攻击输入）。
- 布局编辑器是独立界面，在**布局副本**上工作：预览区直接拖动，按钮是不参与命中测试的绘制，
  **拖动不可能触发开火、投掷或装卸**。保存才写盘，取消原样恢复，另有"恢复此键""全部默认"。
  重置入口永远可达，按钮拖出屏幕或全部隐藏都不会只能靠删配置文件恢复。
- 会同时出现的按钮重叠时给出文字提示（步枪组、刀具组、投掷组分别判定）。
- 位置按控件区实际尺寸每帧重算并做边界裁剪，旋转、分辨率变化、UI 缩放、左右手切换都跟随。
- 面板背后没有任何透明容器，只有按钮矩形消耗输入；隐藏的按钮立刻交还手指。
- 新增"检视"按钮：此前手机上只能靠长按物品格检视。

## 8. 击杀播报与枪械准星（P2）

- **击杀播报文字**与**击杀提示音效**是两个独立开关，默认都开。关闭只影响表现：
  命中判定、死亡确认、计数、升级、伤害结算与诊断日志一概不受影响。
  关闭时立刻清空当前可见的播报队列，重新打开不补播关闭期间的旧消息。
  中心命中标记（普通/爆头/击杀反馈）不属于播报，保持原行为。
- **枪械准星**：仅在活着、第一人称、手持本版可读可用的枪械、未开镜时显示。
  空手、刀具、手雷、原版工具、记录不可读的枪、创造模板、开镜（含 AWP 覆盖层与 AUG/SG553 枪上瞄具）、
  死亡、菜单、对话框、非第一人称一律不显示，也不残留上一把枪的准星。
  绘制期间通过引擎自己的 `IsCrosshairVisible` 钩子隐藏原版准星，**永远只有一层**；
  不持枪时该钩子什么都不做，原版对挖掘/交互瞄准的决定原样保留。
- 样式：原版样式（复用原版贴图着色）/ 十字线 / 圆点；颜色白、绿、青、黄、红预设。
  颜色只影响这一层常驻准星，**不改共享纹理、不改全局静态颜色**，其他玩家、原版工具、
  镜内十字线、命中反馈与曳光都不受影响。准星是屏幕空间固定大小，不随开镜 FOV 放大。
- 顺带解决了手机上非分屏触控模式看不到准星的问题：这一层是模组自己画的，不受原版那条限制。
