# 0.16.5：对 Windows 十条阻塞问题与 Cs2Effects 运行时缺陷的回复

日期：2026-09-05。所有代码改动都在 VPS 侧完成。

**先说结论：十条全部属实（第 9 条部分属实），已全部修掉。
另外你们报的 `Cs2Effects` 运行时缺陷比描述的更严重——0.16.4 里曳光一条都没生成过。**

## 零、Cs2Effects 运行时缺陷（最严重，先说）

### 复现

新增 `ArmPreview loadcheck` 直接调用出厂 C# 的五个加载器。在 0.16.4 上：

```
FAILED: 3 of 34
  FAIL effects/ak47/loaded  -> Cs2Effects.Get returned null
  FAIL effects/m4a1s/loaded -> Cs2Effects.Get returned null
  FAIL effects/awp/loaded   -> Cs2Effects.Get returned null
```

### 两层原因都属实，且后果比描述的重

1. `Flash.Lifetime` 是 `float[]`，而 AK 的 `lifetime` 是标量 `0.05`（M4 消音那条却是 `[0.3, 0.85]`）→ 反序列化抛异常。
2. `sequence_frames` / `color_min` / `speed_max` / `max_length` / `length_fade_in` 是 snake_case，
   `PropertyNameCaseInsensitive` 只忽略大小写、不忽略分隔符 → 即使不抛异常也会保持默认值。

**后果**：整个文件加载失败 → `Cs2Effects.Get` 全部返回 null →
`TracerFrequency` 返回 0 → `QueueTracer` 直接 return，**0.16.4 里曳光一发都没画过**；
`GetFlash` 返回 null → 火光退回旧的写死包络，CS2 的寿命/序列/颜色/透明度/淡出全部没生效。

### 修法（三层）

1. **统一 schema**：`tools/cs2_effects.py` 改为输出 PascalCase，
   `Lifetime` / `Alpha` 一律写成数组，格式号升到 `ScCsgoKnives.Cs2Effects/2`。
2. **钉死契约**：`Cs2Effects` 与 `Cs2Weapons` 的每个属性都加 `[JsonPropertyName]`，
   删掉 `PropertyNameCaseInsensitive` 这根拐杖；另加 `ScalarOrArray` 转换器，
   数字和数组都能读——按你们要求"lifetime 同时支持标量与数组"。
3. **真正的运行时自检**：`tools/cs2_runtime_selftest.py` → `ArmPreview loadcheck`，
   调用 `Cs2Effects` / `Cs2Weapons` / `Cs2Rig` / `Cs2Sounds` / `Cs2SkinnedMesh`，
   断言**到达 C# 的值**而不是文件能否解析。

修完 **70 项全通过**，之前被默认掉的值现在都到位：

```
effects/ak47/flash.seconds   0.05 s
effects/ak47/tracer.speed    20500
effects/ak47/tracer.length   1200
effects/awp/tracer.freq      1
weapons/ak47/spread          0.4016 deg
rig/ak47/animates            magazine moves 6.23 in mid-reload
```

`cs2_effects_selftest.py` 也补了 D 项：文件里不许再出现 snake_case 键，
`Lifetime`/`Alpha` 必须是数组。**两层防护：Python 防文件回退，loadcheck 防运行时回退。**

你们那句"不要只让 Python cs2_effects_selftest PASS"是对的——
旧的 Python 自检只把 JSON 对着 vdata/vpcf 核了一遍，从没验证过运行时能不能读。

## 一、十条逐条

### 1. ArmPreview 只输出 8 个地标 —— 属实

原来只有 `muzzle / wpnEnd / wpnTip / hand_R / hand_L / trigger / clip / finger_index_1_R`。

**已扩到 27 个**，含 `bolt`、`bolt_action`、`rail`、`cliprelease`、`silencer`、`muzzle2`、
`weapon`、`weapon_offset`、`arm_lower_*` 与十余根手指骨。

但那三个名字——`index_knuckle_over_top` / `thumb_edge_on_receiver` /
`cuff_crosses_frame_edge`——**不是骨骼**，是我在上一份交接里自己编的轮廓特征，
`ArmPreview` 不可能输出它们。**这是我的规范错误，已按你们第 5 条允许的方式改掉判据**，见下。

### 2. HAND 遇到未输出的地标不 FAIL —— 属实

原代码只记 `status` 然后 `continue`，`worst_landmark` 保持 0，三个地标全没比也能过。

**已修**：manifest 里列出的地标，只要有一个 rig 产不出来，PLACE / HAND 直接 FAIL 并列出名字。
负例实测：

```
FAIL PLACE  worst named landmark 982.1 px
FAIL HAND   the rig cannot produce these left-hand landmarks, so they were never
            compared: ak47_idle.png/index_knuckle_over_top
```

### 3. left_hand_mask 没有 z-buffer、没有武器遮挡 —— 属实

原来是把手臂三角形投影后做 OR，没有深度测试。

**已修**：新增 `tools/cs2_raster.py`，武器与双臂进同一个 z-buffer（透视校正深度），
每个像素归属赢家。差距实测：

```
ak47 idle 左手：无遮挡 36 339 px  ->  可见 23 604 px   （无遮挡大 54%）
```

而且握持 ROI 正是遮挡最强处。负例实测：拿无遮挡 mask 当参考，HAND 现在

```
FAIL  worst IoU 0.292 (min 0.85); worst contour p95 86.2 px; worst centroid 39.5 px
```

——以前这会被当成几何错误误判，现在是被正确地判为"这张 mask 不是可见轮廓"。

### 4. 没有轮廓 Chamfer/P95 —— 属实

上一份规范写了"轮廓 Hausdorff 距离"，实现里只有 IoU、质心和地标。

**已补**：`cs2_raster.chamfer()` 给出对称轮廓距离的 mean / P95 / max，
PLACE 与 HAND 都用，判据写进报告。不再声称四项都已实现。

### 5. PLACE 只比骨骼点，没比可见剪影 —— 属实，且判据已按你们说的改

你们那句"内部骨骼原点不一定能从截图准确点出"是对的，这也解释了第 1 条那三个编造的名字。

**新判据**：

| 项 | 门槛 |
|---|---|
| PLACE | 武器**可见剪影** IoU ≥ 0.90、轮廓 P95 < 10 px、质心 < 10 px、剪影极值点 < 10 px |
| HAND | 握持 ROI 内**可见**左手 IoU ≥ 0.85、轮廓 P95 < 10 px、质心 < 10 px |
| 两者 | 命名地标降为**可选诊断**；一旦 manifest 里写了，就必须全部解析成功，否则 FAIL |

"剪影极值点"= 最左/最右/最上/最下 + 主轴两端，**两侧用同一段代码从 mask 算出来**，
不需要人去截图上点，也不依赖内部骨骼原点。

### 6. --arm-tone 没有阈值 —— 属实

而且你们指出的物理问题也成立：渲染后的 RGB 比值经过有色光、阴影、色调映射，
不能当底色纹理的硬证明。

**改成受控实验**：`cs2_capture_probe.py --compare b.png --arm-roi X0,Y0,X1,Y1`。
同一位置、同一角度、同一 cvar、同一地图，**只换 loadout**，两张图相减。
场景相同，所以小臂 ROI 上的差异就是 loadout 本身。

```
阈值：ROI 内最大通道差 <= 2/255  -> 手臂与该 loadout 无关
```

自测（合成图）：+1 噪声 → `max delta 1，PASS`；+40 的"另一副手套" → `max delta 40，DIFFER`。

`--arm-tone` 保留，但输出里明确标为 **WEAK EVIDENCE**，只在 `--compare` 判定 loadout 有差异时当 tie-breaker。

**并且把 `arms_verified` 这个可以人工随便置 true 的布尔删了**，换成结构化的
`cs2.arms_evidence`（method / loadouts_compared / arm_roi / max_channel_delta），
checker 会校验 method 与阈值。缺它或超阈值 → HAND 直接 `agent_unverified` FAIL。负例实测通过。

**另外**：我试过从 CS2 安装目录直接找 `bare_arm*` 拿资产证据，
但 CS2 的资源都在 VPK 里，Everything 索引看不到。这条只能靠上面的受控实验，
或你们在 Windows 用 Source2Viewer 从 VPK 里导 agent 模型直接看。

### 7. INPUT 声称缺输入必 FAIL 但并没有 —— 属实，三点全中

- `gamma` 缺失会通过 → **已改为必填**；
- `sha256` 缺失会通过 → **已改为每个参考文件必须带哈希**；
- 只核 manifest 里写的 gamma，不读 PNG 元数据 → **已改为读文件自身的 sRGB chunk / gAMA / ICC**，
  没有任何一项就 FAIL，gAMA 不是 1/2.2 也 FAIL。

三个负例实测全部正确 FAIL，且下游三项一律
"INPUT failed; nothing downstream can be trusted"。

### 8. SOUND 没检查 OGG 是否真在待验收包里 —— 属实

**已改**：manifest 必须写 `package.path` 与 `package.sha256`；checker 打开该 `.scmod`，
先核 SHA-256，再逐条确认每个 `Asset` 对应的 OGG 确实在包内。

负例实测（人为从包里删掉 `movement3.ogg`）：

```
FAIL  0 cues have no asset name and 11 name a file the package does not contain
```

### 9. PHOTO 用 gun 名当 key —— 部分属实

**属实的部分**：`theirs[shot["gun"]]` / `ours[shot["gun"]]` 确实按枪名索引，
两个同枪 shot 会静默互相覆盖，这是不该有的脆弱。

**不属实的部分**：在**当前模板下并不会发生**——PHOTO 与 HAND 都只取 `state == "idle"`，
而模板给 M4 的第二张是 `idle_silenced`、AWP 的第二张是 `idle_scoped`，
所以两张 M4 不会同时进入光度集合。

不管怎样都**已修**：改为按 shot 的 image 名索引，并且显式拒绝同一把枪出现两张：

```
FAIL HAND  two idle shots of m4a1s; pick one state per gun
```

### 10. 注释仍写 M4 inspect CS:MC=5.0、会冻结 —— 属实

`CsmcKnifeRig.cs` 与 `CsmcFirstPersonRenderer.cs` 两处都写着 "5.2999 against CS:MC's 5.0"。

**已改**为本轮实测的说法：CS:MC 的 `Duration` 字段是 **5.3**（5.0 是它采样曲线停的地方），
inspect **不受影响**；真正被影响的是 m4a1s deploy（CS2 1.1332 对 1.1000，最后一帧被切）、
ak47 reload（−1 帧）、awp shoot1（−2 帧）。运行时代码未动。
