## 4. 具体改造方案与验收

### A. 投掷基础体验：F01–F04

**灰色烟雾 F01**

- 将烟粒子与烟内遮罩统一为中性灰；保留明暗层次、柔边和运动，不画成一块均匀灰球。
- 核对图集 RGB/alpha 和混合模式，避免仅改 tint 后仍因源图或光照产生色偏。
- 验收：白天、夜间、逆光及烟内视角均不出现额外蓝绿偏色；Full/Lite/Mini 视觉遮挡能力一致。

**投后第三格 F02**

- 默认目标为快捷栏第三格（索引 2）。成功投出、投掷收尾到点时切换；保持现有出手后才扣量的事务。
- 第三格为空：建议回到仍有效的上次武器槽；没有可用目标则留在当前槽。第三格有物品则按请求切过去，不擅自更换该格内容。
- 若玩家已经手动切槽、打开界面或改变背包，取消延迟自动切换；未投出、取消准备、生成失败、达到活动上限均不切槽。
- 验收：第三格为刀/枪/其他物品/空格，以及最后一枚投出、堆叠仍有剩余、第三格恰是原投掷槽的情况；鼠标和触屏一致。

**速度与力度 F03**

- 将强投速度、轻投速度、上抛角度、玩家速度继承系数集中为可校准参数。现值为 `14 / 6 / 0.18或0.08的方向上抬 / 0.5`，方向上抬不是角度单位。
- 先记录基线：站立、前进、后退、横移、跳投，在相同地形/仰角下的落点距离与飞行时间；检查角色自身走速及世界尺度，再提高强投初速，单独调轻投。
- 明确玩家速度在出手瞬间采样一次；研究完整三维继承对跳投的影响，避免坐骑/载具速度造成异常穿墙。
- 排查帧率耦合：目前每帧物理最多推进 0.5 秒，引信却减完整 `dt`，严重卡顿时可能“飞得少却提前触发”。物理与计时采用一致的时间推进策略。
- 验收：跑投比站投远、反向运动按预期缩短距离、轻投仍可近距离控制；30/60/120 FPS 和卡顿恢复后的轨迹无明显分叉或穿墙。

**烟雾落稳触发 F04**

- 建议状态：准备 → 已投出/飞行 → 碰撞弹跳 → 有地面支撑且速度低于阈值持续一小段时间 → 起烟。记录稳定时间，并在再次腾空时清零。
- 删除“年龄达 4 秒即可在空中起烟”的正常触发条件；另设异常滞留清理上限，不能用强制空爆兜底。水面、斜坡、台阶、地形被挖掉时采用明确的支撑判定。
- 引信最短等待时间与落稳时间分别维护，弹跳次数不作为唯一判据。受热提前触发是 F05 的独立例外，避免互相覆盖。
- 新增状态在新世界正确初始化并在同版本保存/读取；不实现跨版本迁移。保存/读取飞行中和弹跳中的烟雾弹不会立即误触发。
- 验收：高抛、反弹墙壁、滚下台阶、斜坡、落水、存读档后继续运动；正常烟雾不再在明显弹跳过程中起烟。

主要入口：`World/SubsystemScGrenades.cs`、`ScGrenadeState.cs`、`ScGrenadePreparation.cs`、`ScThrowTransaction.cs`、`ScGrenadeVisuals.cs`。

### B. 统一烟雾遮挡及互动：F05–F07

**资源边界与 M0 必过验证**

CS2 体积烟是运行时系统，本地烟贴图序列只能复用外观，不能导入其体素/密度/爆炸扰动实现。F07 是视觉方案最不确定的一项，F06 依赖它选定的统一密度规则。

M0 先做最小实机场景：一团烟遮挡烟内/烟后实体和地形、烟前物体正常、隔墙不过度遮挡、摄像机进入烟、局部爆炸开口并恢复。核对深度取得方式、opaque/transparent pass 时序、透明物体和多摄像机，并在 Windows 与手机后端验证关键能力和帧时间。“接口存在”不是通过标准。如果深度路径不满足条件，M0 就确定并验证替代方案，记录外观限制；不把未验证的渲染路线留到 M2 才决定。

**先建立统一烟体密度/可见性查询（F07 的基础）**

- 复用 `ScSmokeVolume.InsideLength`，定义随成长、消散及爆炸扰动变化的密度；玩家渲染、AI 视觉和后续炸烟共同读取，不各自维护互相矛盾的球体。
- 现有烟雾半径 3、寿命 15 秒，已有烟内遮罩，但最大 alpha 为 230/255，仍会透出背景；单纯增加粒子数无法保证遮挡。
- 第一轮实机分别查明：烟外看穿、人在烟内看穿、透明实体覆盖烟、名称/血条/命中提示泄露目标位置。当前粒子绘制序号为 10，本地参考模型渲染还有 99/201 的后续 pass；透明 pass 顺序是候选原因，不能提前认定。
- 优先实现跨越烟体视线的深度相关遮挡，并让烟内画面按实际浓度过渡。确认当前后端深度纹理/场景合成能力；若不满足，采用受控的烟体渲染与实体可见性处理组合。隐藏实体只可作为补充，不能留下清晰可见的烟后地形、武器或轮廓。
- 不全局关闭全部实体，不让烟遮住位于烟前的人物或墙前物体；姓名标签等表现遵循同一视线条件。AI 保持听觉/记忆行为，消除其纯视觉透烟。
- 验收：烟外看烟内、烟外看烟后、烟内看烟外、烟前实体、边缘、重叠烟、隔墙烟、第三人称摄像机进入烟、多个玩家视口及透明物体。烟浓时无法辨认应遮挡实体；边缘自然过渡。

**火触发烟 F05**

- 建议默认解释为“已经投出的、尚未起烟的烟雾弹进入有效燃烧区域后，提前释放烟雾”，包括燃烧瓶和燃烧弹产生的火区。绝不引爆背包里的烟雾弹。
- 检查弹体运动轨迹与实际有地面支撑的火点接触，不能只用两个大球相交；隔墙、楼上楼下、已经熄灭的区域不算。
- 统一一次更新内的事件顺序：火区有效性 → 弹体接触/受热触发 → 烟成长 → 灭火结算，避免遍历顺序决定结果；每枚烟只触发一次。
- “燃烧瓶让烟提前释放”是本模组拟实现的互动，确切接触阈值需校准；若另做飞行中的瓶子直接碰撞烟弹，应单列补充，当前不假定已有该碰撞机制。
- 验收：烟投进火、火投到等待中的烟附近、近距离擦边、隔墙、重叠火、最后一帧熄火、存读档；烟起后保留现有灭火能力且无重复音效。

**高爆炸烟 F06**

- 建议采用“爆炸附近暂时吹开烟雾，随后恢复”的 CS2 风格效果。范围、持续时间和恢复曲线集中配置；不默认把整团烟永久删除，也不重置烟寿命。
- 新增有限寿命的爆炸扰动区域，对统一密度查询做局部削减；可见画面与 AI 视线同时打开，同步恢复。只有高爆触发，闪光、诱饵不触发。
- 处理多个高爆叠加、烟边缘爆炸、隔墙隔层、烟即将自然消散，以及扰动中存读档；保持原有烟灭火结果，不凭烟被吹开凭空恢复已熄灭火区。
- 验收：中心炸开、边缘只开局部、多烟/多雷、隔墙不穿透、恢复时长稳定；开口期间确实能看到/追踪目标，恢复后重新遮挡。

### C. 枪械耐久：F10

本阶段方案：**按实际击发磨损，耐久归零后禁止射击并保留枪，装配台消耗零件修满。** 只为枪械增加耐久，不扩展到刀具等其他物品。当前每版新建世界，不做旧存档迁移；但不能只把 CSV 的 `Durability=-1` 改为正数，仍需解决当前枪型/弹量数据与磨损数据冲突。

#### C1. 磨损触发规则

| 操作 | 生存模式磨损 |
|---|---|
| 普通枪实际发出一发 | 1 点，打空、打墙、命中生物均相同 |
| 自动枪连续射击 | 每发 1 点；帧率和是否命中不改变消耗 |
| 三连发 | 实际发出几发扣几点；中途打断不预扣未发出的子弹 |
| 霰弹枪射击一次 | 1 点，不按散射弹丸数扣 |
| 双持手枪 | 每次实际击发 1 点，两只枪属于同一件武器，共用该件武器耐久 |
| 电击枪实际放电 | 1 点；已放电但未命中也计，未充能的空击不计 |
| 空枪扣扳机、换弹、切枪、检视、装拆消音器 | 0 点 |
| 创造模式 | 不磨损；已有磨损不自动清除，可通过维修恢复 |

扣弹/耗电与扣耐久在同一次逻辑操作中提交，只有实际生成射击才扣。动画播放、射线命中回调及多个摄像机绘制都不能重复扣耐久。电击枪的充能与耐久分别保存，自动充电不恢复耐久。

#### C2. 各枪类满耐久（首轮测试基线）

| 枪类 | 满耐久 / 可击发次数 | 参考使用量 |
|---|---:|---|
| 手枪、双持手枪 | 1,200 | USP-S 约 100 个满弹匣 |
| 冲锋枪 | 2,000 | MP9 约 67 个满弹匣 |
| 突击步枪 | 1,500 | AK-47 约 50 个满弹匣 |
| 霰弹枪 | 300 | 300 发霰弹 |
| 栓动狙击枪 | 200 | AWP 约 40 个满弹匣 |
| 半自动狙击枪 | 500 | 20 发容量约 25 个满弹匣 |
| 机枪 | 4,000 | M249 约 40 个满弹匣 |
| 电击枪 | 100 | 100 次放电 |

为全部 35 把枪显式登记所属类别，不能按名字猜测；满耐久与单次磨损集中在玩法配置中，支持按枪覆盖。整数记录实际剩余点数，百分比仅用于显示。平衡测试主要调整寿命和维修成本，不隐式修改伤害或射速。

#### C3. 正常、低耐久与损坏状态

- 大于 20%：正常使用；大于 0 且不超过 20%：正常使用，独立耐久显示变橙色；等于 0：标记“损坏”，禁止射击。
- 初版不加入随机卡壳，不因低耐久降低伤害、精度或射速。耐久属于维护成本，射击表现保持可预测。
- 最后 1 点允许完整打出一次射击，再变为 0；自动射击或三连发到这里停止。不能扣掉下一发子弹后才发现枪已损坏。
- 损坏枪仍可切换、检视、转移及维修。建议允许正常换弹和消音器操作，但仍不能射击；这些动作不会修复枪。枪型、枪内余弹及消音器状态原样保留。
- 归零只提示一次“枪械已损坏，请到装配台维修”；再次按射击可给短暂反馈，但持续长按不刷屏、不无限播放提示音。
- 维修后恢复原满耐久，可反复维修；不追加永久降低耐久上限的惩罚。

#### C4. 装配台维修与材料费用

沿用现有装配台，增加“组装 / 维修”入口。维修列表列出玩家背包中实际存在且未满耐久的枪，按武器实例选中；同款枪显示各自耐久及所在格，避免修错。界面展示枪名、当前百分比、维修后 100%、材料需求与当前持有数，提供“维修”按钮。

已核对现有材料为：金属坯件、精密机构、握持组件、光学组件。维修以金属坯件和精密机构为主，按枪型配方决定是否需要其他组件，不新增维修专用物品。

满修材料表在实施时依据 `ScWeaponCrafting` 的真实组装成本制定，目标为重新组装成本的约 20%–30%。这是按材料价值估算的平衡目标，不是把所有原配方数量逐项乘 0.25 后取整；低成本枪的整件零件粒度较粗，需要明确列出实际比例。满修至少有一项正数费用；避免每种材料都向上取整导致维修反而接近重新组装。

对已确定的满修材料表，按缺损比例计算本次需求：

`材料 i 的需求 = ceil((满耐久 - 当前耐久) / 满耐久 × 材料 i 的满修数量)`

满耐久单独返回“无需维修”，不扣材料。满修表中数量为零的材料不参与计算。例：某枪假设从零修满需要 8 个指定零件，则 75% 耐久收费 2 个，50% 收费 4 个，10% 和 0% 均收费 8 个。这只是取整公式示例，**不是 AK-47 或所有枪的实际满修配方**。材料粒度会让临近损坏的维修同价、少量磨损至少消耗一件，界面提前显示准确费用。

- 生存模式材料齐全后点击立即修满，不做等待进度条；首版只提供修满，材料不足不部分扣除或部分维修。
- 默认维修不增加新的等级门槛，已获得的枪可凭装配台和材料维护；组装等级沿用原规则。
- 满耐久、目标已移走、目标状态变化、材料不足、玩家离开/装配台被拆除时，取消或刷新报价，不消耗材料。
- 点击时复核目标实例、耐久、背包修改标记和材料，扣料与恢复耐久一次提交；异常失败回滚已经扣掉的材料。按钮连点不得重复扣款。
- 修理只改耐久，不补弹、不卸弹、不改枪型和消音器。创造模式维修免费，也必须明确点击执行。

#### C5. HUD 与物品显示

保留现有弹量 HUD，在旁边或下一行显示 `耐久 86%`；物品详情显示精确值，例如 `1290 / 1500`。低耐久显示橙色，损坏显示文字“损坏”。百分比显示不能把仍大于零的耐久显示成已损坏，低于 1% 可显示 `<1%`；临近满值但尚未满耐久可显示 `>99%`，避免取整误报满耐久。

耐久用独立文字或进度条表示，不改变命中标记颜色。命中标记始终遵循 F12：普通命中白色、爆头未击杀黄色、击杀红色。打开维修列表时可以看到同款不同耐久枪，不通过物品名称永久拼入会不断变化的数据。

#### C6. 新世界数据设计与物品流转

1. **允许直接设计新格式。** 不实现旧三代枪械解码迁移、旧枪补满耐久、旧世界升级或跨版本降级验证；现有解码代码若有其他用途可以暂留，但不作为本轮验收和工期。实现新的统一创建/读取/更新入口，同步更新组装、初始装备、创造栏和 `ScCsgoBox`。
2. 当前 v3 data 已使用枪型、弹量、消音器和格式标记；本地 `Terrain` 参考实现把 data 放到 value 的高 18 位，最高位还涉及符号扩展。6 位型号、8 位弹量和最高 4,000 点耐久所需的 12 位再加消音器，明显装不进原字段。没有旧存档限制也不能简单移位拼接。
3. M0 以“物品数据存实例 ID + 世界级枪械状态表”为主方案验证。现有背包保存主要是 Value/Count；`WorldItem.DictionaryForOtherMods` 或攻击事件字典不是自动随库存流转的持久字段。除非当前 API 验证发现真正完整的替代接口，否则按实例方案推进，记录 ID 位宽及正负值处理。
4. 最小持久状态至少包括型号、当前弹量、消音器状态、当前/最大耐久及必要的电击枪充能状态。实例身份与物品一起走，不能绑定背包格号、玩家或枪型。**首版 ID 单调分配且不复用已分配 ID**，保存下一 ID 与状态表，检查容量耗尽并安全拒绝新建，不能回绕覆盖旧枪。先验证状态表增长和同版本保存一致性；当前每版新世界，不为了抢做回收增加误删风险。
5. 新组装枪满耐久且为空枪；初始装备、开箱和创造获得的新枪满耐久，弹量遵循各自现有来源规则。实际物品创建时初始化，UI 配方和开箱预览不创建枪实例、不占用 ID、不改变被预览枪状态。
6. 移动、换槽、入箱、出箱、死亡掉落和拾取转移同一实例；同款不同枪各有耐久且不合并堆叠。创造复制现有枪时复制其状态并生成独立身份，不共用可变记录；从创造目录新取一把则初始化满耐久。
7. 换弹、开枪、消音器切换、维修均通过状态更新入口保留其他字段，不能沿用只传型号/弹量的创建方式让“换弹顺便满修”。第三人称和第一人称读同一件枪的状态。
8. 同版本的新世界退出重进必须保留全部枪状态。字段缺失、非法数值或失效 ID 应有明确的安全失败与诊断，不能让数组越界；这些是当前版本数据完整性处理，不扩展成旧格式迁移器。
9. 枪械脱离 `ScNoDurabilityBlock` 的封闭无耐久接口，耐久由模组控制；核对原版 `DamageItem`/近战工具磨损不会再次扣耐久、改写型号或在归零时自动删除枪。其余物品仍保持无耐久。

后续若需回收，先证明持有者扫描完整。本地参考 `SubsystemItemsScanner` 包含各子系统/实体的 `IInventory`、掉落物、投射物和移动方块；还需处理联动暂存、转移中的事务及其他未覆盖持有者。不能只扫背包/箱子/掉落物，也不能在调用 Save 时立即删除/复用 ID。回收必须基于一致快照并确认保存成功，覆盖保存失败和回滚情形；本轮首版不实施 ID 复用。普通移动、拾取保留 ID，创造复制和新获取分配新 ID，不能把所有拿取统一当作复制。

### D. 第三人称完整枪械与投掷物：F08、F09、F11

本节“完整”指约定动作类型齐全、人物持握合理、枪体部件与事件同步；**第三人称人物动作为手工姿态曲线，不来自 CS2，不承诺完整复刻 CS2 人物动作。** 原版简化身体/头/四肢骨骼无法忠实呈现 CS2 肘、腕、手指的所有细节。

**先统一角色动作状态，再挂接渲染**

- 将“当前动作、开始时间、进度、枪型、部件事件”归属到玩家/实体，第一、第三人称读取同一份状态。现有 `KnifeAnimationController` 按 `ComponentFirstPersonModel` 存储状态，必须验证不绘制第一人称时仍正确推进。
- 只在更新阶段提交开火/换弹/投出事件，渲染只采样；切视角、多个摄像机绘制同一人物不重复扣弹、出声或生成弹体。
- 角色之间动画状态和蒙皮缓冲独立；现有缓存中可变的 `SetPose`/`Skin` 数据不得导致多人同帧互相覆盖。

**M3 前的缓存与多人预算**

源码确认刚性武器缓存为 8 项、蒙皮武器缓存为 8 项、动画缓存为 12 项；地面/背包枪静态网格为 12 项并有两秒近期使用保护。因此大量不同枪同屏动画存在抖动风险，但不能断言静态掉落堆一定每帧重建；托管缓存淘汰也不等于完全释放 GPU 对象。

- 明确当帧/活动对象对资源的持有关系，正在使用的资源不得被淘汰；不可变几何共享，当前骨骼矩阵和可变蒙皮结果按实体分开。
- 预算同时覆盖网格、动画、纹理/GPU、临时分配；不能只把容量 8 改大作为完成标准。保留主线程创建 GL 资源规则。
- 验证超过 8 种不同武器同时播放、同款多人不同动作、大量静态掉落枪、快速来回切枪、多个摄像机以及退出世界释放。记录加载/重建次数、缓存未命中、托管内存和帧时间，重点检查手机。
- 按实测设置热资源保护、闲置淘汰及必要的距离细节策略。Full/Lite/Mini 可以有资源预算差异，但不能改变玩法和动作事件。

**完整模型与材质 F08**

- 复用现有 CS2 武器模型和部件，去掉第一人称手臂/手套及仅服务镜头的偏移；按枪械实际尺寸及握把锚点挂到原版角色手部。
- 为枪种定义握持姿态/偏移，避免把背包单位盒缩放直接用作第三人称。分材质绘制枪身、弹匣、消音器、镜片等，复查背面、枪托及内部是否缺面。
- 接入 `OnModelDrawExtra` 时只替换目标模组手持物，保留原版人物、其他装备和必要额外绘制；明确骨骼矩阵是世界空间还是摄像机空间，避免二次套视图变换。
- 使用世界光照、深度测试和适当剔除；确认阴影、远处裁剪、透明镜片与烟雾的顺序，避免第一人称常亮效果迁入第三人称。

**原版手臂和动作 F11**

- 保留原版身体、皮肤及手臂外形，只控制其可用骨骼姿态。CS2 手指/肘部骨骼无法直接一一映射到原版简化手臂，采用按枪类设计的姿态曲线与握持约束；不要求原版手臂出现不存在的关节。
- 人物抬手、支撑、换弹与收手均为按枪类手工编制，可参考 CS2 节奏；直接复用仅限可用的枪体部件运动与时间点。
- 动作范围：持枪待机、走跑/转身、上下瞄准、开火后坐、切入/切出、普通及空仓换弹、逐颗装弹、栓动拉栓、消音器装拆、检视；双持手枪两只枪与左右开火对应，电击枪独立处理。
- 枪内运动部件优先采样已有 CS2 动画；弹匣拔出/插入、拉机柄、枪栓的事件时间与现有第一人称相符。角色移动/跳跃与上半身动作叠加，死亡/睡眠/游泳等状态有明确优先级。
- 不把第一人称整段模型直接缩小放到角色胸前。完整动作以合理握持、部件运动和时间一致为验收依据，原版手臂简化带来的动作细节差异需记录。

**投掷物 F09**

- 拔销、强/轻投准备及第三人称出手的人物姿态同样手工制作；viewmodel 片段仅提供参考和事件时间。弹体模型与配件可复用，飞行自旋、碰撞后旋转和落稳姿态由本模组计算，不声称来自 CS2 飞行动画。
- 区分手中完整物、拔销/持有阶段、释放后弹体；复用 `ScGrenadeWorldMesh` 的配件过滤，核对拉环/握片消失时机和燃烧瓶打火机/火焰显示。
- 修正当前使用 `camera.ViewPosition + direction * .45` 的生成方式：方向从准星射线求目标，弹体从角色手部附近出发，随后朝目标解算；角色到出手点以及出手点到目标都做近墙处理。
- 第一/第三人称切换不改变同一姿态下的真实出手逻辑；肩后摄像机、镜头贴墙时不从摄像机或墙后生成弹体。
- 支持拔销、强投准备、轻投准备、松手出手、取消、投后收尾；真正释放事件与手中模型隐藏、物品扣除和弹体出现同一时刻，手中不残留一枚复制品。
- 飞行模型旋转与静止状态分离；不让落地静止的诱饵还按年龄持续自转。保存姿态所需的最小状态，重进世界不突变。

覆盖样本先选 AK-47、M4A1-S、AWP、Nova、M249、Dual Berettas、Zeus 及六种投掷物，验证架构后扩展到全部 35 把枪。验收含正面/背面/左右视角、蹲姿/移动/跳跃、贴墙、快速切视角、动作中换槽、多人同屏和低帧率。

主要入口：`Animation/KnifeAnimationController.cs`、`Rendering/CsmcFirstPersonRenderer.cs`、`Cs2SkinnedMesh.cs`、`Cs2RigidMesh.cs`、`Cs2Placement.cs`、`Blocks/ScGunBlock.cs`、`ScGrenadeBlock.cs`、`ScGrenadeWorldMesh.cs`、`Mod/ScCsgoKnivesModLoader.cs`；建议增加独立第三人称渲染和角色动作状态模块。

### E. 爆头判定与黄色命中标记：F12（追加）

**可行性与兼容边界**

黄色反馈是局部修改；准确的爆头检测为中等难度。原版生物种类有限，可以逐类验证，适合先做。不能保证任意模组生物零配置准确识别头部。

| 对象 | 方案 | 难度与边界 |
|---|---|---|
| 原版人形、四足、鸟类、不飞的鸟类四类模型 | 利用 `Head` 骨骼及头部网格建立局部判定体，随当前姿态变换到世界坐标 | 约 3；本地参考四个模型类均有 `Head` 查询，仍需校准头区与缩放，不飞鸟还要处理颈部 |
| 原版鱼类 | 按实体模板配置头区，默认绑定身体坐标；原模型类有 Body/尾部/Jaw，无标准 Head 查询 | 约 3–4；Jaw 可辅助定位，但开合下颌不能直接代表整个头 |
| 其他特殊体型或缺少独立头骨骼的生物 | 按实体模板/模型配置局部头区，跟随身体或指定骨骼 | 约 3–4；不能拿身体最上面一截统一充当头 |
| 沿用原版模型结构的模组生物 | 复用已验证规则，检查缩放、偏移、骨骼层级及头区大小 | 约 3；骨骼同名只是识别线索，不足以保证头部尺寸一致 |
| 自定义骨骼、多头、动态变形、独立命中组件的模组生物 | 提供配置/适配接口，指定头骨骼、局部位置与大小，或由模组返回有效头区 | 约 4–5；按具体模组验证，无法可靠识别时仅按普通命中处理 |

**当前源码事实**

- `SubsystemScGunBlockBehavior` 使用 `m_bodies.Raycast(start, end, 0.35f, ...)`，得到的是扩大的身体碰撞盒交点；没有现成的头部结果。这个交点不能直接拿去比较眼睛高度或判断是否落在头模型里。
- 霰弹目前逐弹丸检测后按目标合并伤害，只留下一个命中点。新增爆头必须先按弹丸判断部位，再累计身体/头部伤害，不能因为其中一颗中头就把整枪伤害都翻倍。
- `ScCombatFeedback` 目前为普通命中白色、击杀红色；`ScSurvivalBalance.Attack` 在攻击前后比较 `ComponentHealth`，只对确认扣血的结果报告命中。可以在此链路传递部位信息，保留“实际造成伤害才提示”的规则。

**实现方案**

1. 新增头区描述与命中结果，例如实体/模型匹配、骨骼名、局部偏移、判定体尺寸，以及 `Head/Body/Unknown`。优先使用经过验证的原版配置；通用识别只有在模型结构及范围可靠时启用。未知结构仍正常受伤，不冒称爆头。
2. 用真实散布后的弹丸射线测试随动作变化的头区，推荐定向包围盒或椭球，不依赖渲染三角形逐面相交。候选范围必须包含伸出原身体盒的头，避免长颈/前伸头部根本进不了检测。
3. 对已适配对象建立足够可靠的身体遮挡范围，比较头、身体、其他实体和地形的最近有效交点；从背后打中躯干后不能继续用延长线碰头判为爆头。原来的 0.35 宽容命中可单独保留为普通命中兜底，不能扩展成同样宽的爆头范围。
4. 命中使用世界坐标及当前逻辑姿态。本地参考的 `AbsoluteBoneTransformsForCamera` 含摄像机变换，而且可能只在绘制时刷新；不能直接用于伤害。避免为了判定再推进一次动画，离屏、不同视角和同帧多个摄像机应得出相同结果。
5. 将爆头伤害倍率作为可配置的玩法参数，与枪种及生物抗性一起校准。用户已明确要求判定和黄色提示，尚未指定倍率；建议首次测试以 2 倍为起点，不承诺枪枪秒杀。电击枪建议默认无爆头加成；刀、手雷、火焰不自动套用枪械爆头。
6. 保留现有攻击/护甲/模组钩子，不直接扣血绕过它们。若支持玩家或穿甲人形，单独核对头盔规则：本地衣物参考实现默认随机选择受护部位，真实爆头不能因此随机算到鞋子。通过攻击部位信息及护甲钩子适配，具体行为再对当前安装 DLL 验证；其他模组已有爆头加成时防止重复叠乘。
7. 霰弹按命中部位分别累计；若头身护甲需要分开结算，保留部位分组，整次击发最终统一生成准星/击杀提示。存在击杀则红色；没有击杀时避免最后一颗普通弹丸覆盖前面的黄色爆头。同一枪击中多个目标时也只合成一次中心提示，击杀记录独立保存。

**头区配置与模组接入细节**

首版提供配置驱动适配，不为每一种生物另写完整射击逻辑。以“模组/实体模板/模型资源”定位规则，优先级为：目标明确提供的有效适配接口 → 精确实体模板配置 → 已验证的模型配置 → 普通命中回退。优先级和已选中规则可在开发诊断里查看；不使用显示名称匹配，避免翻译和重名造成误识别。

| 配置项 | 含义与约束 |
|---|---|
| 目标标识 | 实体模板、模型路径及必要的模组标识；避免规则影响外形不同的同名生物 |
| 头骨骼 | 一个或多个骨骼名；缺少独立骨骼时明确使用哪个身体坐标系 |
| 局部偏移与尺寸 | 头区相对所选骨骼的位置、方向和盒半尺寸/椭球半径，必须为有限合法数值 |
| 缩放处理 | 跟随当前模型/实体缩放，区分模型单位与世界单位，避免重复乘缩放 |
| 身体遮挡区域 | 必要的躯干/颈部等判定体，供最近部位判断使用；普通宽容碰撞盒不等于精确身体表面 |
| 可爆头/部位倍率 | 支持关闭爆头、指定弱点倍率或交给模组处理；多头可配置多个区域但单弹丸只结算最近一次 |
| 伤害结果接口 | 默认使用标准 `ComponentHealth`；自定义血量的模组需明确返回是否实际受伤及是否死亡 |

实施时先枚举原版实体模型并产出支持清单，每个条目标明“骨骼头区 / 模板头区 / 无头或暂不支持”，不能把第一只狼调通当作全部生物完成。标准结构的模组生物可以复用模型规则，但自定义模型需校准；巨型、多头、模型运行时替换/变形的生物通过专门规则或接口补充。

骨骼索引与静态头区配置可缓存，当前姿态变换按实体更新；模型改变时使缓存失效。仅对射线附近候选做精确检测，禁止每颗霰弹遍历全世界所有模型三角形。粗筛命中的第一个大盒经过精确检测若未真正命中，要继续考察后方候选；最终命中仍由有效距离与地形遮挡决定。

开发验证可临时绘制头区、身体判定体、射线及命中点，并记录选用规则；调试显示默认关闭，不把适配参数放进正常射击 HUD。头区应覆盖实际头部，不能覆盖角、耳尖周围大片空气或把长颈全部算头。

**伤害结算与例子（测试倍率 2.0，可调）**

按当前散布后的射线得到命中部位，以 F13 提高 1.5 倍后的枪械基础威力为基数，计算距离衰减和单弹丸威力，再对头部应用倍率，最后进入既有护甲/抗性/伤害钩子。爆头与击杀是两个独立结果，不使用“伤害很高”“目标死亡”倒推是否爆头，也不直接设置目标生命为零。

`进入防护结算的总威力 = Σ(各实际命中弹丸调整后的基础威力 × 距离衰减 × 该部位倍率)`

“调整后”已包含 F13 的 1.5 倍，不能在爆头分支再重复乘一次全枪倍率。

| 示例 | 结算与提示 |
|---|---|
| AK-47 近距离打中身体 | 当前 10，F13 实施后以 15 进入后续防护结算；目标存活显示白色 |
| AK-47 同距离打中头 | 新基数 15，测试倍率 2.0 时以 30 进入后续防护结算；目标存活黄色，死亡红色 |
| AWP 近距离身体 / 头部 | 当前 38，调整后身体 57；测试头部倍率 2.0 时为 114，仍经过防护及实际生命结算 |
| MAG-7 一枪 8 颗弹丸，调整后总基础威力 36，其中 2 颗头、3 颗身体、3 颗未命中 | 忽略距离及防护仅演示：每颗基础 4.5，合计 `2×4.5×2 + 3×4.5 = 31.5`；不把 36 整体乘 2 |
| 头区被墙或前方实体挡住 | 不向后方头部结算伤害，不能显示其爆头反馈 |
| 射线碰到头区但该部位伤害被完全免疫 | 不因几何相交单独显示黄色；若同枪其他身体弹丸有效且未击杀，则按普通有效命中显示白色 |

表内数字是攻击力，不保证等于玩家/动物实际扣除的生命值，最终由原有伤害链路决定。按头身分组调用伤害链路时，保留每组实际扣血结果；控制击退、硬直、音效和击杀事件不能因分组重复触发。若其他模组已经接管部位伤害，使用协商的适配标记确定由谁施加倍率，不能两边各乘一次。

普通枪械默认可爆头；电击枪首版默认只做原有放电伤害和普通命中反馈（不计爆头），以后需要可通过枪种配置启用。刀、爆炸与火焰不经过这套枪械头区倍率。耐久只看击发次数，头身命中、是否击杀和倍率都不额外增加磨损。

**命中标记显示规则（用户已明确）**

- 普通命中且未击杀：白色。
- 爆头命中但未击杀：黄色，用来告知玩家这一枪打中了头，但目标仍存活。
- 击杀一律红色，包括爆头击杀；继续显示击杀文字并播放现有击杀音效。这里改的是短暂出现的命中标记，不是常驻瞄准准星；颜色需求本身不代表爆头必须一枪致死。
- 同一次击发的合并优先级为：击杀红色 > 未击杀的爆头黄色 > 普通命中白色。受保护、无敌或未扣血的射线交点不显示成功命中。
- 状态按最新有效击发事件记录类型与时间，避免上一次红色击杀的 0.45 秒保持期盖住下一次未击杀的黄色爆头。支持连发、霰弹和多目标合并。
- 第三方生物若使用自定义血量而没有标准 `ComponentHealth`，需适配其伤害结果接口；不凭调用攻击方法就推断伤害成功。

| 一次击发的最终有效结果 | 中心命中标记 |
|---|---|
| 没有造成伤害 | 无新命中标记 |
| 只有普通命中，无击杀 | 白色 |
| 至少一次有效头部命中，无击杀 | 黄色 |
| 任意击杀，包括爆头击杀，或同枪其他目标被击杀 | 红色 |

保留现有命中标记形状，普通/爆头提示可沿用约 0.22 秒，击杀约 0.45 秒；新增有效击发覆盖上一事件，未命中不凭空制造标记。黄色建议使用清晰金黄（例如 RGB 255/210/50），实机检查明亮背景下的辨识度。只在实际击杀时播放现有击杀音，爆头未击杀不误播；首版无需新增爆头音效。

**验收**：原版各模型族清单逐项记录支持状态；站立、低头、转头、奔跑、跳跃、鱼游动、缩放模组生物；正侧后方射击、头边缘擦过、身体挡头、墙挡头、另一生物遮挡、远近距离、离屏及视角切换。霰弹头身混合只放大头部弹丸，护甲/友伤/无敌行为不变；白、黄、红及连续事件优先级符合规则。没有已验证头区的模组生物正常承受普通伤害，不崩溃、不误爆头。

主要入口：`World/SubsystemScGunBlockBehavior.cs`、`ScSurvivalBalance.cs`、`ScCombatFeedback.cs`、`Rendering/GunSpec.cs`、`tools/PackageCheck/CombatRegression.cs`；建议新增 `ScHeadshotResolver` 和可扩展的生物头区配置。无需新增 CS2 图像资源，也不要求先完成枪械耐久；可先于第三人称完整动作交付。
