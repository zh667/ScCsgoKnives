## 1.5.3 的处理

1. 先按明确的布局/schema读取，保留既有1.0.0、1.2.0转换链。整表或来源无法辨认、未来格式、不支持的记录结构、实例堆叠继续拒绝进入。
2. 对格式明确的局部缺记录、已隔离记录和型号冲突，在独立XML副本中只准备编号水位及诊断标记，不改物品、枪型、弹量、皮肤、击杀、等级、耐久或任何原始记录行。
3. 创建并逐文件核验整个原世界的 `.snapshot`，包括地形与其他模组侧文件；成功后才启用准备结果。schema或版本备份可复用同次已核验快照，避免重复复制。失败不启用任何部分修改。
4. 编号水位高于所有旧实例引用，包括未选中的库存、掉落物、投射物、移动方块、补偿与待结算击杀。缺失 #900 时，新枪从至少 #901 分配，不能再次占用 #900。编号仍不回收，空间满时不能创建新实例。
5. 正常枪继续可用，异常枪以原物品保留且不能射击、维修、涂装或升级；进入世界给一次说明，备份路径及详细异常写入日志/`GunIntegrityProtection`。标记和编号水位通过实际子系统保存入口一起持久化。
6. 异常型号引用不能作为重复枪的证据，避免同编号的健康枪被误拆分、清掉成长。跨世界快照逐物品核对型号；错误状态不再被当作正确枪导出。既有快照中的恢复证据保留并标记Error，携带异常枪跨世界仍被阻止。
7. 复制整个世界并保留原来源信息时，局部冲突交由上述保护处理，不误判成只搬运玩家的跨世界导入。存档布局v5/schema6/rules7、枪型ID与所有正常枪记录保持不变。

**这能解除因这两把异常枪导致的整世界拒绝，但不恢复它们已经丢失的M249/M4A1-S原状态。** 恢复原弹量、耐久、皮肤和成长仍需同一世界丢失前的可信备份。实际玩家世界和已安装Mods均未修改；只在隔离副本和测试快照上验证。
