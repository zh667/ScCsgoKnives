# 打开背包中断换弹：1.2.2 修正

用户复现：换弹过程中打开物品栏，换弹动画突然消失，后续音效也消失。该问题已在包内 DLL 的实际 `UpdateGun` 路径复现，不再只是声音队列的推测。

## 原因和处理

旧代码把 `ModalPanelWidget != null` 或玩家界面有对话框直接列为取消换弹条件。`CancelReload` 同时取消装填事务、动画以及剩余音效。即便仅删掉这个条件，紧随其后的输入门仍会提前返回，挡住装弹和消音器状态提交。

现在先验证正在进行的事务并推进其事件，再禁止菜单内的新输入。打开背包、箱子或工作界面本身不取消换弹；枪仍在同一选中槽、弹药足够时，装入弹匣后更新弹量，拉栓/收尾完毕才解锁。消音器拆装也能继续提交。

装填、拆装、切枪锁定与动画/音效统一使用 `KnifeClock`，避免游戏时间暂停或变慢后动画结束、装弹却仍等待游戏时间。射击间隔、电击枪充能与存档时钟保持游戏时间。若某界面完全停止世界更新，则库存提交在恢复更新后校验并结算，不在绘制线程修改库存。

换枪、切槽、换库存对象、模式改变、原枪失效仍会取消；装入前失去弹药时不凭空补满，也不额外扣料。装入后已扣付的弹药保留，不因取消而回滚。菜单中清除霰弹枪收尾后的排队射击、R8 待击发和剩余连发，防止关菜单后补发旧输入。

检视、切枪动画已有菜单内采样路径，本次没有找到与换弹相同的取消原因。刀具攻击命中路径会因菜单停止，但这不等于证明刀具音效丢失的根因；不能把本修正表述为所有刀枪缺音效均已解决。

## 数据与验证

- 不改变武器/涂装 ID、物品布局 v5、注册表 schema、迁移规则和保存字段；新增/调整的计时均为会话内动作状态。不补满玩家现有弹药或重置枪械状态。
- 新增 `MenuActionRegression`，直接调用最终包 DLL 的 `StartReload` / `UpdateGun`，使用原生界面容器和装填事务。覆盖 34 种非电击枪 × 生存/创造、装入前后换槽/移走枪/换库存/移走弹药/切模式、两种消音器、三种逐颗装填枪的提前收尾，共 83 项。
- 将游戏时间固定而推进动画时间，验证插入前不加弹、插入后仍锁定、完成只扣一次、菜单内不射击、剩余音效队列未被开界面清空。音频测试将音量设为零，验证调度路径，不冒充扬声器实听。
- 同套测试对保留的 1.2.0 包出现 78 项失败，其中 68 项在打开菜单后直接断言换弹被取消；其余失败包含依赖换弹继续的场景。这些不是 78 种独立缺陷。最终 1.2.2 为 83/83 通过。
- 全包兼容性/两轮存读档检查及最终包哈希见 [交付验证](visual-feedback-verification-20260918.json)；专项细节见 [专项报告](menu-action-verification-20260919.json)。离线验证不替代 Android/Windows 的画面与声音实机验收。

## 玩家验收

1. 生存模式带弹匣，用 AK 或 M4 打掉几发，按 R 后立刻打开背包；等换弹完成再关闭。应正常装满，材料只扣一次，声音和动画不应被开背包突然清掉。
2. 再试一次，在弹匣刚装进去、拉栓尚未结束时开背包。已装入的弹药应保留，不能提前射击。
3. 用 Nova 或 XM1014 换弹时开背包，应继续逐颗装入；中途把枪移到其他槽，后续装填应停止。
4. M4A1-S/USP 拆装消音器中打开背包，回来后状态应与完成的动作一致。另试工作台/箱子；若仍出现某把刀缺声，请记录刀型、动作、打开的界面及时间点。
