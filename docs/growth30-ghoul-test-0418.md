# 0.41.10：30 级成长与通用跨世界枪械快照

日期：2026-09-10。按用户最新补充，耐久保持温和增长，把后 20 级的收益集中在伤害、射速和弹匣。

## 成长规则

仍需先安装计数器才累计有效击杀并开启成长，不追溯安装前击杀。每级 100 次，3000 次到 Lv30。
原有计数保留，超过旧上限 1000 次的已记录击杀可以解锁后续等级，在枪械空闲时通过原事务应用。
仅计数世界仍仅计数，不擅自改为成长。

所有加成对该枪基础值累加，不复利；有效涂装先提供原有的基础伤害 ×1.5。

| 等级 | 累计击杀 | 伤害倍率 | 弹匣倍率 | 射速倍率 | 最大耐久倍率 | 电击枪充能 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Lv0 | 0 | 1 | 1 | 1 | 1 | 10 秒 |
| Lv10 | 1000 | 2 | 1.5 | 1 | 1.5 | 5 秒 |
| Lv20 | 2000 | 5 | 3.5 | 2 | 2 | 2.5 秒 |
| Lv30 | 3000 | 10 | 6.5 | 3.5 | 2.5 | 1 秒 |

- Lv1–10 数值不变。
- Lv11–20 每级：基础伤害 +30%、基础弹匣 +20%、基础射速 +10%。
- Lv21–30 每级：基础伤害 +50%、基础弹匣 +30%、基础射速 +15%。
- 耐久始终每级增加基础上限的 5%，不跟着后两阶段跳涨。
- 弹匣向下取整，使用整数分数计算以免浮点误差少一发。电击枪仍只能放电一次，不能存多次充能。
- Lv10 起的零散布、无射击后坐力、无伤害衰减、无普通子弹枪自身距离上限继续保留，不能因扩级退回。
  子弹仍受墙壁和连续已加载区域边界限制，不强制加载、不自动瞄准。
- 电击枪继续保留有限距离特例，距离倍率在 Lv10/20/30 为 1.5/3/5。
- 普通伤害与爆头伤害一起按伤害倍率提升，爆头倍率本身不重复增加。
- 射速缩短实际开火调度间隔，覆盖普通枪、连发组间/组内、R8 主副模式及狙击枪自动回镜等待。
  属性页使用同一成长公式，并说明这是理论射速：实际受帧率、操作和充能影响。
- 不加速换弹动画、装填事件和检视动作。逐发装填的霰弹枪弹匣变大后，完整装满所需时间自然增加。

例：原厂 AK 的基础普通攻击力 15 → Lv30 为 150；涂装 AK 为 225。AK 弹匣 30 → 195，
AWP 5 → 32，Negev 150 → 975。电击枪基础 150 → Lv30 为 1500，仍需充能和维修。

## 旧存档处理与降级边界

- 枪械型号编号、实例 ID 编码、物品布局 v5 不变。
- 记录 schema **3 → 4**：具名字段不换名，只扩展合法等级域为 0–30；成长规则版本为 2。
  schema 1/2/3 的读取与转换均保留，schema 3 的合法等级仍严格限制在 0–10，不能借升级接受来源中的非法高等级。
- Lv0–10 的旧记录在加载/转换时原样保留；不在 Load 中重置击杀、等级、弹量、耐久、涂装、消音器、充能或补偿。
- 新等级通过现有 ScGunMutation / ScGunGrowthService 事务在非忙碌时应用，耐久保持比例，报废仍报废；
  装填弹量不补满，容量缩小时超出部分进原有备用弹量；进行中的充能保持剩余比例，不直接充满。
- 第一次读取旧 schema 会先制作并校验完整世界备份。备份失败拒绝加载；重复读取仍为旧 schema 的磁盘世界不能跳过备份。
- 新版正常保存后写 schema 4。0.41.7 会拒绝 schema 4，这是必要的前向保护；回退请恢复升级前备份，不可直接拿新档降级。
- 正式 0.28.2 的专用迁移链保留，不支持猜测 0.29–0.36 内部测试格式。

再进行完整复制和逐文件校验。原版 GetRegionStream 对已关闭缓存会自动重新打开，成功或失败都会释放锁、恢复地形工作线程。

原始异常及文件路径完整写日志，弹窗改为简短中文，避免错误内容被裁切。

## 本次发现并修复的真实保存钩子问题

反编译本机 Survivalcraft.dll 确认：`GameManager.InternalSaveProject` 先对空 XML 调用 `ProjectXmlSave`，
再调用 `ProjectData.Save` 写内容，最后调用 `OnProjectXmlSaved`。
旧的携带快照逻辑挂在前者，可能根本没拿到枪械记录。现在注册后者。

快照生成仅读取冻结的保存 XML，不再从保存线程读取活跃注册表和 GameManager.WorldInfo。
主线程 Subsystem.Save 将世界路径写入 `GunTravelSource`；待结算击杀/补偿也从同份 XML 判断。
运输包 v1 继续按旧 schema 3 验证，新增 v2 明确承载 schema 4，避免旧版把 Lv11+ 当坏记录。

v1/v2 旧协议仍按其原有主世界与直接 Tartareosity 子世界关系验证。0.41.10 的 v3 改为通用跨世界协议，详见下节。
尸鬼原有切换会复制并写入目标世界的玩家 XML，因此不能声称整条跨模组链条具有自动事务回滚。
测试入口多一层源世界完整备份，但不承诺其它模组的数据也由 CS 模组迁移。请始终用世界副本验收。

## 0.41.10：创造背包漏传与通用多世界

用户 0.41.9 实测日志确认源世界有 6 条记录、目标世界导入 0 条。只读检查真实 XML 及原版源码发现：
ComponentCreativeInventory.Save 的开放槽位只有 Contents，没有 Count；旧读取器要求 Count，因而跳过所有创造枪械。
现在按原版实际格式读取 CreativeInventory，每个非空槽为一个物品；生存/其他库存仍要求合法数量，不猜损坏格式。
保存前检查和加载合并都核对携带枪械数量与快照逐项对应，不能再次把“携带 6 把却快照 0 条”当作成功。

新协议 v3 不依赖尸鬼名称或父子文件夹。它携带 schema/layout 标记、源世界路径、枪械原始状态与独立身份，
任意世界路径间都可按同一套规则合并：目标 ID 冲突分配新 ID，返程按身份更新原记录，其他容器仍持有同身份枪时拒绝覆盖，
不同世界成长模式冲突时拒绝偷偷切换加成。新身份用保存的 GunTravelWorldIdentity UUID 派生，避免目录被新世界复用而串枪；
旧的枪械身份保持不变，不重新编号旧枪。
对“整个世界复制/还原后路径变化”另做完整本地记录核对；不会把已经随整个世界复制过来的注册表误当成缺失表。
未知协议仍拒绝，不能借世界复制绕过格式保护。

这适用于“通过正常世界存读档切换，并保留玩家实体扩展 XML”的多世界模组。
提供者也需按游戏正常流程保留或转换方块编号映射。
只复制物品数值但丢弃玩家快照、自定义库存不使用已支持编码、在同一 Project 内自行换维度等提供者仍需适配，
不宣称能自动覆盖未检查的所有多世界实现。

用户这份 World34 主世界仍有 6 条原始完整记录，已用于只读快照回归，没有改写玩家真实世界。
对已由旧版保存成缺记录的里世界，不自动从同名 ID 猜回状态。可退出游戏回到主世界 World34（WorldPath 仍指向主世界），
使用新版重新生成完整携带快照后穿越；或恢复已核对的传送前快照副本。
