# 1.0.5-preview：视频反馈修复与指定 1.0 包迁移

交付给 API 1.9.3.1。没有替换用户 Mods、修改玩家世界或覆盖指定旧包。以下是打包 DLL 与真实引擎类的检查结果；游戏内画面、声音和设备外观仍需按本文步骤验收。

## 五项变化与玩家操作

| 变化 | 在游戏里怎么试 | 应看到什么 |
| --- | --- | --- |
| 切枪／切刀中途换原版物品 | 快捷栏放一把 CS 枪、一把 CS 刀、泥土和其他模组物品；拿起 CS 武器，动作没结束就换泥土或其他物品。再迅速切回来。 | 原武器动作继续并向下退场，不冻结上一帧；切回来正常起手，不把原武器的检视排队到新物品上。 |
| 准星预览 | 设置→模组设置→CS 枪械→打开设置，滚到“枪械准星”。用“调整：颜色／形状”切换参数组，拖动红绿蓝，再把十字线长、间距、粗细、整体大小全部拉满。 | 左边调、右边看。预览始终在参数旁，最大十字也留在自己的区域内。预览按固定比例缩小，不以自动缩放掩盖大小变化。保存生效，取消不保存。 |
| 设置入口 | 在原版设置中进入“模组设置”。 | 找到“CS 枪械”；打开设置后取消能回到 API 模组设置，不再单独占用原版设置主页按钮。 |
| 每级 100 杀 | 在“计数＋成长”的世界，用带计数器的枪查看属性；累计击杀到 99→100、1099→1100 或 2999→3000。 | 每个等级都是 100 杀，分别到 Lv1、Lv11、Lv30。战斗动作结束后应用升级。仅计数世界仍不升级。无需为了验收手动刷满 3000 杀；30 个边界均有 DLL 检查。 |
| 立体掉落枪 | 丢出步枪和手枪，绕着看；第三人称拿起再丢下比较。也试涂装枪、计数器枪，以及装／拆消音器的枪。 | 掉落枪有完整厚度，随游戏时钟旋转并轻微浮动；用第三人称持枪的米制尺寸，不把所有枪缩成同样大小。第一人称使用专门视野角，屏幕上的像素大小不作为实物尺度。 |

视频中的停顿对应两处代码共同作用：控制器在引擎仍绘制旧物品时直接返回旧姿势；渲染器又关闭了原版退场位移。现在旧动作继续采样、取消尚未开始的检视，只对正在离开的物品恢复退场位移。新武器仍使用自己的 CS 起手动画。

掉落物复用已组装的第三人称枪体、零件绑定与贴图；围绕枪体中心旋转，保留消音器和计数器。使用独立绘制环境，避免共享环境的 UI 模式把掉落枪画成图标。模型随掉落物缓存，中心只计算一次，不在每帧重新遍历枪体顶点。

## 从用户指定 1.0 完整包升级

来源：`D:\下载\CS枪械\[API1.9]CS武器1.0-作者ZH667.scmod`。

- 包内版本确为 `1.0.0`，原 API 声明为 `1.9.2.1`，实际记录 schema 为 4。
- 来源包 SHA256：`9c700bc8133942ca4fe0ce7e9604296e7acd1533f684aaa5dd4bfda252e84424`。
- 35 款枪的保存编号与物品布局 v5 不变；记录 schema 4→6，仍读 schema 1～5。schema 5 的中间预览版也有专门转换。
- 升级前，由游戏加载钩子生成整个世界的 snapshot，重新打开并逐文件校验。备份失败则拒绝启用升级；未知未来格式拒绝载入及改写。备份名称含来源／目标 schema、时间和唯一后缀，保留旧备份。
- 枪型、编号、皮肤、计数器、实际击杀、已应用等级、当前弹量、磨损、消音器和溢出弹药保留；不重新分配原世界枪号，不清表，不补弹、不复活损坏枪。
- 1.0 本身每级也是 100 杀，升级不额外收取历史击杀。已够新门槛的枪在空闲时补升，原有高等级不降级。
- 战斗数值沿用此前确定的 1.0.4 曲线：Lv10／20／30 伤害 ×2／×4.5／×6.5，射速 ×1／×2／×3；本次只改击杀门槛。它们不等同于旧 1.0 的全部平衡参数。
- Zeus 从旧 1.0 的充能周期转换为当前 5／3／2 秒规则时，保留剩余充能比例；例如旧周期充到一半，升级后仍剩一半。1.0.4 的周期已是当前规则，不重复转换或直接充满。
- 跨世界携带：用真实旧 DLL 写出携带快照，在新世界为记录分配当地编号并同步改物品引用，保留原身份与完整状态；拒绝损坏快照。这里覆盖保留玩家 XML 快照的既有传送机制，不承诺所有未知模组都支持。

安装时退出游戏，在 API 1.9.3.1 中移出旧完整包，安装 `ScCsgoKnives-1.0.5-preview.scmod` 与 `ScCsgoResources-1.0.0.scmod` 两个文件。只保留一份 CS 武器核心包；如果已经装有相同资源包，不必重复安装。

首次进入原世界会走上述备份转换。先核对快捷栏／箱内几把不同枪的涂装、弹量、磨损、等级，保存退出后重进两次，再试丢出捡回、箱子搬运和原来使用的传送方式。若源档里的记录早已缺失，此升级不会凭空重建原枪；正常完整旧档迁移与损坏数据恢复是两种情况。
