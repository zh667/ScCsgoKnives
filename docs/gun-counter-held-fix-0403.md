# 0.40.3 — 创造计数器枪无法使用、手持模型错位

## 原因与证据

用户在 0.40.2 实测：计数器枪拿在手里巨大/错位，没有正确手持动作，不能开火、换弹等。

本机 Game.log 11:57:47 确认加载 0.40.2：`gunBlock=302, counterTemplateBlock=303`。这次日志中原厂 AK 有正常开火记录，计数器模板未见转换成功记录。核心代码证据是 `SubsystemScGunBlockBehavior.Update` 原来只调用 `ScGunSkinTemplateBlock.Materialize`，从未调用计数器模板的 Materialize。尽管目录、模板解码和转换事务已存在，运行时入口没有接上。

计数器目录物品的 contents 仍为计数器模板 block，无法通过后面的 gunBlock 判断，因此跳过 UpdateGun；第一人称 hook 也不能识别为枪。原版随后绘制模板的物品网格，产生截图中的模型异常。这不是 CS2 资源缺失，也不是计数器成长数值引起的。

## 修复

- 活玩家选中模板时，更新入口同时识别普通皮肤模板和计数器模板，分别调用各自 Materialize。
- 转换成功后立即重新读取 ActiveBlockValue，再进入原来的枪械状态、动画、HUD 与交互流程。
- 成功输出一次 `[GUN_TEMPLATE]`：玩家、槽位、计数器标识、枪型、皮肤、实例 ID。下一帧已是普通枪实例，不重复安装/重置。
- 登记失败继续使用既有拒绝提示和事务保护。计数器模板不再走原版 FirstPerson 物品绘制；图标与掉落物绘制仍保留。
- 升级为 0.40.3。保留 0.40.2 的 UI 修复和此前已有功能。

## 数据影响

- 物品布局仍为 v5，记录 schema 仍为 3。型号顺序、计数器目录编码和 block 身份不变，无存档迁移。
- 背包/快捷栏里原有的计数器目录模板，无需删除、重新获取或新世界；选中后经既有事务登记成独立枪械实例。
- 模板本来无独立世界记录；首次实例化按该目录物品定义生成满弹、满耐久、0 击杀 Lv0 的枪，保留原枪型和皮肤。
- 已有枪械实例（含装配台安装计数器的枪）不会进入模板分支；ID、弹量、消音器、耐久、充能、击杀及等级不被此补丁重新初始化。
- 不修改只读创造目录。状态表满、非法模板或拒绝写入时不删除物品。原有回滚、补偿和未来格式保护继续使用。
- 不操作玩家真实世界文件；测试使用内存库存及独立 XML 数据。

## 检查

新增 99 项检查：

- 46 个目录条目（35 枪 + 11 皮肤）编码稳定且互不碰撞。
- 全部条目通过实际 ComponentCreativeInventory 取出，正确转换为独立实例，普通枪识别和 CS2 动画型号正确，计数器/皮肤状态正确，目录不变。
- 全部条目通过实际 ComponentInventory 转换，执行弹量/耐久/击杀状态事务后，将库存和注册表一起写为 XML，连续两轮读取保存，验证状态一致。
- 同款两次获取分配独立 ID；只读目录拒绝转换；表满和非法模板保留原物品；未转换模板的第一人称绘制不触碰资源/渲染器。
- 读取包内 DLL 的 Update IL，检查计数器识别、转换调用存在，且发生在枪械识别和 UpdateGun 之前，并在转换后重新读取 ActiveBlockValue。原来“辅助方法存在但没有接入”的版本会失败。

工作区构建预检：6981 项、0 失败。最终 Full/Lite 包检查记录分别为 `output/ScCsgoKnives-0.40.3-check.json` 与 `output/ScCsgoKnives-0.40.3-Lite-check.json`，必须各 0 失败且包内 DLL 哈希相同。

这些是入口连接、真实库存/事务、动画型号和存读档的离线检查，不代表实际游戏已完成开火命中/手持画面验收。实机请选中已有模板，待切枪动作结束后检查开火、换弹、检视及消音/开镜功能；日志应新增对应 `GUN_TEMPLATE ... result=Success`。若无记录，优先确认加载版本、物品是否模板及登记拒绝提示。
