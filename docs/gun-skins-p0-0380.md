## 2. UV 实测：为什么不能直接贴图案

模组绘制的是 CS2 **当前** `body_hd` 模型，`<gun>_hd` 贴图就是该模型的材质。11 款里 10 款在 CS2 里标了 `use_legacy_model=1`，
它们的图案是按**旧版模型**的 UV 画的。用边缘相关性对比图案与新旧两套 AO：

| 图案 | 对旧版 AO | 对当前 AO | 结论 |
|---|---:|---:|---|
| 火神 `cu_ak47_rubber` | **+0.207** | −0.029 | 旧版 UV |
| 巨龙传说 `cu_medieval_dragon_awp` | **+0.163** | −0.049 | 旧版 UV |
| 永恒之枪 `gs_awp_gungnir` | **+0.175** | −0.022 | 旧版 UV |
| 雷击 `am_lightning_awp` | −0.025 | −0.027 | 通用图案，与任何单把枪的 UV 无关 |
| 水栽竹 `am_bamboo_jungle` | −0.024 | +0.012 | 同上 |

把旧版 UV 的图案直接贴到当前模型上，会把龙头印到弹匣上。规范要求"不匹配时离线烘焙"，
而离线烘焙需要旧版模型网格做 3D 对应——**VPS 上没有**：`02_models/extracted-vmdl-paths.txt` 只导出了
`weapons/models/*`（当前模型），`03_legacy_vmodels_materials` 只有贴图没有网格，也没有旧版位置图。
所以本版没有盲贴，而是按图案性质分两条路。

## 3. 三种烘焙模式（`tools/build_gun_skins.py`）

底图一律是模组自己的 `<gun>_hd` / `_hd_orm` / `_hd_normal`，涂装区取自当前模型的 `composite_inputs` 遮罩（R 通道）。
这样皮肤只能改颜色、粗糙度和金属度，**永远不会改动图案位置**。

| 模式 | 适用 | 做法 |
|---|---|---|
| `pattern` | 雷击、水栽竹 | 配方是 anodized-multi：图案 R/G/B 三通道按配方的 `g_vColor0..3` 选色，套用配方自己的缩放/偏移/旋转。图案本就是 CS2 跨多把枪共用的通用纹理，放到当前 UV 与放到旧版 UV 同样成立。**颜色与规则均按配方还原。** |
| `palette` | 其余 9 款 | 以 CS2 **官方轻度磨损图标**（即 CS2 自己渲染的成品枪）为取色源，按亮度分位把配色分布映射到当前模型的明暗上，再按图标整体亮度归一。**颜色是皮肤的，图案位置是枪自己的——这是近似，目录里以 `Approximate` 标记，工作台确认框也会写明。** |
| `fade` | 暂未启用 | 渐变之色的 `aa_template` 走 paint-by-number 遮罩，本版未解出其着色语义，已降级为 `palette`（图标取色，结果与官方图标一致）。 |

每款输出 4 个文件：`<gun>_hd__<key>.png`、`_orm`、`_normal`、`<gun>_slot__<key>.png`（图标直接用 CS2 官方图标，**与 UV 无关，完全正确**）。
来源、SHA-256 与所用参数见 `docs/gun-skins-assets.json`。

离线预览：`docs/gun-skins-preview.png`（`tools/gun_skin_preview.py`，用模组自己的 OBJ 部件与 UV 渲染）。**这是贴图检查，不是游戏截图。**

## 4. 存档与实例模型

- `GunSpec` 的 35 个型号顺序、v5 物品布局、低 6 位型号、10 位实例 ID、第 16 位含义**全部未改**。皮肤不是新型号。
- 皮肤存在实例记录里，值是 **CS2 的 Paint ID**（稳定、有含义、未知值可检出），0 = 原厂。
- 记录 schema 1 → **2**：schema 1 是 7 字段，schema 2 追加第 8 个字段。读到 schema 1 时 `SkinId = 0`，弹量、消音器、耐久、最大耐久、充能、修订号原样保留；写出一律 schema 2。
- 物品布局戳 `GunDataLayout` 仍是 5——皮肤不改物品编码，也不要求玩家新建世界。
- 未知 schema：整棵子树原样保留、枪械停用（沿用 0.35.2 起的规则）。
- **未知 Paint ID、或属于别的枪的 Paint ID，整条记录进隔离区**，保留原文、拒绝使用，不猜测枪型也不猜测皮肤。事务的记录校验器同样拒绝写入这类值。
- 0.28.2 迁移出的枪 `SkinId = 0`，迁移规则未改，不重复补耐久。

## 5. 换肤事务与费用

`ScWeaponSkinning` 走的是 M4 那套唯一事务 `ScGunMutation`：报价冻结记录 ID、修订号、当前皮肤和逐项材料；提交时复核，
材料不足 / 记录缺失 / 库存拒绝 / 状态变化 / ID 表满 / 写入异常一律整体回滚，不扣材料、不换枪。
弹量、耐久、最大耐久、充能、消音器、修订号以外的字段一个都不动。仍是新枪模板的枪在换肤时立即登记实例 ID，之后不可能再作为可堆叠模板。

费用集中在 `ScGunSkinCatalog.Cost`（UI 与事务都读它）：

| 档位 | 皮肤 | 金属坯件 | 精密机构 | 涂装材料 |
|---|---|---:|---:|---:|
| Standard | 雷击、火蛇、水栽竹、火神、二号玩家、金蛇缠绕 | 2 | 1 | 1 |
| Premium | 巨龙传说、野荷、印花集 | 4 | 2 | 2 |
| Special | 永恒之枪、渐变之色 | 6 | 3 | 3 |

涂装材料是 `ScWeaponMaterialBlock` 的第 5 个 kind（data = 4，只增不改），有自己的合成配方与图标网格。
拆回原厂外观按 Standard 的一半向上取整（1/1/1）。重复选择当前皮肤直接提示"已是该外观"，不进事务、不扣料。

## 6. 渲染

统一入口 `ScGunSkinCatalog.Material(asset, paintId)` / `Icon(...)`，按 `(Variant, SkinKey, SilencerOff)` 取材质：

- 第一人称：`CsmcFirstPersonRenderer.SkinId` 由第一人称钩子从手持物记录取，绘制后清空；贴图缓存键含皮肤（`asset#skin`），PBR 的 `_orm`/`_normal` 随材质名自动跟随。开镜、换弹、消音器拆装都走同一材质名。
- 第三人称：烘焙几何仍按型号缓存（皮肤不改几何），绘制时按记录换贴图；消音器组仍按记录隐藏。
- 物品栏 / 快捷栏 / 箱子 / Stash / 地面掉落物 / 工作台预览：都经 `ScGunBlock.DrawBlock`，图标与手持模型都按记录取皮肤。
- 任何取不到的皮肤（未知、属于别的枪、贴图缺失）都回退到原厂材质，绝不空绘。

堆叠：`ScGunBlock` 的 `MaxStacking` 是 1，枪本来就不成堆；且带皮肤/不带皮肤/不同皮肤的枪实例 ID 不同，物品值不同，任何合并入口都不会把它们并在一起。
