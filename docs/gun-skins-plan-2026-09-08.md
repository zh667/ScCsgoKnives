# 枪械皮肤接入方案与 VPS 交接

日期：2026-09-08（Asia/Shanghai）。

## 2. 存档和实例模型

现有 `GunSpec` 型号编号和 v5 物品布局冻结：低 6 位是枪械型号，后 10 位是实例 ID。不能为 11 款皮肤追加 11 个枪械型号，不能占用第 16 位，也不能改变旧编号顺序。

皮肤是 `GunRegistry` 实例记录的字段：

```text
Id
Variant
Rounds
SilencerOff
Durability
MaxDurability
RechargeRemaining
SkinKey
Revision
```

现有 schema 1 严格是 7 个字段。增加 `SkinKey` 必须使用新的记录 schema 和明确转换器，不能把新增字段伪装成 schema 1。schema 1 读入时 `SkinKey = none`；未知 schema 原样保留并拒绝正常使用/自动保存，不能猜测或覆盖。

0.28.2 专用迁移和 0.37.0 基线规则继续有效：

- 0.28.2 迁移出的枪默认 `SkinKey = none`，只按原迁移规则一次性补满耐久。
- 0.37.0 及以后已有记录默认无皮肤，弹量、消音器、耐久、充能和修订号不能改变。
- 皮肤字段缺失不是损坏，按无皮肤处理；字段存在但非法是坏记录，保留原文并拒绝使用。
- 不能为皮肤功能重新编码物品 data，也不能为了皮肤要求玩家新建世界。

给枪应用皮肤时，必须在同一个事务中：验证持有物、验证材料、分配实例 ID（如果仍是新枪模板）、复制状态快照、写入 `SkinKey`、替换物品、扣除材料、发布记录。任何一步失败都回滚。带皮肤的枪不能继续使用没有实例记录的 fresh ID。

## 3. 材料消耗和工作台流程

皮肤选择必须有额外材料消耗。第一版建议沿用现有武器材料体系，并把费用集中在一个可调表中，不把数量散落在 UI 或配方代码里。

推荐的初始费用档位如下，数值属于可调平衡参数：

| 档位 | 适用 | 金属坯件 | 精密机构 | 涂装材料 |
| --- | --- | ---: | ---: | ---: |
| Standard | 雷击、火蛇、水栽竹、火神、二号玩家、金蛇缠绕 | 2 | 1 | 1 |
| Premium | 巨龙传说、野荷、印花集 | 4 | 2 | 2 |
| Special | 永恒之枪、渐变之色 | 6 | 3 | 3 |

`涂装材料`可以先复用 `ScWeaponMaterialBlock` 的一个新 kind；若实现为独立物品，必须有稳定的内容/数据定义，并在工作台事务中按数量扣除。皮肤名称不应编码进枪械型号或通过字符串猜测费用。

工作台交互建议：

1. 选择背包中的一把枪。
2. 只显示该枪械可用的皮肤。
3. 预览皮肤、显示当前弹量/耐久/消音器和费用。
4. 确认后原子完成换肤。
5. 默认不提供免费换肤、自动补弹或自动维修。

重复选择当前皮肤应直接提示“已是该皮肤”，不扣材料。换回 `none` 可以作为单独的“恢复原厂外观”操作；建议第一版同样收费，费用设为 Standard 的一半并向上取整，或者暂时不开放拆除，避免增加不必要的回滚分支。

开箱和奖励池暂不作为首个实现入口。后续如果开箱直接给皮肤枪，也必须调用同一套实例登记事务，不能直接写裸 data 或创建没有 `SkinKey` 的物品。

## 4. 堆叠和物品流转

有皮肤的枪、无皮肤的枪、不同皮肤的枪不能占用同一个物品堆。由于皮肤枪在应用时立即分配实例 ID，所有个性化枪都应带独立实例记录；不同枪械型号、不同 `SkinKey`、不同实例状态都必须被视为不同物品。

需要覆盖：

- 生存背包和快捷栏
- 原版箱子、Stash
- 地面掉落物
- 投射物和移动方块携带物品
- 创造模式复制
- 拖拽暂存和工作台输入/输出
- 开箱模组奖励池

在实现层面，不能只依赖物品 data 判断是否同堆，因为 `SkinKey` 在世界记录中。任何会合并物品的入口都必须以完整实例身份判断。创造复制品若复制同一 ID，首次进入事务前按现有复制隔离规则拆成新 ID，并复制 `SkinKey`、弹量、耐久、消音器和充能状态。

同一皮肤的两把枪如果实例状态不同也不能合并；这是耐久和弹量能够正确保存的必要条件。数量大于 1 的堆只允许用于没有实例状态的无皮肤 fresh 模板，应用皮肤时必须先拆成单件并登记。

## 5. 渲染接入

建立统一的 `GunSkinCatalog`/`GunSkinResolver`，所有绘制路径通过 `(Variant, SkinKey, SilencerOff)` 查询资源：

- 第一人称
- 第三人称
- 背包和快捷栏图标
- 箱子、Stash 和地面掉落物
- 工作台预览
- 开镜、换弹和消音器拆装状态

渲染缓存键必须包含皮肤，不能只按枪械型号缓存。缓存预算要把同屏多人和掉落物的不同皮肤算进去；缓存不足时淘汰资源，不改变存档状态。

运行时建议使用 1024 贴图，保留导出目录中的 2048 原始图作为源。生成颜色图、ORM 图和必要的法线/珠光遮罩；不要把整套 CS2 VPK 或所有未使用的依赖打进 `.scmod`。最终运行时资产必须复制到 `ScCsgoKnives/src/ScCsgoKnives/Assets` 并进入项目清单，不能让 Windows/VPS 构建依赖本机 `E:` 路径。

先验证旧版 UV 的十款皮肤，再处理渐变之色。若某款涂装与现有模型 UV 不一致，优先离线烘焙到当前模型 UV；只有确实无法匹配时才增加独立模型。不要为了皮肤复制整套骨骼和动作。

## 6. 推荐批次

### P0：目录和离线预览

- 固定 11 个 `SkinKey`、名称、Paint ID 和资源路径。
- 生成每款的颜色/ORM/法线/遮罩运行时资产。
- 在 AWP、AK-47、M4A1-S 当前模型上输出预览图。
- 不修改枪械保存格式，不进入游戏物品流转。

### P1：三款试点

先做 AWP 雷击、AK 火蛇、M4A1-S 印花集，覆盖普通图案、自定义图案和珠光遮罩三种情况。

- 增加 registry schema 追加字段和 schema 1 转换。
- 工作台选择皮肤并扣费。
- 验证皮肤、弹量、耐久、消音器和充能同时保存。
- 验证同槽换枪和复制隔离。

### P2：全部 11 款

- 接入剩余皮肤。
- 补齐每款图标和工作台预览。
- 处理渐变之色的新版配方和遮罩。
- 做所有容器、掉落物和开箱接口回归。

### P3：材质质量和性能

- 实机比较印花集、永恒之枪的珠光近似。
- 统计同屏多皮肤缓存命中率、显存和帧时间。
- Full/Lite 使用同一 DLL，Lite 只在打包阶段生成降采样纹理。

## 7. 必须通过的验收

- schema 1 记录升级后 `SkinKey = none`，所有原状态不变。
- 皮肤枪保存、退出、重进、再次保存两轮后仍保持皮肤和实例状态。
- 皮肤枪在背包、箱子、Stash、掉落物、投射物和移动方块之间流转不丢皮肤。
- 皮肤枪和无皮肤枪不能合堆；不同皮肤不能合堆；不同实例状态不能合堆。
- 创造复制不会让两把枪共享后续耐久、弹量或充能变化。
- 材料不足、记录缺失、库存拒绝、ID 表满和写入异常时整体回滚，不扣材料、不替换枪、不丢待恢复物品。
- 未知 `SkinKey` 或未知 schema 不会被替换成另一款枪，也不会在自动保存时被改写。
- 离线 PackageCheck、真实引擎存读档、Windows 生存模式和创造模式分别报告；离线通过不代替实机验收。

本方案不改变当前枪械型号编号和 v5 物品布局，也不解除 M4 之外的批次暂停。完成皮肤功能前，M4 耐久和保存流转基线仍是前置条件。
