# CS 武器 1.0.7-preview：全量与 512 优化版

本次按用户要求制作两套安装包，并修正“开启简化材质后印花集明显变黑”的光照计算。两套使用同一份玩法 DLL，所有 35 枪、刀具、皮肤、动画、配件与音频保留。物品布局 v5、注册表 schema 6 和成长规则版本 4 沿用 1.0.5，没有新加存档转换步骤。

## 安装文件

- `output/CS武器-1.0.7-全量版.zip`：主包 `ScCsgoKnives-1.0.7-preview.scmod` + 原样保留的 `ScCsgoResources-1.0.0.scmod`。
- `output/CS武器-1.0.7-512优化版.zip`：主包 `ScCsgoKnives-1.0.7-Optimized512-preview.scmod` + `ScCsgoResources-1.1.0-Optimized512.scmod`。

ZIP 是安装文件集合，请先解压，再安装其中两个 scmod。退出游戏后，移出旧 CS 主包/资源包，只安装所选一套，不同时安装两个版本。全量资源 1.0.0 已存在时不必重复安装。暂存的 1.0.6 包不是本次最终交付，应使用上述 1.0.7。

设置入口：游戏设置 → 模组设置 → CS 枪械 → 打开设置 → 武器画质 → 简化材质。修改后保存。优化版在没有已有明确选择时默认开启，全量版默认关闭；已有保存选择优先。取消和保存失败保留原选择。两套共享本机设置，所以从全量切到优化版后可能仍保留之前的关闭选择。

从用户指定的 1.0 完整包迁移仍走既有自动备份/转换链；切换这两套 1.0.7 不要求清空世界或注册表。源档已经缺失的历史记录不会凭资源优化恢复，也不承诺任意老 DLL 能读新格式。

## 资源变化

| 内容 | 全量 | 优化 |
|---|---:|---:|
| 资源包大小，十进制 MB | 329.599 | 62.450 |
| 模型资源累计三角形 | 1,828,100 | 965,133 |
| M249 本体三角形 | 58,960 | 29,666 |
| Negev 本体三角形 | 57,089 | 29,177 |
| 蝴蝶刀本体三角形 | 11,996 | 5,998 |
| 双手三角形 / 顶点 | 10,802 / 6,274 | 8,214 / 4,840 |

模型总数是资源集的累计值，不是一帧的负担，也不是性能提升百分比。处理了 224 OBJ、32 刚性二进制模型、29 蒙皮模型，共 285 份；229 份面数减少，其余受体积、接缝或骨骼约束，保留几何并做索引/顶点整理。计数器内嵌的 330 面外壳与 48 面数字显示另行检查后保留，避免改变数字 UV 编码。没有宣称每个小零件都减半。

减面逐材质、逐刚性骨骼分组执行，锁定边界、极值点、混合权重顶点及跨骨骼连接；目标比例 50%、meshoptimizer 误差阈值 0.002，不能为达到比例突破误差约束。随后优化索引顺序、去除不再使用的顶点。保留顶点的位置、法线、UV、骨骼编号和权重逐字节保持原值，63 份动画数据保持原字节。第一人称、第三人称、掉落物复用各自对应的优化资源；没有新增按距离切换的动态 LOD 系统。

513 张纹理转为 WebP，其中 510 张有损 Q85，3 张特殊图集无损保留；342 张 1024² 缩至 512²，小图不放大。法线缩放后先归一化。`env_specular_rgbm`、`muzzle_fire`、`muzzle_smoke` 保留原尺寸/像素，避免 RGBM 数据、图集布局受损。普通 ORM/法线也接受用户授权的有损编码，完整材质下细节可能变化，不称为视觉无损。全部音频原样保留。

1024² 降到 512² 后，该张基础 RGBA8 纹理占用从 4MiB 降到 1MiB；同尺寸 WebP 本身不减少解码后的纹理内存。资源包大小降低约 81.1%，不能换算成手机帧率提升。

## 渲染变化与印花集修正

简化材质使用一个颜色纹理采样、几何法线和基础场景光照，不加载其 PBR 法线、ORM、环境图和 BRDF 图。关闭开关可恢复完整材质，但优化版图片/模型仍是优化资源，需要换全量资源才能恢复原分辨率和原几何。

最初的简化实现直接把线性光照强度乘在 sRGB 颜色上，间接光下会压暗过头。1.0.7 改为 `pow(light, 1/2.2)` 后再乘颜色，等价于当前 gamma 近似下的解码、照明、编码。没有用全局夜视或纯自发光掩盖问题。三款印花集转换前后的平均颜色没有显著下降；用户反馈“只有开启简化材质才黑”与该路径一致。修复已通过独立桌面 GPU 实验，最终手机现场效果仍待复验。

不变的刚性枪身改用持久顶点/索引缓冲，最多缓存 8 个网格，淘汰和退世界时明确释放；设备重置后重新上传。动态手部/刀具保持逐帧更新，不能误用不变缓冲。没有合并必须独立动画的骨骼部件，因此没有把 M249 的 36 个部件谎报为一次绘制。

## 重现构建

所有构建、Python 工具通过 `tools/dev.ps1` 运行，临时数据保持在项目 `.tmp`。

1. `python -m pip install --target .tmp/optimization-deps meshoptimizer==0.2.30a0`（构建端依赖，玩家不需要）。
2. `python -X utf8 tools/optimize_weapon_resources.py`；明细写入 `output/optimization-106/assets.json`。
3. 用实际 API DLL 构建主项目 Release，再 `python -X utf8 tools/pack_scmod.py --edition full --split-resources`。
4. `python -X utf8 tools/pack_optimized_scmod.py` 构建独立派生资源 DLL 并输出配套优化包。
5. `python -X utf8 tools/validate_optimized_models.py`；用 PackageCheck 对两套最终包执行上述回归。
6. 可选独立 GPU 检查另需构建端 `moderngl`、`glcontext`，运行 `preview_optimized_geometry.py` 和 `validate_simple_lighting.py`。
