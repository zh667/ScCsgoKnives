## 为什么当前曳光不像 CS2

### 1. 起点错误：从眼睛/准星射线出发，不是从第一人称枪口出发

`SubsystemScGunBlockBehavior.Fire()` 当前：

```csharp
Ray3 ray = input.Dig ?? input.Hit ?? new Ray3(eyePosition, eyeDirection);
Vector3 start = ray.Position;
...
QueueTracer(spec.Name, start, direction, travel);
```

这里的 `start` 是命中检测射线原点。`Cs2Effects.MuzzlePosition()` 只用于枪口火光，完全没有用于曳光。
所以曳光在几何上从相机/眼睛开始，而不是从屏幕上可见枪管的枪口开始。这会直接产生“从准星附近射出”“贴脸是一整块亮带”等不自然观感。

第一人称枪使用独立 viewmodel FOV，因此不能简单把 rig 坐标当作普通世界坐标。建议：

- 取得与 `DrawCs2MuzzleFlash()` 完全相同的枪口 rig 点和 placement；
- 用 viewmodel projection 得到精确枪口屏幕位置；
- 用普通世界相机投影得到命中点/远端的屏幕位置；
- 在屏幕/clip space 绘制从枪口到移动 head 的带，或实现能保持这两个投影端点一致的混合路径；
- 不要再以 gameplay ray 的眼睛位置作为可见曳光起点。

### 2. CS2 的材质被记录但没有被使用

JSON 已记录：

```text
AK/M4: particles/weapons/cs_weapon_fx/weapon_tracers_assrifle.vpcf
AWP:   particles/weapons/cs_weapon_fx/weapon_tracers_rifle.vpcf
```

但运行时只调用 `FlatBatch3D` 画两个纯色三角形。没有加载 tracer/spark 纹理，也没有采样 CS2 的 trail material。

报告已经写明 AK/M4 的颜色来自 spark 贴图；当前 `ColorMin/ColorMax` 缺失时却直接退回纯白，因此源文件已明确指出的信息并未进入最终画面。

### 3. 形状是固定宽度的矩形

当前实现：

```csharp
side = side / length * 0.012f;
QueueTriangle(...);
QueueTriangle(...);
```

即固定半宽 0.012、总宽约 0.024 引擎单位的相机朝向矩形。该宽度没有来源；没有头尾收尖、沿程 alpha、半径曲线、UV 或软边。近处尤其容易看成一根白板/激光条。

### 4. 时间包络也只是部分近似

当前只做：

- `head = speed * age`；
- `tail = head - maxLength`；
- 全带统一 alpha，用 `age / fadeIn` 淡入；
- 尾端越过命中距离后整条直接删除。

没有 CS2 `C_OP_RenderTrails` 的沿程宽度/透明度和贴图变化，也没有材质 bloom/HDR 表现。因此频率、速度、最大长度数字正确，不等于视觉已还原。

## VPS 侧建议修法

1. 先修枪口起点。该项是几何正确性的硬门槛，不能用调宽度掩盖。
2. 从本地 CS2 导出件取得 `weapon_tracers_assrifle` / `weapon_tracers_rifle` 最终使用的 trail material 和 spark 纹理；如果引擎不能复现完整 VPCF，至少烘成带透明软边、头尾渐变的 1D/2D trail 纹理。
3. 从 VPCF 继续解析 `C_OP_RenderTrails` 的半径/宽度曲线和 alpha 曲线，不再写死 0.012。
4. 用带 UV 的 textured/additive ribbon；按长度分段或在 shader 中沿 UV 做头尾收尖与亮度衰减。
5. 区分 AK/M4 spark 材质颜色和 AWP 的颜色范围，不允许 AK/M4 因缺 `ColorMin/Max` 直接变纯白。
6. 将“曳光视觉”加入单独 FX 验收，而不是只断言 JSON 数字到达 C#。

建议的 FX 实拍验收至少包含：

- AK/M4 每 3 发、AWP 每发的频率；
- 枪口起点相对可见枪口误差（建议 <= 3 px）；
- 远距离对墙时逐帧量 head 位置、可见持续时间与尾长；
- 中段宽度、头尾宽度和亮度分布，与同分辨率 CS2 参考帧比较；
- 不允许纯白硬边矩形或整条单帧突消。
