# 极简包开源压缩方案与 30 MB 评估

本次要求保留轻量枪械轮廓、512 颜色、35 枪/13 枪皮并开启检视；40 MB 是交付上限，30 MB 是探索目标。
实测可交付文件为 **36,095,429 B**，30 MB 尚未实现，仍需减少 **6,095,429 B**。

本次从下列项目的官方 GitHub README 读取信息，来源 URL 和内容哈希见证据。资料里的速度/比率不是本项目实测结果。

| 项目 | 能处理什么 | 当前适配判断 |
| --- | --- | --- |
| [meshoptimizer](https://github.com/zeux/meshoptimizer) | 顶点/索引编码、量化、减面等独立能力，MIT | 本项目已用减面；无损编码另做实际试验，见下文。需要运行时解码器才能使用编码数据。 |
| [ACL](https://github.com/nfrechette/acl) | 动画压缩/运行时采样，MIT，C++11 | 值得进一步评估，但需编译和接入对应平台解码/采样器，验证骨架、事件及 additive 行为。未完成 Android 集成。 |
| [Brotli](https://github.com/google/brotli) | 通用无损压缩，MIT | .NET 可用解码 API，但 DLL 内新封装仍需接入资源读取，不会仅靠改文件后缀生效。压缩包小不表示展开后的动画数组小。 |
| [Basis Universal](https://github.com/BinomialLLC/basis_universal) | KTX2/Basis 与 GPU 纹理转码 | 需调整现有 WebP→原生纹理路径和 GPU 格式支持。高压缩档有损；未进行手机纹理转码/显示验收。 |

## meshoptimizer 实测

使用已安装的 Python meshoptimizer 0.2.30a0（原项目减面工具同一依赖），读取当前候选中全部 62 个内嵌 `.parts/.skin`。
保留坐标、法线、UV、骨骼、权重的原浮点位和所有索引顺序；未做量化、重排、减面。
顶点编码后逐块解码比对字节；索引用 index **sequence** codec，避免 triangle codec 的三角顶点循环旋转改变 provoking vertex。
元数据和编码数据组成实验容器，再以 Brotli quality 9 压缩。

| 同一组模型 | 大小 |
| --- | ---: |
| 原始二进制 | 25,552,416 B |
| 逐文件 zlib9 对照 | 11,646,410 B |
| meshoptimizer + Brotli9 实验 | 12,115,353 B |

本次无损配置反而多 **468,943 B**。与库文档一致：编码器更适合已量化且优化布局的顶点。
不能由此推断 meshoptimizer 无用，也不能把库的典型 2–4 倍压缩比套到本项目已经 Deflate 的文件上。
该容器是离线实验，不是引擎可加载的格式；没有发布实验数据或声称已经接入 Android。

## 下一步可行方向与限制

追 30 MB 最值得评估的是：适度且误差可控的顶点量化配合 meshoptimizer、OBJ 转紧凑的原生二进制几何，
以及 ACL/等效动画压缩。它们可能在保留面数的前提下降低体积，但需要编解码、姿态、UV、第三人称和手机加载验证。
目前没有本项目证据支持“开启检视、恢复画质后，无损一定能压到 30 MB”。
本次按已验证的 40 MB 范围交付，保留现有原生读取方式，不以未经接入的编码大小充当正式包大小。

## 检视测量方法

`audit_minimal_animation.py` 比较旧轻量动画 JSON 移除检视前后的逐文件 zlib9 大小，并统计 float32 数字载荷。
90 段检视共有 829,165 个关键帧，边际压缩估计 7,077,406 B，数字载荷 16,073,888 B。
本版简化后的检视关键帧为 236,251；新旧同画质候选实际包差约 2.97 MB。

`AnimationMemoryCheck` 在独立进程加载包内核心/资源 DLL，先预热元数据，再按固定顺序采样64个资源，
完整 GC 后读取托管内存，并报告缓存实际项数（40）。随后只在诊断进程清除已缓存检视曲线再次 GC，观察边际释放。
测量不包括 GPU/声音/网格/峰值，不可视为 Android 内存实测；几 KB 的负差值是测量噪声。
