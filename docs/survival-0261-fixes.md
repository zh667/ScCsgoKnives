# 0.26.1 实机反馈修复

用户提供三张游戏截图及 Bugs/Game.log，本轮修复换弹实际失败、投掷物图标空白、装配台手持异常，并将装配台移至“物品”。

## 原因与修复

- 创造模式换弹：游戏 `ComponentCreativeInventory.GetSlotCount` 返回 536870911 表示无限物品，原换弹事务要求数量恰好为 1，每帧因此取消。日志可见 FAMAS reload/idle 在数毫秒间反复切换。修复为辨认可写创造槽位，在动画的丢匣/插匣/逐颗装填事件写回子弹数据，使用创造背包原生覆盖接口；生存模式仍严格检查单件武器和扣料。只读创造目录不改写，切槽、换物品或取消后仍停止事务。
- 投掷物图标：原版 DrawFlatBlock 即使传入独立图片也会读取方块的贴图分格设置。此前继承 16×16 图集，实际只取到独立图片左上角透明区域。六种投掷物改为完整 1×1 图片，并让图标平面正对栏位相机；立体模型预览保持独立路径。
- 装配台：此前第一人称使用默认缩放 1、偏移 0，镜头位于模型附近。现在采用原版工作台的第一人称缩放 0.4 和偏移 (0.5,-0.5,-0.6)，第三人称持握缩放 0.5；世界中的桌子尺寸不变。同类新增弹匣/霰弹/零件也设置了单独的持握大小与偏移。
- 装配台分类从 Construction 改为 Items（游戏“物品”）。不改物品编号、配方或模型资源。

## 验证

本轮用**真实 API 创造背包**代替普通库存模拟类，覆盖 34 把非电击枪的空枪及半匣装填、管式逐颗装填、MAG-7 换匣、150 发内格夫、重复事件、切槽/换物品取消和只读目录保护；使用包内方块参数检查图标完整 UV、持握网格离开镜头及分类。

同一组新增检查在旧 0.26.0 包上产生 80 项失败，修复后最终包 **3333 项通过，0 失败**。对比与日志片段见 [回归对照](survival-0261-regression-comparison.json)，全部结果见 [包检查](survival-0261-packagecheck.json)。
