## 已实施的玩法

- 属性页增加 −10／+10；窄屏单独一行。保留 ±1 和点击等级恢复实际等级。所有操作只做预览，0～50 自动限界。
- 普通枪基础射速 ×0.65；SCAR-20／G3SG1 再 ×0.75，即旧射速的48.75%，连狙基础整发伤害27→24。普通枪及连狙沿用线性成长，栓狙保留独立曲线。三连发间隔／组间隔、R8 副攻／准备、再开镜时间通过同一射速函数计算。换弹动画不加速。
- AK-47 伤害仍为 Lv0 15、Lv50 150；射速600→390 RPM（Lv0），900→585 RPM（Lv50）。原厂连狙 Lv0 117 RPM、Lv50 175.5 RPM，身体伤害24／240。
- Nova／XM1014／Sawed-Off／MAG-7 的 Lv0 近距离整发伤害分别54／36／60／54；新增基础补偿随等级线性减少，Lv20归零，再乘原有成长与皮肤倍率。整发预算分给各弹丸，不按每颗重复计算。基础散布分别2.10／2.05／3.20／2.10度；移动、跳跃和连续射击惩罚保留。
- Zeus 新充能约15.3846秒（Lv0）、7.6923秒（Lv10）、1.53846秒（Lv50）。属性页按充能限制显示有效射速，避免显示扳机间隔对应的虚高数值。旧枪正在进行的充能在版本迁移时保留剩余秒数和原周期；下一次发射才启用新周期。普通游戏内升级仍保留充能剩余比例。
- 玩家、友方持枪 NPC 使用同一有效属性来源；敌对 NPC 原来绕过生存伤害表，现接入 Lv0 整发伤害、衰减和基础射速，保留角色射距、误差、连射停顿和最低间隔。实际 NPC 吞吐仍受这些限制，不能直接等同表格理论 RPM。
- HE 半径6→7.8格、中心攻击力48→96；小鸡爆炸单独保留6／48。燃烧瓶／燃烧弹地面半径2.5→3、3→3.6格，火区每秒攻击力4→6，寿命6／7秒。保留墙体、楼层、水、烟雾灭火、友伤限制及重叠火区只取最高预算。**没有加入生物着火或离区持续灼烧。**

Glock／P2000／P250／USP 装配改为坯件3、机构1、握持1。其他枪的装配组件数量、等级门槛及额外矿物按原规划保留；详见[35枪及阶段材料表](gun-balance-tables-2026-09-24.md)。霰弹原材料不变，每份产出8→12，批量1／2／3份实际得到12／24／36发。

首次上皮：机构2＋涂装4＋钻石1；有效皮肤互换：涂装2；拆皮：涂装1；同皮重复选择不扣费。选项材料显示与确认／事务共用报价逻辑，皮肤变更不重置枪械身份、击杀、等级、弹药或耐久。

维修只收下列两类组件。表内是**全损**费用，顺序均为“坯件／机构”：

| 类别 | Lv0–9 | Lv10–19 | Lv20–29 | Lv30–39 | Lv40–49 | Lv50 |

| 手枪、霰弹 | 2／1 | 3／2 | 3／2 | 4／2 | 4／2 | 4／2 |
| 冲锋、步枪、栓狙 | 3／2 | 4／3 | 5／3 | 5／4 | 6／4 | 6／4 |

| Zeus | 5／5 | 6／6 | 7／7 | 8／8 | 9／9 | 10／10 |

实际费用使用未取整的 Lv0 基数，以整数长整型计算：

`ceil(基础数 × (5 + floor(已应用等级 / 10)) × 缺损耐久 / (5 × 最大耐久))`

只在最后取整，**不把上表的全损整数再乘缺损比例**。例如 Lv10 手枪缺损40%收坯件1／机构1，而非2／1。待应用等级、击杀已解锁等级和预览等级都不参与提前加价。报价冻结实例、修订号、已应用等级及耐久；状态变更须重新报价，材料不足或扣料失败不会给枪满修。25／50／75／100%缺损的120组材料明细继续见附表。

## 用户指定旧安装包的迁移

| 来源 | 实际内部版本／API | 布局／schema／成长规则 | 新代码处理 |
|---|---|---|---|
| `[API1.9]CS武器1.2.0-全量版.scmod` | 1.2.0／1.9.3.1 | v5／6／7，50级 | 不转换结构；测试中的原记录字段逐字保持，运行属性使用新平衡 |
| `[API1.9]CS武器1.0- 作者ZH667.scmod` | 1.0.0／1.9.2.1 | v5／4／2，30级 | 使用已有 schema4→6 转换；先校验完整世界备份，失败拒绝加载 |

两个包的 SHA256、提取 DLL 和固定 XML 样例哈希记录在[验证证据](gun-balance-implementation-evidence-2026-09-24.json)。验证直接调用这两份 DLL 的旧序列化器和跨世界快照生成器，不用新代码伪造“旧存档”。仓库保存压缩后的旧 XML 数据样例，未纳入用户的巨大安装包或 DLL。

1.0 的30级成长换算继续按既有规则：取新版首次达到旧**成长倍率**的等级，若已存击杀可解锁更高等级则取更高者；Lv30映射Lv50。显示击杀不变，差额记为成长信用，不虚构击杀。这里保留的是成长权益，连狙本轮主动降低的基础伤害／射速仍会生效。计数模式不因旧击杀突然获得成长。

旧型号及实例引用保持；弹药不赠送，超容量弹药保留在该枪储备；耐久按旧比例转换，坏枪仍坏、满枪仍满；涂装、消音器、修订号和分配水位保留。版本升级不会把正在充能的枪重置充满，也不会因本次降射速延长它的剩余秒数。两轮保存重载后的结果稳定，不重复补偿或升级。

schema4→6 备份包含 `Project.xml`、地形文件和第三方附属文件，排除已有 snapshot 防止嵌套膨胀；备份逐文件校验。未落盘前重试创建独立备份，保留首次成功快照。1.2.0 是同 schema 参数更新，不会触发“schema迁移专用自动备份”。

**玩家升级流程（供后续发布使用）：** 退出世界及游戏，另存一份完整世界副本，并保留对应旧安装包；使用符合新版要求的 API，只启用一个 CS 核心版本。先在世界副本验收背包、各容器、掉落枪和两把独立充能枪，存退后重进两次。实际1.0旧包声明 API1.9.2.1，本次转换测试运行于1.9.3.1，不能把旧包来源版本等同于新版本运行要求。不要直接用1.0打开已转为schema6的世界；回退时同时恢复升级前世界与匹配旧包。1.2.0同格式也不视为任意降级承诺。

## 验证与边界

- 源码构建0错误；完整 `Cs2SelfTest` 加新平衡及真实旧包回归 **28,627／28,627**。
- 35枪×6等级×两种枪感设置对照原规划数值；120组维修报价；霰弹逐级伤害单调性及整发预算；组件、装配、批量弹药；材料不足、扣料故障、过期维修报价和首次上皮／换皮／拆皮实际扣费。
- 两旧版合计11,340条旧枪记录，覆盖多级、满／半／坏耐久、满／半／空弹、消音器及旧皮肤轮选，经过两轮 XML 存读，共22,680次记录状态核对。1.2.0完整记录原样保持，1.0按明确规则换算；另测 CountOnly、源 XML 不变、完整世界备份、重试和备份失败。
- 两个旧版×35枪×生存／创造共140组实际跨世界快照导入，每组3把不同状态枪，验证重映射后的整条记录和源数据不变。原有未来 schema／布局拒绝、事务回滚、补偿恢复、注册表满及0.28.2专用迁移检查继续通过。
- 指定 Mods 中真实 Sushi DLL 回归及相关存档／事务检查 **2,248／2,248**。源码测试宿主补齐了三把 OBJ 枪模型的读取依赖，避免宿主缺内容造成假失败。
- Windows 原生控件在1100×650、850×479、480×850、360×640共 **28／28** 项通过：±10按钮在屏内，五次达50／0，边界限界，恢复实际等级，整个枪表未变。

这些是实际旧 DLL 生成数据的离线迁移、原生控件及合成世界文件测试，**不是玩家原世界或整套 Mods 的实机验收**。尚未实测安卓触控手感、不同模组防御后的真实掉血、所有第三方容器组合、引擎断电／磁盘故障落盘及完整游戏战斗。旧世界应先在副本验收；不能据此承诺任意损坏来源和任意 Mod 组合都绝对安全。当前没有包装发布，所以玩家安装版仍未自动获得这些改动。

## 复现

在项目根执行 `./tools/BalanceCheck/Run.ps1`：先按固定哈希核对两个用户包，只提取核心 DLL 至 E盘项目 `.tmp`，再通过 `tools/dev.ps1` 构建／测试，显式禁用打包。可用 `-Version120`、`-Version100` 指定同哈希包的新位置。

原生UI：`./tools/dev.ps1 dotnet run --project tools/BalanceCheck -c Release '-p:SkipScmodPackaging=true' -- --ui '<API的Content.zip>' .tmp/balance-ui.json`。

完整检查明细在本机 `.tmp/balance-check.json`、`.tmp/balance-ui.json`、`.tmp/balance-inventory.json`；提交的证据记录分组计数、失败列表和文件哈希。固定旧样例位于 `tools/fixtures/balance-20260924`；重新生成须与已有样例精确相等，不能覆盖它来掩盖回归。
