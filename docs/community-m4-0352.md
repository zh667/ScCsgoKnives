# 0.35.2 旧格式枪械不再自动转换：保留原样、明确提示、世界布局戳

日期：2026-09-08。复查确认 0.35.0 把 0.32–0.34 的 v4 枪（如 116173、115720）当成 v3 旧枪解码，读成 P250/MP9 并在开枪、换弹后写进了实例表（该世界 ID 1、ID 2 已固化为 P250/MP9，**无法可靠还原**）。
根因：`IsLegacy` 只看第 16 位，而 v3 的格式标记和 v4 的耐久码都会置这一位，两种格式无法靠位模式区分。

## 改法

- **取消自动旧枪识别。** 第 16 位置位的物品一律视为"旧版本格式"：型号名显示为"旧版本枪械数据（0.34 及更早，已保留，请新建世界）"，物品栏画成未知贴图，
  不能开火、不显示 HUD、任何写入（开枪/换弹/消音器/维修）都不发生，也不分配实例记录。数据原样保留。
- 手里拿到这种枪时提示一次："这把枪是旧版本的数据，本版无法使用（已保留原样）。请新建世界。"并写 Game.log 警告（含 data 值与世界布局戳）。
- 世界存档新增 `GunDataLayout = 5` 布局戳；读档时把戳和本版布局一起写进日志（无戳 = 0.34 及更早保存或新世界）。以后布局若再变，按戳判断而不是按位猜。
- v5 新枪的第 16 位永远为 0，自检断言所有 fresh/记录值都不置位。

## 验证

PackageCheck 6158/6158，运行时自检 5887/5887（`community-m4-0352-packagecheck.json`）。新增 `gun-old-format-kept-untouched`（65858/116173/115720 三个复查值：识别为旧格式、读不到弹量、写入不改值、不分配记录、`IsKnown` 为假），`gunspec/layout` 的 v3 段改为"旧格式不被解码不被写入"。

## 说明

- 已经被 0.35.0 转换并保存的枪（那个世界的 ID 1/ID 2）无法还原，需新建世界。
- 0.35.0 新建的世界不受影响。
