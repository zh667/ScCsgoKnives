# 1.3.0 全量：小队和多人卡顿诊断

用户反馈上一轮动画缓存修复后仍有短暂卡顿，尤其三人、五人队和多次召唤；要求读取 Bugs 日志、参考尸鬼，并授权增加日志。本轮交付带限频性能日志的全量诊断包，公开版本继续 1.3.0。这是进一步定位用构建，不宣称已解决剩余卡顿。

- 安装的全量 SHA-256 是 `b4d31f6e785cb8fb5814c01b9d228dbacf3b097da98c73528ee868eaf9a38099`，确实为上一轮预烘焙动画缓存包。
- 日志包含多次启动。最新一次约 20:37–20:38，世界正常进入/退出，没有召唤分段耗时或 CS_PERF，无法从这段日志直接确定长帧发生在哪个操作。

## 对比和可复现的开销

只读反编译官方尸鬼包的 `ComponentSAGPlayer.Spawn`，仍是 CreateEntity、设置角色状态和位置、AddEntity；该入口没有异步工作队列。此前资源审计中尸鬼最大的 DAE 约 582 KB，模型路径与 CS 全量人物、持枪资源的成本不能等同。完整反编译临时资料不纳入交付或提交。

Windows / RTX 3060 Laptop 原生隔离探针发现：

1. 上轮移除了重型 glTF 动画转换，但首次人物纹理解码/上传仍有成本，CT/T 的探针约 0.11–0.18 秒；首次动画控制器还包括 JIT/配置初始化成本。
2. 三人、五人队一次创建完成后，会首次展示多种随机武器。`ScThirdPersonWeapon.For` 首次构建 AWP、AK、MP9、M249、沙鹰的网格分别约 0.21–0.25、0.16–0.18、0.05–0.06、0.09–0.11、0.05–0.11 秒（独立探针重复运行范围）。此测量不含枪械纹理上传、AI、整帧 GPU 工作，不能直接当作手机或完整小队召唤耗时。
3. 这些模型分别约 119,292、78,498、24,393、54,973、15,038 个第三人称顶点。连续 1,000 次重复取用保持同一对象，未发现每帧重建。缓存超过 12 项时有 2 秒活跃保留，不能仅看到容量 12 就断言多人场景缓存抖动。
4. 1/3/5/20 人隔离动画和骨骼层级计算显示随人数增加的 CPU 开销及临时分配。20 CT 约 0.49 MB/帧、20 T 约 0.22 MB/帧（探针含少量反射控制开销）。实际 Engine.Animation.AnimationPlayer 每次采样创建通道聚合 Dictionary，证实存在这种分配来源；此探针不包含武器绘制、AI、地形、碰撞或其他模组。不能由此报告游戏 FPS 或认定它是用户手机唯一瓶颈。

因此优先用实际世界分段日志确认首次武器准备、持续武器提交、骨骼/动画、AI 的占比，再决定后续优化。没有改成后台 GPU 加载，没有分帧破坏整队召唤的消费/失败回滚语义，没有降低资源质量或调整人数和战斗规则。

## 诊断字段

日志写入游戏已有日志系统，不创建世界诊断文件，也不添加存档字段。

- 启动标记 `[CS_PERF] build=crowd-diag-20260926` 和 tacticalMvid 用于区别同为 1.3.0 的包。
- 每 10 秒汇总当前敌队/同伴数、窗口峰值、引擎帧均值/最大值、50/100/250 ms 长帧数、GC 次数和托管内存。单个原生帧只采一次；无 CS 活动时不输出空汇总，退出世界输出余量。
- 分段：Placement、EntityCreate、Configure、AddEntity、ModelLoad、ModelSet、AnimationCache、ActionsInit、EnemyAI、CompanionAI、Animate、Bones、Extras、WeaponResolve、WeaponBuild、WeaponDraw、Director。
- 每段包含次数、总耗时、单次最大值和当前线程累计分配。模型/武器记录最大耗时对应资源，便于找出特定枪型。父段包含子段，不可相加当作总帧耗时。
- 召唤开始/结束及成功状态至多每秒一组；被抑制的明细仍保留累计计数。小队记录从创建开始，Placement 单独统计；投放无落点不会被记作已开始创建的小队。
- 热路径只有时间戳、线程分配读数和固定数组计数；无逐帧字符串格式化或磁盘写入，无强制 GC。100,000 次计时范围分配检查和日志节流检查通过，电脑单次约 0.2 微秒，手机成本尚未测量。
- 引擎帧时间包含其他模组、地形、渲染等待和垂直同步；统计不是 GPU 时间。CS 各段低而整帧高时还要继续区分 GPU、原生渲染/物理、其他模组等，不能直接归责第三方。
