## 二、P0 动作别名与资源完整性

### 1–2. 补齐 18 个别名

`tools/cs2_knife_rig.py` 的别名表加了 `deploy2 -> draw2_*`、`inspect2 -> lookat02_*`、
`inspect3 -> lookat03_*`。22 把刀重新生成后，**CS:MC 提供的每个别名，CS2 侧都答得上**：

```
butterfly  CS:MC wants [deploy,deploy2,idle,idle2,inspect,inspect2,inspect3,slash1,slash2]
                answered [deploy,deploy2,idle,idle2,inspect,inspect2,inspect3,slash1,slash2]
...  22 把全部 wants == answered
```

### 生成器现在自己会拦

生成时对照该刀的 `.csmc.animation.json`：CS:MC 提供、CS2 答不上的别名会让
`cs2_knife_rig.py` **exit 1 并列出刀名和别名**。这类洞不会再悄悄进包。
（`idle2` 是唯一豁免：CS2 和 CS:MC 都同意 bowie / falchion / push 只有一个 idle。）

### 3–4. 按 profile 查询

新增 `Cs2Rig.HasAlias(asset, alias)`——严格解析，不带 idle 回退。控制器新增：

```csharp
static bool HasAlias(int variant, string alias) =>
    Cs2Placement.Active(variant)
        ? Cs2Rig.HasAlias(CsmcKnifeRig.GetAssetName(variant), alias)
        : CsmcKnifeRig.HasClip(variant, alias);
```

四个选别名的地方全部改走它：`deploy2`、`slash2`、`idle2`、`inspect/2/3`。

### 5. 回退不再静默

`ResolveOrIdle` 仍然回退（画 idle 好过不画），但非 `idle/idle2` 的回退现在
`WarnOnce` 打出：哪个 asset、请求的别名、这把刀实际有哪些别名。

另加动作映射日志（你们要的那条）：

```
[ScCsgoKnives] CS2 action: asset=butterfly requested=deploy2 resolved=draw2_butterfly
```

只在 `Cs2Placement.Active` 时打，每次 `Start()` 一条。

## 三、P0 输入状态机

`State` 增加 `PendingInspect`。

1. **Draw 期间按 G** → 记 `PendingInspect`，返回 true。deploy 结束时
   `Update()` 优先兑现它再回 idle，不再静默吞键。
2. **检视进行中再按 G** → 直接返回，**不重置 `StartedAt`**。
   （你们测到 0.174 / 0.187 / 0.173 秒的连续重启就是这条。）
3. **切刀时清 `PendingInspect`**，上一把刀的挂起不会带到下一把。

`KnifeQa` 激活或待命时不排队，避免和采集流程打架。

## 四、P1 回归与可观测性

### 强制覆盖测试

`Cs2SelfTest` 新增两组，**7 把 + 10 把 + 1 把按名字写死**：

```csharp
static readonly (string Alias, string[] Knives)[] RequiredVariants = [
    ("deploy2",  ["butterfly","canis","cord","kukri","outdoor","skeleton","ursus"]),
    ("inspect2", ["butterfly","canis","cord","css","falchion","outdoor",
                  "skeleton","stiletto","talon","ursus"]),
    ("inspect3", ["butterfly"]),
];
```

写死名字是有意的：0.17.0 能通过"没有刀缺别名"这种测试，**因为文件里压根没有那些别名可缺**。

判据是**解析到的 clip 不同**，不是时长不同。第一版我用时长判，6 把刀的 `deploy2` 和
`deploy` 都是 1.0000 秒直接误报——时长区分不了两个动画：

```
variant/butterfly/deploy2   draw2_butterfly (1 s), deploy is draw_butterfly
variant/butterfly/inspect2  lookat02_butterfly (4.5 s), inspect is lookat01_butterfly
variant/butterfly/inspect3  lookat03_butterfly (4.8666 s), inspect is lookat01_butterfly
```

另加**全别名一致性**：每把刀，CS:MC 提供的每个别名都必须在 CS2 侧严格解析成功
（`knife/<name>/aliases`，22 项）。

### 计时拆三档

```
[ScCsgoKnives] cs2 CPU skinning over 120 frames:
  arms 0.xxx ms/frame (6274 vertices, 10802 triangles);
  weapon 0.xxx ms/frame (butterfly, 10337 vertices, 11996 triangles);
  combined 0.xxx ms/frame.
```

刀网格的顶点数和三角数按当前实际那把打，不是常量。

### KnifeProfile 写进调参文件

`Serialize()` 现在在 `GunProfile` 之前输出 `KnifeProfile`，带中文注释。
版本戳重写后它会自己出现，不用手工补。

### Drawable 重复注册

`Load()` 改成先 `RemoveDrawable(this)` 再 `AddDrawable(this)`，幂等。
（`AddDrawable` 本身是 `TryAdd` 不抛异常，唯一损害是那行 ERROR 会被误读成真故障。）

### kukri 左臂警告

同意你们的判断：那是 `BuildLeftArmUsable()` 对**旧 CSMC rig** 的启动期预计算，
CS2 路线走 `DrawCs2Arms()` 不读这张表。本版未改，属于日志噪声。

## 六、Windows 最小回归（按你们第 8 节）

装 0.17.1，`KnifeProfile = 1`，其余保持。**不需要跑 22 把完整长测。**

1. **7 把 deploy2 刀**各切入约 10 次：`butterfly` `canis` `cord` `kukri` `outdoor`
   `skeleton` `ursus`。普通/特殊切刀都应实际播放，不再直接 idle。
   日志里应能看到 `resolved=draw2_<name>`。
2. **10 把多检视刀**各按 G 约 5 次：上面 7 把里的 5 把加 `css` `falchion` `stiletto`
   `talon`。每次按键都应启动可见动作；蝴蝶刀应能看到三种不同检视。
3. **deploy 期间按一次 G**，确认 deploy 播完自动进入检视。
4. **检视期间快速连按 G**，确认当前检视不被重置回第 0 帧。
5. **补测 `bayonet`、`bowie`** 的 deploy / idle / inspect / 左右键挥砍
   （0.17.0 这两把没触发加载）。
6. 玩约两分钟，回收新的三档 CPU skinning 数字。
