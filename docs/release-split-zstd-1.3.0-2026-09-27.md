## 使用和手机验收

只玩武器可以单独更新轻量包；使用探员功能时，**同时更新本次轻量包与探员包**。旧版虽然也标 1.3.0，但缺少新资源解码器，新探员包会明确拒绝与它混用。外观功能仍沿用 NekoMeko Model 1.1 和 Neorxna 1.4 的前置要求。

手机端优先测试首次进入和重进世界、连续召唤 3/5 人小队、已有较多 NPC 时继续召唤、NEO 换模。原有 CS_PERF 预热/召唤/帧与 GC 日志继续保留，可用于比较卡顿。**本轮完成的是 Windows 原生验证，尚未进行 Android 实机验收，也未宣称手机帧率或常驻内存改善。** 压缩后的资源仍须还原成原有对象；包体积下降不等于运行内存同比下降。

全量包、极简包及其他既有 output/scmod 均校验不变；未安装到 Mods，未读写玩家世界。原轻量/探员包保存在 .tmp/codec-release-130-20260927/baseline，属于开发归档，不是自动世界备份。

## 实现边界

- 外层继续使用游戏支持的标准 ZIP stored/Deflate，保留未改变成员原有的强压缩流。内部 126 份模型/JSON 嵌入资源与 65 份探员动画/NPC 几何为候选编码对象；外部缓存仅在节省体积时换用新流。
- SCZSTD01 封装包含压缩前后长度、原始数据 SHA-256 和 Zstd frame。长度在分配前限制为各 64 MiB；验证截断、额外字节、解压长度和校验和。原格式仍可读取。
- 解码后把原始字节交给既有 JSON、模型、动画读取器；沿用 35 枪、44 枪皮、22 刀及皮肤、524 武器动作、512 颜色贴图，以及 CT/T 各 170 动画片段。全部 191 份资源逐字节比对旧交付通过。
- 解码按既有加载/缓存边界执行。临时解码结果不再做第二份完整复制，也不建立新的常驻原始数据缓存。ContentManager 共享输入流保持打开；只释放当前读取器拥有的流。
- NPC 缓存损坏或内存不足明确拒绝，不进入昂贵的原始几何重建回退。正常资源缓存复用和失效生命周期保持原样。CT/T 继续在既有加载预热中读取缓存，GLB/OBJ 与原生缓存没有删除。
- ZstdSharp.Port 0.8.8 使用 NuGet 记录的固定源码 commit 2cd0c019693bc786a5fe5c3be94e107b24e7267e，按原 Fody 内联方式编译为 **ScCsgoResourceCodec.dll**。采用不同程序集身份，不提供全局 DLL 别名，不替换其他 mod 的 ZstdSharp。
- 解码库仅在核心携带一份，是托管 C# 实现；没有增加 Android 原生 .so。保留 MIT 许可与来源。目标 API/.NET 与既有包一致；Android/AOT 的最终行为仍由实机验收确定。
- 不改存档 v5/schema6/rules7、物品 ID 或公开版本。新增程序集和读取器在独立构建目录生成，没有覆盖 Full/Mini 的构建产物。

## 源码与重建

本轮开始时已有另一工作线的 Zeus 未提交修改。未改写或提交它们；构建使用当前工作区快照，并对照旧交付验证平衡/存档行为。源文件输入哈希记入证据；不能将本提交单独宣称为包含那条工作线的完整源码提交。

通过 tools/dev.ps1 执行以下步骤。基线为研究记录的当前分离包，不可把早期总轻量包或极简模型当作编码输入。依赖前轮研究的 .tmp/resource-codecs-20260926/inventory.json 与原始提取文件；需要时用 ResourceCodecCheck extract 从固定基线重建它们。

1. prepare_codec_release.py：验证基线、固定上游 ZIP、原始资源哈希；生成新封装和隔离源码快照。
2. dotnet build src/ScCsgoResourceCodec -c Release；依次构建本轮 stage 的 resources、core/source、agents/source 项目。
3. package_codec_release.py：生成候选，保留原 ZIP 流，强压缩变化成员，更新配对标记和许可。
4. CodecReleaseCheck：运行正常路径与 DOTNET_EnableHWIntrinsic=0 路径。
5. stage_codec_checks.py：从候选准备原生测试夹具；构建 checks 下 resources、npc、actor、split、load-check、compat-runner 项目。
6. check_codec_release.py 的 load、runtime、compat 三组检查。
7. publish_codec_release.py：校验检查报告、包/资源/DLL/源码哈希和未动交付后，仅替换两个目标文件。

固定来源：[ZstdSharp 0.8.8 源码](https://github.com/oleg-st/ZstdSharp/tree/2cd0c019693bc786a5fe5c3be94e107b24e7267e)。实验 ZIP、原始基线、完整日志和可回查图片保存在项目 .tmp；交付证据随源码提交。
