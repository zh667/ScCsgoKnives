# 0.38.1：枪械事务回滚与未知格式保护

日期：2026-09-08。基线：52556ec / 0.38.0。Windows 本机实施。

## 范围与格式

只修复审查的事务回滚和未知格式保护，并按用户要求更新 Git 协作规则。物品布局仍为 v5，记录 schema 仍为 2，型号/实例 ID/皮肤 ID 含义不变，不新增迁移，不要求正常 0.37.x/0.38.0 世界重建，不重复补满耐久。0.28.2 专用备份迁移入口继续保留，schema 1 读入仍只给皮肤默认值 0。

## 记录回滚

已有记录在修改前复制完整状态；发生异常时先原地恢复型号、弹量、消音器、耐久、最大耐久、充能、皮肤、修订号及 Holder，再执行库存逆操作。这样退款回调也只能观察到恢复后的记录。事务的 Id 和 Expected 同时恢复。新登记/复制记录失败仍标记 abandoned，并保留 ID 水位，避免复用已发出的 ID。

审查措辞修正：原实现确实缺少记录撤销，但记录写入后没有普通库存回调；`ScInventoryTransaction.Changed` 只是更新内部弱引用表的修订号。不能把它描述为已复现的常规游戏扣料漏洞。本版用仅测试设置的实例级 `AfterRecordWrite` 故障点验证异常分支，正常游戏不设置此回调。

## 未知格式

- `Classify` 明确区分 Legacy（布局 4）与 Unknown（其他未知非零布局）。无戳历史推断保持原规则，显式布局 0 不被当成无戳。
- XML 加载钩子在 0.28.2 迁移之前验证布局和 schema，只接受显式布局 4/5、记录 schema 1/2。未知格式不进入迁移。
- API 会吞掉钩子异常，所以钩子在内存 XML 写临时错误字段，真实子系统 Load 在 base.Load 之前检查并抛出异常，阻止完成世界加载。磁盘原存档不由此流程写入。
- 子系统 Load 也独立检查格式，即使绕过 XML 钩子仍拒绝。记录/补偿结构不支持时，不把注册表发布为当前世界。
- 保存入口先检查加载完成标志、源布局和注册表状态，再调用 base.Save 和任何 SetValue。加载失败、未知布局/记录表的保存请求直接失败，输出字典的布局和数据不改写。
- 已知旧布局 4 继续保存为 4；未知布局 6 不再被改成 4。schema 99 不会被重写成 2。底层 registry 的未知子树保留机制继续用于诊断，但正常世界不能靠停用枪械继续运行并自动保存。

## 验证

新增 `gun-format/*` 回归覆盖：未知布局/未知 schema；XML 临时错误与原字段保持；绕过钩子的真实 Load 拒绝；Load 失败后的真实 Save 拒绝且输出不变；强行置为加载完成时的保存防御；布局 4 两轮实际子系统保存和 XML 重读；schema 1 状态两轮子系统保存和 XML 重读；已有记录写入后故障及退款观察；新登记/复制发布后故障及 abandoned 水位。

检查使用安装包内 DLL 和本机 SCAPI 1.9.2.1 的 Content.zip。最终 PackageCheck **6250/6250** 通过，新增 **15** 项故障/存读档回归全部通过；Full/Lite 均为 746 条目且 DLL 一致，Lite 派生 210 张 512px 贴图。检查结果和包哈希见 `output/guard-final-check.json` 和各包 `.resources.json`（构建产物不提交 Git）。

边界：无头检查包含实际子系统方法和 XML 序列化，不等于完整游戏启动/手机 UI/引擎写盘故障实测。不可承诺此前已发出的 DLL 有同等未来格式保护。0.38.0 九款皮肤配色近似等资源限制均未由本修复改变。

## Git 交接

AGENTS.md 与 CLAUDE.md 改为独立工作区、Git 交接；开工前检查状态，干净时 `git pull --ff-only origin main`，完成后验证、提交、推送，再由另一端拉取。旧 reset 同步脚本改为仅报错退出。`git restore`/`reset --mixed` 不再用于日常同步。本次文档和脚本修改没有自动停止 Syncthing 服务；两端应让活动仓库退出文件同步，外部资源另行传输。用户原有未提交皮肤规划文档不纳入本次提交。
