# Android 设置与背景渲染修正 0.41.3

## 对之前判断的更正

用户的新日志 `D:/下载/Game(1) (1).log` 中，17:18 新会话加载 0.41.2，17:18:20、17:19:51
保存失败内容已经变成 `ScCsgoUi.json.<GUID>.tmp`，可确认上一轮补丁仍失败，不能归因于用户没有换包。
同一会话还出现 Gunplay 和 Tuning 文件失败。之前“只有重复按钮”和“换 Storage API 就能写”的结论不充分。

Engine.Storage Android 分支明确：app: 交给 APK AssetManager；GetSystemPath(app:) 拒绝，
OpenFile(app:, Create) 也不会获得普通可写文件。临时文件名错误不是已证实的 rename 失败，
不能用直接覆盖回退掩盖它。已撤销之前的 Storage.MoveFile（先删除目标）及本轮早期未交付的直接覆盖尝试。

## 修正

- ScLocalSettings：Android 使用 ModsManager.DocPath，即原版 Settings.xml 所在目录；
  Windows 仍使用原 app:/ 文件，保持既有设置。UI/手感/调参/截图诊断统一路由。
- 不读取或复制 APK 里的虚假“旧设置”；正确目标已有文件则正常读取。UI 不识别的文件版本仍保留并禁止覆盖。
- UI 保存：解析正确文件系统路径，同目录临时文件→Flush(true)→逐字节校验→覆盖式 rename；
  不预先删除原配置，不直接截断原配置，不做不安全回退。既有注入失败保留旧文件测试继续运行。
- Gunplay 首次创建文件失败仍保持默认 survival 参数；已有配置损坏的保护行为保持。
- 背景绘制：独立 DrawContext、独立清空的 RenderTarget，不复用外层 UI 批次；
  退出嵌套 ViewWidget 时通过 finally 恢复 RenderTarget、Viewport、ScissorRectangle。
  渲染目标尺寸随窗口变化重建，使用原游戏相机但不 Update 游戏。截图中的重复文字/平铺枪体不能仅用两套按钮解释。
- 两个页面 Enter 都立即隐藏现有实时触控按钮，取消手指捕获；不等待已暂停游戏的下一次 Update。
  是否处于菜单从 CurrentScreen 推导，不再留下需要手工清零的全局开关。
  退出世界清理注册的触控面板，避免持有旧世界 UI。
- 设置页固定标题、滚动区域、底部按钮及状态文字；按钮宽度适配窄屏。
- 新版本号 0.41.3，不再覆盖旧 0.41.2 同名包。CS_UI_0413 日志标记包括进入页面、配置目标、保存成功/失败完整异常。
