# 0.40.7 — 返回循环、计数器规则说明与伤害提升

## 返回导航

API 的 Help 使用 ScreensManager.GoBack（历史栈），Recipaedia 则使用自己记住的 m_previousScreen。我们的属性/配方页直接跳回最初入口，没有把中间页面从栈弹出；SwitchScreen 只在目的地恰好位于栈顶时弹出，否则反而压入当前页。于是目录→帮助→返回会再次落入旧目录/属性页面。

另一个问题是 Recipaedia.Enter 根据 `m_screens["RecipaediaRecipes"]` 的对象引用判断是否从子页返回；属性与配方之间来回替换实例可能让它把子页误记为外层入口。

本轮返回前将栈退到保存的入口，再用原生 SwitchScreen 弹出该入口；回目录时将实际离开的自定义页登记为当前 recipe 实例，让原生 Enter 保留正确外层返回目标。未改动无关菜单。

回归使用真正的 SwitchScreen、过渡动画、原版 Recipaedia.Enter/Update；帮助页返回逻辑使用与原版相同的 GoBack。连续四轮 Game→Help→Recipaedia→属性→配方→属性→Back→Back→Back，都回到 Game 且栈为空；另外测试装配台直接 Game→属性→配方→Back。模拟 recipe 实例已被替换，确认不会污染 catalogue 的 m_previousScreen。

## 伤害（两种游戏模式共用）

`伤害 = 原厂 Lv0 基础伤害 × 涂装倍率 × (1 + 0.1 × 已应用等级)`。

- 原厂倍率 1；属于该枪、当前支持的非原厂皮肤倍率 1.5。
- Lv0→Lv10，每级线性增加该基准的 10%，满级 +100%。不按上一级结果叠乘。
- 原厂满级为原厂 Lv0 的 2 倍；皮肤满级为原厂 Lv0 的 3 倍。换另一款皮肤不再次叠加；去皮只移除 1.5 倍。
- 普通伤害和爆头、霰弹逐颗伤害都从 EffectiveGunStats 的同一 Power 推导，属性预览和实战一致。
- AK：15→30；皮肤 AK：22.5→45。AWP：57→114；皮肤 AWP：85.5→171。电击枪无新增皮肤，150→300。
- 等级仍 10，每级 100 杀。弹匣/耐久 +50%、电击枪充能 10→5 秒、射程/后坐力/散布与其他规则均不变。

这是派生战斗数值变更，不把计算后的伤害写进存档；旧实例立即按已有皮肤和已应用等级使用新伤害，不重新分配 ID、不清零、不改已有弹量/耐久/充能。物品布局 5、记录 schema 3、成长持久状态转换版本 1 不变，因为没有新增持久字段或改变耐久/容量转换公式；不触发新格式迁移。

## 计数器与操作顺序

- 等级选择器附近和成长说明明确显示：**安装计数器后才解锁等级机制；从安装时开始计数，安装前的击杀不计入**。只预览不会安装计数器，也不应用等级。
- 不装计数器的皮肤枪可以有 50% 的皮肤基础伤害加成，但等级固定 Lv0；这不意味着获得历史击杀或等级。
- 先计数器后皮肤、先皮肤后计数器都可用。安装计数器从 0 杀 Lv0 开始；已经安装则拒绝重复安装，不能借此重置。
- 换肤、换另一皮肤、去皮、维修、箱子转移、丢弃交接遵循原实例规则，保留已有计数器、击杀数、已应用等级与待应用等级。真正复制出来的另一把仍使用已有复制隔离规则，不继承原枪击杀/等级。
- 换肤报价过期（例如等待确认期间新击杀改变记录修订号）时拒绝旧报价，重新报价，不覆盖新击杀。
- 装配台换肤确认文案同步说明伤害提升与状态保留，不再写“只改外观”。
- 明确选择“仅计数”的世界仍不提供等级成长；该已有选择未被覆盖。
