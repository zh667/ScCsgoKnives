# 0.37.1：武器台掉落与水面前枪口火焰

日期：2026-09-08（Asia/Shanghai）。基线 `cf39f60 / 0.37.0`。用户本次明确反馈并授权处理这两个具体 bug，属于原 M4-only 暂停范围的窄例外，不恢复其他批次。

## 武器装配台挖掘不掉落

根因：`ScWeaponWorkbenchBlock` 直接继承自定义 Block 基类，未设置 `DefaultDropContent`，也未重写 `GetDropValues`。本机 API 的 `Block.DefaultDropContent` 默认是 0，原版掉落函数因此不生成任何物品。默认工具要求为 0，不是工具不够高级或创造/生存耐久导致。

修复：重写装配台掉落入口，在满足工具等级时生成一个 `Terrain.MakeBlockValue(BlockIndex)`。使用当前世界运行时分配的方块编号，不在构造阶段写死编号；不携带地形光照位。保留原版工具要求、碎屑开关和 `DestroyCell` 的 noDrop 控制，不强行让创造模式拆除也出掉落。

回归通过引擎真实 `GetDropValues` 调用检查徒手级别 0、工具等级 1/3，掉落恰好一个装配台，并经过拾取库存 Save/Load。新检查运行在旧 0.37.0 Lite 包上，三条全部失败，其余检查通过，复现了本次报告。

## 枪口火焰在水面前异常

用户两张对比图：P90 朝水面时只有暗淡蓝灰色残影，朝不透明山体时可见橙色火焰。截图本身没有相同开火时间点，不能据此精确测量亮度差；代码和本机引擎则确认存在以下绘制顺序问题。

| 原版绘制阶段 | 顺序 |
| --- | --- |
| 不透明地形/裁切地形 | 0 |
| 第一人称武器模型及原枪口粒子入口 | 1 |
| 天空 | 5 |
| 透明地形/水面 | 100 |
| 原版粒子 | 300 |
| 本模组世界烟火 | 310 |
| 本模组枪械特效与反馈 | 350 |

枪体写入第一人称深度，水面无法把枪体覆盖。火焰采用加法混合，余烟采用非预乘透明混合，两者只读深度，不写深度；画在水面之前，便会被后画水面覆盖/稀释。给火焰改颜色或提高亮度无法修正顺序，给整张透明贴片写深度则会错误挡住后面的水和天空。

修复：早期第一人称阶段只暂存本相机、本帧的姿态、投影、视口及深度范围；在现有 350 号阶段绘制枪口火焰和余烟，电击枪枪口粒子同样延后。枪体和真实 CS2 手臂仍按原路径绘制，贴图、亮度与开火时长不变。

晚画时沿用早期捕获的视口（原版把 MaxDepth 压到原值的 0.1 倍），因此普通枪口粒子的 DepthRead 仍与枪体深度一致；不通过关闭深度测试让火焰无条件穿过枪身。电击枪原有的无深度测试行为保持。绘制结束恢复视口、混合、深度和光栅状态。记录按相机隔离，仅当帧消费一次，过期丢弃，退出世界清理；开镜不画枪、切第三人称等不能复用上一帧粒子。

新增运行时回归覆盖不同相机不会互取、同帧仅消费一次、过期丢弃、保存的投影/深度范围与枪型保持对应。离线检查不创建 GPU 上下文，不宣称这些检查已经验证实际水面像素。
