# 0.40.4 — 计数器流转修复与公开版 0.28.2 迁移验收

## 本轮范围

用户明确：主要保证正常玩家从唯一公开版 0.28.2 升级到最新版；不扩展 0.35.x 内部测试存档的兼容。保留原有 schema 1/2 → 3 转换、完整备份、未来格式保护。物品布局仍为 v5，记录 schema 仍为 3，无新格式迁移。

## 计数器问题与修复

1. 创造模式：原实现的 `ScGunKillCredit.For` 和 `ScGunKillRules.Counts` 两处都排除了 creative。改为与生存模式一样接受有效枪械击杀。仍排除无计数器、自杀、玩家目标、有人骑乘的坐骑和明确测试目标；同一死亡只记一次。成长仍取决于世界计数/成长规则，不增加独立 XP。历史创造击杀没有凭据，不倒算或猜补。
2. 箱子取放：日志 12:12:09 / 12:12:11 分别将记录 9 → 12、10 → 13。原物品一处在创造背包 8/9 格，另一处在 Stash 箱子 65/67 格。API 同时保存普通/创造背包，`ComponentMiner.Load` 按模式只启用其一；旧扫描把休眠背包也当成第二个实时持有者。现在扫描排除玩家未启用的普通/创造背包，不排除可访问的 Stash、箱子、合成栏、掉落物等。正常取放不再因此错误拆分 ID/清零成长。
3. 真正复制：继续分配独立 ID，清零复制品击杀和等级，保留弹量守恒与耐久比例规则；计数器模块属于装备，不再一并拆除。
4. 名称：实例 `GetDisplayName` 现在包含皮肤及“击杀计数器”后缀，不只目录模板有标识。通过真实 ComponentChest 来回转移测试。
5. 已被旧版清除的记录不会仅凭型号/皮肤猜测补回。World32 中记录 12/13 的 `ct=0` 已写入；没有保存在记录中的复制来源，自动给所有同款普通枪安装计数器不安全。本轮不改真实存档；这类已有损失需可信备份或用户明确授权的定点恢复。

## 0.28.2 → 最新版

没有放宽迁移器对混合数据的识别，也没有将缺 Schema 的记录表强行当作合法版本。本轮新增 `Published0282Regression`：

- **直接从实际发布包 DLL 调用旧版 GunSpec.MakeData**，不是让新迁移器自己生成期待数据。
- 35 枪、每种合法弹量（0 至该枪容量）、消音器两状态，共 **1960 种状态**；逐枪迁移后进行两轮 XML/注册表存读，核查型号、弹量、消音器和首次满耐久，确认迁移不重复执行。
- 对真实未改写的 0.28.2 世界备份，只读 ZIP 内 Project.xml，在内存中迁移 **6 把枪**，再两轮 XML/注册表存读。备份原文件迁移测试前后哈希一致。
- 现有跨容器（生存/创造库存、Stash、掉落物、投射物、移动方块）、备份失败、容量预检、未知/混合来源拒绝、原文件保持不变等检查继续运行。

源码/证据：发布源码 `a95a0ef` 的 `Rendering/GunSpec.cs`；本机发布包 `output/ScCsgoKnives-0.28.2.scmod` SHA256 `86961b36607b0e39919507a107551c41bfaff0da84ecb0e152e1883e5f7534d3`；真实源备份 `World31/ScCsgoKnives-before-0282-20260907-183455-4b6d1349.snapshot` SHA256 `d820cccc25c2fff99012030afdcd5f986b59c72d06a12515ce46afad3539a8d1`。

这验证正常公开版数据的迁移，不承诺所有来源不明或曾回退覆盖的测试档都能自动修复。真实原世界未被执行升级或保存。

## 本次粘贴报错分类

- World23 / World30 版本字段为 0.28.2，但保存了无新版标记的 data=834、95 等值。这些并非发布版当前 MakeData 正常写出的值；按旧版兼容读取，95 会读成沙鹰 23 发（正常容量 7），834 也超出允许的旧格式位范围。混用/回退/异常写入的来源不能仅凭版本标签排除；保留拒绝，不猜枪型和弹量。
- `GunRegistry.Schema=0` 是缺 Schema 时采用的诊断默认值，不是一个受支持的“schema 0”。本机 TianjinCentre/World28/World29 的保存版本为 0.35.2，其中记录表确实没有 Schema。按本轮范围不增加其迁移；错误信息改为明确“缺少 Schema”，去掉重复套用的错误前缀。
- 日志中 World31 的 schema 1 → 3 已完成备份和升级，World32 的 schema 2 → 3 也正常加载。这与未改写 0.28.2 备份的迁移检查一起说明，正常受支持链并未被统一拦截。
