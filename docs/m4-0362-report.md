# M4 · 0.36.2：接手修复五项审查问题

日期：2026-09-08。基线 `489b632 / 0.36.1`。用户授权接手五项修复，验证通过后本机打包。仅 M4 ACTIVE，其他批次继续 BLOCKED（2026-09-08 00:22:15 +08:00）。不迁移旧世界，不回收 ID。

## 改动

1. **换弹异常丢枪/弹药**：`ScGunMutation` 不再调用不透明的 `ReplaceWithCost`。材料、弹药、枪的删除与添加都通过 `ScGunInventoryJournal`，在 `finally` 中以槽位前后实际数量记录反向操作，覆盖修改前抛异常和修改后抛异常。已有 ID 的枪原位更新记录，不再每发删除/添加整把枪。
2. **部分回滚重复退款**：归还按实际到账数减余额；原槽只收到一部分时，其他槽只接收剩余量。添加后抛异常仍核算到账数，不重退整份。失败替换的新枪须先撤回，再归还原枪，防止同时存在原枪与失败副本。
3. **同帧复制漏检**：删除按帧缓存。每个已登记枪的提交执行新的引擎持有者扫描，覆盖同帧普通库存复制/转移；扫描继续包括已加载实体/子系统库存、掉落物、投射物、移动方块。尚未交付的枪械补偿也计为持有者。
4. **补偿丢失**：取消静态 `PendingRestore`。补偿按世界存入 `GunRegistry/Recovery`，有 schema、单调编号、稳定归还目标、顺序操作和剩余数量。读取后每秒尝试归还；目标缺席、容器未加载或拒收时保留。玩家目标使用 PlayerIndex；普通实体库存使用引擎保存的 Entity.Id、组件索引及类型；子系统库存使用索引及类型。不存运行时对象引用。补偿完成移出待处理队列，下次保存不再重发；部分进度也保存。未知/损坏补偿格式保留原始注册表并停用，避免猜测发物品。
5. **哈希身份碰撞**：运行时容器身份使用 `ConditionalWeakTable` 分配的递增编号＋槽位，不用 RuntimeHelpers.GetHashCode 的数值做唯一键。

补充安全措施：事务绑定 Prepare 时的注册表，世界切换后拒绝提交；新实例发布在库存步骤全部确认后执行；保留全局提交/补偿重入保护。材料与弹药同值时合并预检。事务或补偿运行中禁止取枪表保存快照，避免保存一半库存、一半记录；普通帧结束后可正常保存。未完成补偿的库存暂拒绝新枪事务，玩家仍可整理物品腾出空间。
