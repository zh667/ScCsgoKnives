## 二、三处更正（请先看这一节）

### 2.1 我的说法撤回：`Drawable already added` 不是曳光重复增亮

你们反编译的结论我接受：`SubsystemDrawing.AddDrawable` 用 `Dictionary.TryAdd`，
重复项记日志后返回，`Draw` 只遍历一次。我当时是从"如果重复注册"的假设推的，没有验证实现。
上一轮审查文档顶部已加更正声明。

**本次没有改这段代码**，理由：mod 里**只有一处** `AddDrawable`
（`SubsystemScGunBlockBehavior.cs` 的 `Load()`），没有手工重复注册可删。
那行日志说明引擎侧已先收录了这个 `IDrawable`。盲删有风险——若引擎并不自动收集，
开镜遮罩和曳光会整个不画。

**要清日志的话，这是一个 Windows 侧实验**：删掉那一行显式注册，构建，确认 AWP 开镜
遮罩仍然绘制、曳光仍然出现。确认后我再把改动固化。

### 2.2 你们的说法要修正：`Weapon_M4A1.AddAmmo` 有源音频

它不是"无 WAV 所以无源"，是**整个 m4a1 目录只解码出 `.mp3`**：

```
Weapon_M4A1.AddAmmo   decoded = m4a1_addammo_01.mp3      <- 存在
Weapon_M4A1.Clipin    decoded = m4a1_clipin.mp3          <- 同样
Weapon_M4A1.Clipout   decoded = m4a1_clipout.mp3         <- 同样
```

我的 `tools/cs2_sound_timings.py` 只过滤 `.wav`，所以把它报成无源。

**结论：34 条 cue 全部补齐，覆盖率 69/69，不需要任何书面豁免。**
你们那条"不能一边标独立 FAIL 一边放到发布后"的意见成立，现在这个矛盾消失了。

### 2.3 你们指出的机制正确，但举的例子不成立（我在实施中实测发现）

`pose.Time` 被 CS:MC 时长截断后又拿去采 CS2 rig —— **这个机制判断完全正确**。

但 M4 inspect 并没有冻结：`GetDuration` 返回的是 CS:MC json 的 **`Duration` 字段**（5.3），
不是它 `Times` 数组的末值（5.0）。151 vs 160 是**曲线采样**被截断，不是 `Duration` 被截断。
所以控制器本来就跑到 5.3，`Cs2Rig.Sample` 再夹到 5.2999。

实测真正受影响的是四条（`ArmPreview durations` 的输出）：

| 枪 | clip | CS:MC | CS2 | 差 | 症状 |
|---|---|---:|---:|---:|---|
| m4a1s | **deploy** | 1.1000 | **1.1332** | **+1 帧** | **CS2 拔枪的最后一帧被切掉** |
| ak47 | reload | 2.4667 | 2.4333 | −1 帧 | 动画先结束，状态机多跑 1 帧 |
| awp | shoot1 | 1.6667 | 1.5999 | −2 帧 | 动画先结束，状态机多跑 2 帧 |
| m4a1s | shootSilenced | 0.4000 | 0.3999 | ≈0 | 可忽略 |

**量级是 1–2 帧，不是 9 帧。修法不变、仍然必要**（两边必须用同一个时长来源），
只是收益要按实测说，不要按"M4 inspect 后 9 帧冻结"说。

## 三、你们八条要求的逐条落实

### 1. 拆分开关 —— 已完成

| 开关 | 管什么 | 默认 |
|---|---|---|
| `GunProfile` | CS2 网格、材质、动画、摆放、手臂、特效 | 0 |
| `GunNumbers` | CS2 伤害、衰减、散布、后坐 | **0** |
| `GunSoundProfile` | 独立 A/B：只换声音时间表 | 0 |

`Cs2Weapons.Active` 的判据由 `GunProfile` 改为 `GunNumbers`，
**视觉翻默认不再连带改玩法**（CS2 的 AWP 不开镜散布 4.63° 现在要单独 opt-in）。
声音条件不变：`GunProfile >= 0.5 || GunSoundProfile >= 0.5`。三个开关互不隐含。

### 2. CS2 动画时长 —— 已完成（默认翻转前）

新增单一仲裁者 `CsmcKnifeRig.GetProfileDuration(variant, clipAlias)`，
**控制器、`BusyUntil`、`Cs2Rig` 采样三处共用**。

`KnifeRigPose` 新增 `RequestedTime`（**未截断的控制器时间**）与 `Looping`；
`DrawCs2` 用它们按 **CS2 clip 自身长度**重新算采样时刻（循环取模、非循环截断），
不再拿被 CS:MC 截断过的 `pose.Time`。

替换的 6 个调用点：控制器 3 处（clip 结束判据、`IsAttaching`、`IsBusy`），
枪行为 3 处（deploy / reload / 消音器装拆的 `BusyUntil`）。
**未替换** `MeasureHolds`（刀专用离线测量，在 `IsGun` 提前返回之后）。

**刀与 `GunProfile = 0` 不得改变** —— 已断言：`cs2_placement_selftest.py` 新增
23 组 枪/刀 × clip 检查，**0 处问题**：

- `GunProfile = 0`：所有条目与 `GetDuration` 逐位相同
- 刀（m9、karambit）：`GunProfile = 1` 与 `= 0` 逐位相同
- 枪 `GunProfile = 1`：取 CS2 时长，重新计时的就是 §2.3 那四条

副作用（已记录、可接受）：`GunProfile = 1` 时 CS:MC 那份姿态在自己的时长处冻结——
cs2 路径只从它取 `ClipAlias` / `RequestedTime` / `Looping`，姿态本身不画。
CS2 的 idle 时长是 0（单帧静态），所以 cs2 profile 下待机完全静止，这是 CS2 的真实行为
（待机摇摆来自程序化的 viewmodel lag/bob，SC 侧由机体运动承担）。

### 4. 数值验收改无损静态 PNG + 先做截图探针 —— 已完成

**你们的探针结果已写死进 checker**（原生 1400×1050、4:3、RGBA 无损、alpha 全不透明、
sRGB gamma 0.45455、无需反变换）：

```

```

### 5. checker 必须 manifest 驱动 —— 已完成

`tools/cs2_reference_check.py`，六个独立项，**没有总 PASS 字段**：

| 项 | 规则 |
|---|---|
| INPUT | 尺寸/变换/gamma/alpha/色彩模式/哈希/cvar/mask 与 manifest 一致；**任一缺失即 FAIL** |
| PLACE | 预测出自 `ArmPreview cs2`（出厂 C#）；**offset 固定为读回值，禁止拟合**；每个武器地标 < 10 px |
| PHOTO | 命名为"**固定场景下三枪相对光度一致性**"；一枪拟合唯一全局倍率，另两枪验证：均值 < 5%、形状比 < 10% |
| HAND | 只在**握持/接触 ROI** 内比左手：IoU ≥ 0.85、质心 < 10 px、三个边地标 < 10 px |
| HAND-R | **只报告，不 gate** |
| SOUND | 已打包 cue 覆盖率；触发时间记 source-verified |

`--fit-fov` 只打印诊断，不进任何判定。缺输入一律 FAIL，不静默跳过。

握持 ROI 定义：左手 mask 与武器 mask 各膨胀 12 px 后的交集，
并上左手 mask 与武器 mask 相邻 24 px 内的部分。

**删除** `tools/cs2_videocheck.py`（手填 `LANDMARKS` 表已被 manifest 取代）。
`tools/cs2_render_check.py` 保留为开发工具，但背景猜测已删——
`tools/pbr_emulate.py` 现在输出真实覆盖掩码，它读掩码。

### 6. 手部像素验收前必须确定 team/agent/loadout —— 已加硬门槛，但结论要你们出

**导出件能证明的**：12 套 `glove_*` 全部用 `bare_arm_133` 当手臂材质；

**可测量的判据**（替代猜测）——`bare_arm_133` 底色统计（1024×2048，仅不透明纹素）：

## 五、请 Windows 侧做的（按顺序）

### 第 1 步：确定 agent / loadout（HAND 项在此之前不会 PASS）

同一位置、同一 cvar，用 2–3 个候选 loadout 各拍一张 idle PNG，
例如 T 默认 agent 无手套皮肤、CT 默认 agent 无手套皮肤。

```
python3 tools/cs2_capture_probe.py <shot>.png --render 1400x1050 --arm-tone X0,Y0,X1,Y1
```

`X0,Y0,X1,Y1` 取一块**裸露小臂**（避开手套、避开武器）。工具会打出该区域的
R/G、G/B 以及与 `bare_arm_133` 的差。

- 各 loadout 一致 → 手臂与 agent 无关，任选其一记录；
- 不一致 → 取色比最接近的那个。

把 team / agent / gloves 三项写进 manifest，并置 `arms_verified: true`。

### 第 2 步：生成 manifest 骨架

```
python3 tools/cs2_reference_check.py --manifest reference/cs2/2026-09-05/capture.json --template
```

会写出一份已经填好 `comparison_size` / `capture_transform` / gamma / 你的 cvar 的起始文件，
并列出需要的五张静帧：

```
ak47_idle   m4a1s_idle   m4a1s_idle_silenced   awp_idle   awp_idle_scoped
```

把所有 `REPLACE` 填掉（CS2 build、setpos/setang、team/agent/gloves、
`weapon_recoil_scale`、各文件 SHA-256）。

### 第 3 步：采集

**必须是出厂皮**（无皮肤 / 无贴纸 / 无 StatTrak），**卸下手套皮肤**。
固定 `setpos_exact` / `setang_exact`，光照均匀处。
每张用 `Win+Alt+PrintScreen` 出无损 PNG。

另外三段 MP4 只做人眼 QA（漏声 / 错声 / 重复播放 / 动画跳变 / 火光曳光观感），
不参与任何数字判定。

### 第 4 步：mask 与 landmarks

每张静帧配两张同尺寸 8-bit PNG mask：`masks/<shot>_weapon.png`、
`masks/<shot>_lefthand.png`（非零 = 目标区域）。**没有 mask 就 FAIL，工具不会猜背景。**

`landmarks/<shot>.json`：

```json
{ "weapon":    { "muzzle": [x, y], "trigger": [x, y], "clip": [x, y], "bolt": [x, y] },
  "left_hand": { "index_knuckle_over_top": [x, y],
                 "thumb_edge_on_receiver": [x, y],
                 "cuff_crosses_frame_edge": [x, y] } }
```

手部**不要点指尖**：trigger 深度处 10 px 只有 3.34 mm，比指甲还细。
上面三个都是高对比的**边**，不是团块。

### 第 5 步：跑验收

```
python3 tools/cs2_reference_check.py --manifest reference/cs2/2026-09-05/capture.json
```

产出 `cs2-reference-report.json` / `.md`，每项独立 PASS/FAIL。
`--fit-fov` 可加，只出诊断。

### 可选、不阻塞：AK 弹着图

用来把后坐绝对尺度从估计变成实测。补记 `weapon_recoil_scale` 和游戏 FOV 即可；
**不需要墙面距离**——视角还原后弹孔的屏幕位置就是射击角度。
