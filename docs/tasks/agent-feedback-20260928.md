### 2.1 同伴数据丢失：优先级最高

入口是 ComponentTacticalCompanion.Load/Save、TacticalModLoader.OnSaveSpawnData/OnReadSpawnData、SubsystemTacticalEnemies.SaveSpawn/ReadSpawn，以及 ScTactical.xdb。

同伴设置Creature.ConstantSpawn=true不代表禁止卸载。原生SubsystemSpawn.DespawnChunks检查ComponentSpawn.AutoDespawn和相机距离，本地API源码默认半径60、约每2秒检查。第三方运行时可能调整阈值。卸载只自带模板、位置、ConstantSpawn、EntityId和Data，不自动保存全体组件；SpawnEntity从模板重新创建，再调用读钩子。

安装DLL离线结果：正常组件Save保存OwnerIndex=0，普通库存Save有Slots；但卸载Data为空，经过原生字符串序列化/重读仍为空，得到 ScTacticalT,80,64,0,True,,321;。新组件默认OwnerIndex=-1。OwnedBy仅比较玩家索引，失败统一提示“这是其他玩家的同伴”。这解释了无主数据被误报成别人的同伴；不是已证明发生真实所有权转移。CT与T共用该路径，都要修。

不能给-1自动认主、按型号重造一把枪、填满空弹药，或者从残留枪表随便匹配主人。已丢失状态只能从可信旧档恢复。普通Save回归不覆盖远距卸载，是现有检查的缺口。

### 2.2 台阶和AI：能力存在，控制不足

原生继承解析确认同伴/敌人WalkSpeed=4.5、JumpSpeed=5、MaxSmoothRiseHeight=0.51。半砖应具备平滑抬升条件；一格台阶仍需导航主动跳跃和可落地空间。

- 同伴SetDestination传入250,false,true,true：关闭随机移动、忽略高度差。进入水平Follow半径1.8且垂直差不超过1.5即StopMoving，主人仅高一格时存在提前停止的明确条件。
- path.IsStuck后停止并等2秒，没有根据障碍区分跳跃、绕行、重选目标或不可达提示。
- 敌人约0.65秒再次SetDestination，还直接写body.Rotation；可能和Pilot转向/状态机竞争，需日志确认，不能因此认定所有台阶故障都是它造成。
- 同伴Visible未检查SmokeBlocksSight，敌人检查了；移动阶段的交战资格和Shoot入口也应统一。
- “掩护”目前只是走到主人前方2.5格，不是选遮蔽点。没有队形、协作射界或危险区域代价。

最小地形对照：平地、0.5半砖、各朝向楼梯、1格台阶、连续台阶、2格不可越墙、矮屋顶、窄门、斜坡、积雪、移动方块、水边。分别验证CT/T、持枪/盾、跟随/守卫/掩护、敌人追击。记录目标、路径状态、碰撞盒、实际位移、StandingOnValue、JumpOrder、转向来源。禁止把每帧跳或瞬移当通用修复。

### 2.3 语音和动画

安装包现有204条语音，CT/T×中英各51条，17类语义含投掷、确认、感谢、跟随等。ScAgentVoice.Emit已有可选事件接口。AgentVoice.Receive现在由NpcEnabled控制，排队项只分Manual；直接接玩家投掷会让玩家自动语音错误受NPC开关控制，需先区分来源。

玩家投掷事件应在SubsystemScGrenades事务Commit成功、Released=true后发出；取消准备、物品移动、活动数量满时不能喊“投雷”。同伴交互应在面板成功打开一次、指令确实变化、装备事务成功时触发，不能每帧刷新或按住E刷语音。当前指令回应受PanelOpen提前return影响，可延迟到关闭面板，宜从确认指令事件触发。

ComponentCsPlayerAppearance.INeoModel.Animate只向CsPlayerPose.Sample传水平速度、持枪、盾、蹲、躺。包内ScTactical.json与源码字节一致，只有idle/walk/run/aim/aimwalk/shield/shieldwalk；无起跳、空中、落地。NPC原生控制器虽有IsOnGround，配置也没消费。ScAgentActions以spine_0上半身掩码覆盖武器动作，新增腿部空中状态要保留分层。

ComponentTacticalModel.Animate死亡时冻结最后姿势、少量弯脊椎/手臂、根节点旋转90度，没有腿部约束和地形碰撞；CorpseDuration=3秒也缩短表现窗口。当前不是布娃娃，不能通过多加几个随机弯骨就声称移植了CS2物理。

### 2.4 友伤、下包、拆弹

SubsystemScGrenades.Friendly的true实际表示允许效果；目标无ComponentPlayer就直接true，敌方Owner=-2也放行。安装DLL探针确认玩家区域伤害对同伴放行，即使世界玩家友伤关闭。引擎默认友伤保护主要是玩家打玩家，不会自动保护同伴。火区每秒攻击力预算6，AreaAttack走AttackResilience，改FireResilience不能替代阵营保护。

阵营不能按CT/T外观判断：招募T是友军，敌队T才是敌人。Owner=-2只有敌方类别，没有Squad身份；主人离线后也要能识别留在地上的火区来源。

敌方C4为40秒、Power250、Radius12；玩家C4默认20秒、Power5000、Radius32，且玩家可设计时。统一拆弹入口不应统一重写它们的爆炸参数或保存集合。避险必须读取具体炸弹参数。下包者只退6秒后就恢复通常战斗，其余人没有撤离状态，不能保证最后40秒爆炸时仍安全。

创造目录槽GetSlotCount在探针中为536870911，代表无限来源；HasKit仅前10槽所以返回false，放槽0后true。这不是资源没注册。自己放的包不能拆则是两个子系统集合没有共同交互入口。

## 4. 实施顺序和具体方案

### P0：同伴生命周期守恒，独立第一批

1. 先将安装DLL卸载Data为空做成失败用例，不能只增加普通Save测试。
2. 推荐完整同伴休眠载荷：版本、稳定同伴身份、OwnerIndex、命令、守卫位置、停火、死亡/掉落终态、健康、朝向、精确5槽物品value/count及未完成义务。普通枪引用原GunRegistry，不Allocate/Clone、不按型号新建。活动换弹在卸载前安全取消或保存事务义务，不能吞/复制弹。
3. 接入OnSaveSpawnData、OnReadSpawnData及淡出期间OnEntityRemoved最终刷新；覆盖淡出期间取放、受伤、死亡。使用自有命名空间编码，保留其他mod的Data片段，避开原生字符串分隔符。
4. 先验证完整载荷，再应用。引擎SpawnEntity捕获异常后，SpawnChunks仍可能清空SpawnsData；仅throw不等于原文保留。设计持久待恢复账本或进入前拦截，明确失败重试与去重路径；不补丁第三方/引擎二进制。
5. 休眠枪引用也要纳入holder、完整性、恢复扫描；活动实体和休眠副本不能被误认为两位持有者而分裂枪/丢成长。EntityId与RecoveryOwner关联保持一致。
6. 紧急保守备选是仅招募同伴禁止AutoDespawn、保留正常实体保存、远处暂停AI；但必须测大量同伴、地形卸载下落和内存成本。不能把无限永久活动实体当最终方案，也不能用禁卸载代替完整验收。
7. 区分“主人信息缺失，待恢复”和“其他玩家的同伴”。不自动认领Owner=-1；主人死亡、暂时离线、再次上线不改变归属。

验收：CT/T×枪/盾/弹药/空栏；三指令；跨卸载阈值再回来；休眠时保存退出重进两轮；淡出取放/死亡；损坏载荷、旧空载荷、恢复失败；第二玩家和主人离线。逐项核对枪ID、完整记录、身份、弹量、耐久、等级、精确槽位、掉落只一次。已丢装备无来源时明确不能恢复。

### P1：统一阵营、持续避险、生成公平性

建立核心可选接口供战术注册，识别玩家/所属同伴、敌方/Squad、中立实体；角色外观不决定阵营。分开判断敌对目标、伤害许可、闪光效果、区域归属。默认建议玩家对同伴、同伴对主人/同伴、敌队对同队区域友伤关闭，保留玩家自伤；明确友伤设置可开启，不取消原版其他环境伤害。

区域来源须持久化，不能仅保存Entity引用。旧Owner=-2只能按已有敌方类别保守处理，不假造Squad。新字段经过旧兼容包保存是否保留必须实测，必要时回移读写或放入已受保护载荷，不能认为追加字段就自然兼容。

危险优先级：死亡/失效 → 炸弹迫近/脚下火区 → 失明和必要动作中断 → 护主/战斗 → 跟随/巡逻。根据已知炸弹位置、剩余时间、具体半径及遮挡判断，不增加全图透视。下包后通知同队、远离落点建立防线；建议剩余12秒开始全面撤离，持续验证可达安全点，禁止普通追击又把人拉回爆炸区。下包者和其他队员都执行，路径失败换候选点，不只是等6秒。

火区成为导航高代价；站火时寻最短安全出口，安全后恢复原命令。即使同队友伤关闭，也不故意站己方火中。

手动敌队建议保留12格内指定方向的操作，搜索外围可达落点：每位玩家距每名敌人至少18格，目标区域约18–28格。找不到全队安全点整次失败、不扣信标。建议3秒准备提示，结束后再累计瞄准门槛；玩家先攻击可结束准备，但不能同帧无预警反杀。只保护新生成挑战队，不让现存全世界敌人暂停。自然生成30天门槛、全队创建原子性、全局生物预算保持各自职责。距离/秒数以测试调整并记录。

### P2：台阶、队形和有限战术智能

先建地形场景，再改条件。到达判定区分水平/高度可达，主人在另一楼层不能按水平半径完成；不无条件ignoreHeightDifference。跳跃前探测脚前碰撞、可站台面、头顶、落地空间：半阶走、可跳一阶跳、过高或无落点绕路。原生Pilot/Locomotion负责移动和转向，单一控制源；消除敌人每帧body.Rotation竞争。

卡住分阶段处理：无进展确认→局部替代点→重寻路→有限侧绕→不可达提示；有时间/次数上限。不每帧重启搜索，不自动破墙或传送，不在未加载地形寻路。

每名同伴有稳定队形偏移，盾牌/近战/步枪/狙击分别用距离带。目标资格统一检查活着、烟雾、可见性、主人范围及切换滞后，射击/移动共同使用。掩护候选需身体遮蔽、枪口可见、不会挡队友；使用少量局部候选，不无限射线。队友挡枪时暂缓并有限侧移，不通过墙壁开火。

先测5/10/20个活动探员，记录感知、寻路请求、控制、动画、绘制CPU和GC，错峰感知并重用缓冲。手机报告平均/P95/P99帧时间，不以Windows微测保证不卡，也不降资源质量换AI性能。

### P3：统一拆弹、创造语义和一次性奖励

统一可拆炸弹视图和取消/终态接口，不合并保存数组。接入玩家charges和敌方Bombs，保持Owner/Fuse/Power/Radius和旧键。拆弹优先于下包、伙伴交互、E开背包；允许拆自己的C4，他人C4遵循明确的世界权限。键鼠/触屏/手柄一致。

生存检查真实随身库存，复用已验证个人库存代理规范化；不能让远处同步箱的钳子算随身。创造建议明确“直接具备拆弹工具，5秒”，不扫描无限目录制造携带假象。当前版本临时办法是放快捷栏。生存有工具5秒/无工具10秒；中途模式变化、工具丢失取消后重新开始，避免进度套利。保留平局爆炸、松手/移动/墙挡/死亡/菜单取消规则。

建议首轮奖励：生存成功拆除敌方已武装C4，金属坯件2+精密机构1，一颗只结算一次。自己/他人放的包、创造来源挑战包、失败/取消不奖励。必须记录生成时来源，不能仅看拆弹时模式，否则创造生成再转生存可刷。多玩家只由完成者领取，按住键、同时抢拆、重进不重复。

增加稳定BombId、来源和结算凭据。已拆终态与待发收据作为同一保存状态，不能先删炸弹后直接GiveItems而无恢复手段。复用带持久收据的物品事务/恢复机制；满背包留待领取，若选择掉落也要有去重关联，不能读档再掉。旧无可信BombId/来源的包按无奖励兼容处理，不猜资格。新增字段和账本必须跨旧兼容保存不丢、不重复发放。

### P4：自动语音

区分PlayerManual、PlayerAutomatic、NpcAutomatic和设置；玩家自动语音建议独立开关。旧JSON不丢未知字段，新增默认值明确。六种投掷物只在事务成功后调用对应现有语义；伙伴互动用affirmative/thanks/followingfriend/waitinghere，不用不相关台词冒充拆弹专用句。

危险喊话优先于闲聊，玩家主动语音保留高优先级；延续全局最多2声、区域防叠、说话者冷却、同句防重、短队列过期。出生小队只选少量发言人。卸载/死亡/关闭设置清理Entity引用和排队，避免累积。中英CT/T声线、时间点、取消不说话需真实听音/录像，不以解码成功代替听感。

### P5：跳跃动画、CS2风格关节倒地

玩家和NPC共享落地、垂直速度、起跳沿/落地沿、空中时长；加入起跳、上升/空中、下降、落地过渡和腿部屈伸/髋部响应。上半身持枪/换弹/开火叠加保留；盾、蹲跳、空手单验。视觉姿态不得改真实Body位置，导入片段去除重复根位移；多相机不可推进多次。

通过Windows worker先盘点原始ct/t是否有可用jump/fall/land及骨骼一致性。当前七种动作不足；有原片段则带来源重定向，没有则制作适配姿态并说明。Full/Lite各自配套烘GLB+scanim，不从剥离marker GLB烘，不把资源树搬到VPS。

死亡分两阶段：先独立尸体姿态状态继承最后活姿、根速度和有限命中冲量，不跳bind pose、不重复击杀掉落；再引入骨盆/胸/头/上下臂/大小腿约10–13个受约束物理段，关节角限制、重力、地形接触，并重定向回原骨骼。地形碰撞是验收必需，整体转90度不算完成。

建议起始预算：最多6具近处活动尸体，30Hz固定步、每帧最多2子步、有界约束迭代，约6–8秒休眠/淡出，远处冻结。最终依据手机性能定值。活体命中/伤害状态独立；尸体原则上不挡导航、不生成可刷实体。覆盖爆炸、墙角、台阶、斜坡，避免穿透/抖动。死亡身份/掉落终态需持久化；尸体姿态是否保存明确，允许读档为静态尸体但不复活重掉装备。未达到验收前称改进倒地/简化布娃娃，不承诺CS2同款物理精度。
