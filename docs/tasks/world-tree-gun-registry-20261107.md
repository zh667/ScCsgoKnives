# 设计：一个主世界一本枪械记录本（world-tree-gun-registry-20261107）

状态：设计已确认（2026-11-07 用户：“需要我定的都按照你的建议来”），实现中
用户决定（2026-11-07）：“我们这个枪械，和那种有子世界的模组一起用，总是会出现 bug，有没有什么一劳永逸的方法” → 选择“根治这条路”。
相关：`docs/tasks/subworld-travel-generic-20261003.md`（现有逐个模组适配）、`World/ScGunRecordMirror.cs`（1.5.1 记录副本）、`docs/agent-guide/compatibility.md`。

## 1. 问题

枪的状态（弹量、耐久、皮肤、成长、计数器……）放不进物品值（只有 17 位），所以物品只带一个**编号**，状态存在**每个世界自己的**记录本（Project.xml 的 `ScGunBlockBehavior/GunRegistry`）里。同一个编号在主世界和子世界里指不同的枪。

子世界模组搬物品的方式各不相同，每种都要单独适配，新模组一来就出新 bug：

| 模组 | 子世界位置 | 怎么搬物品 | 已出过的问题 |
|---|---|---|---|
| 尸鬼 2.0.x | `主世界/Tartareosity` | 先存档，把玩家 XML 复制进目标 Project.xml，再加载 | 带着坏枪穿越 → 目标世界整个拒绝加载（2026-11-07 玩家截图） |
| 远古世界 0.41.x | `主世界/Dimensions/Ancient` | 加载完成后再把物品值塞回库存 | 新枪在子世界生成记录、带回撞号（2026-10-03） |
| 无缝传送门 xianyu.portal 1.5.0 | `主世界/Space_N`（`SpaceProject.xml`） | **两个世界同时运行**，穿门时直接把玩家实体移到另一个项目，不读档不存档 | 进 Space_0 时被重新编号，走回主世界后编号被当主世界的读，#1/#3 记录对调（玩家日志 10-31 23:08→23:41） |

另外，静态的 `ScGunRegistry.Current`（全代码 157 处引用）、`ScGunMutation.HolderLocator` 默认“同一时间只有一个世界”，传送门同时运行两个项目时会被后加载的那个覆盖。

## 2. 方案一句话

**一个主世界文件夹（连同里面所有子世界）共用一本记录本**，存在主世界文件夹里的单独文件，作为唯一权威；所有同时加载的项目共用内存里同一个实例。同一个编号在整棵世界树里永远指同一把枪，物品怎么被搬都不需要改编号。

已知的三个子世界模组都把子世界放在主世界文件夹之内，所以都被覆盖；以后的模组只要也这样放，就不需要再写适配。

## 3. 存在哪里、谁说了算

- **世界树的根**：`Worlds/` 下第一级目录（如 `app:/doc/Worlds/World1`）。子世界 `World1/Tartareosity`、`World1/Dimensions/Ancient`、`World1/Space_0` 的根都是 `World1`。不同的顶层世界（命令方块的 `world` 指令切换）互不共享。
- **权威文件**：`<根>/ScCsgoGuns.xml`：格式版本、树 ID（GUID）、代数（每次写入 +1）、记录本（记录、Next、成长规则、待结算击杀、补偿批次）、身份表、各世界的同步回执（见 §5）。写法同 1.5.1：校验过的临时文件 → 旧文件留 `.bak` → 同目录替换。
- **内存**：按根路径缓存一个共享实例；同一棵树的每个项目（含传送门的子项目）加载时拿同一个实例，最后一个项目释放时才卸下。`ScGunRegistry.Current` 指向它；`HolderLocator` 改为遍历这棵树当前加载的所有项目。
- **存档**：树里任何一个世界存档（`OnProjectXmlSaved`，在 Project.xml 落盘前）都写一次树文件；同时该世界 Project.xml 里**照旧写一份完整记录本**并标上树 ID + 代数——给旧版本读（§6），也作为树文件损坏时的后备。
- **读档优先级**：内存已有 → 用内存；否则读树文件；树文件缺失或损坏 → 从 `.bak`；再不行 → 从本世界 Project.xml 那份完整副本重建（并记日志）。
- **1.5.1 的记录副本**（`ScCsgoGunRecords.xml`）在新格式里由树文件取代；方块编号被占的改回逻辑保留（按世界做）。

崩溃一致性：树文件先于 Project.xml 落盘。若在两者之间崩溃，树文件更新：多出的记录没人持有，无害；物品状态（弹量等）可能比世界“新一点”——可接受，写进说明。

## 4. 现有存档的一次性合并

第一次用新版加载一棵已有多本记录本的树时：

1. 以**主世界**的记录本为基准，主世界物品的编号全部不变。
2. 扫描树里每个子世界的存档（`Project.xml` / `SpaceProject.xml` 里的枪械组），逐条按**身份**并入：
   - 身份已在主世界、型号相同 → 同一把枪，用主世界编号。状态取“物品现在在哪个世界就用那个世界的”；两边都有持有者或都没有 → 保留主世界的，另一份原样存为隔离记录（不丢）。
   - 身份不认识 → 分配新的树编号。
3. 每个子世界得到一张“旧编号 → 树编号”的对照表，存进树文件；该世界下次加载时把它里面的物品改号（尸鬼/远古在读档钩子里改 XML；传送门子项目没有读档钩子，在 CS 子系统加载完成时改活的库存），改完标记已完成，不会重复。
4. 认不出来、对不上的一律不猜：原样保留并标“记录异常、暂停使用”，进世界时提示数量。

**已经错位的旧枪**（玩家主世界 #1/#3）：按 §8 决定 2 处理。

## 5. 和旧版本（1.4.0～1.5.1）来回切换

项目规则要求任意两个正式版之间直接来回切换存档不出错、不丢状态。

- **新 → 旧**：每个世界的 Project.xml 都有完整记录本，旧版本照常读。树文件旧版本不认识，留在文件夹里不受影响。
- **旧 → 新**：旧版本存档时会按它自己的格式重写该世界的枪械组，树 ID/代数标记会丢。新版加载时据此判断“这个世界被旧版本玩过”，用同步回执（新版上次写入该世界时那份记录本的摘要）找出旧版本改过的记录：
  - 只有这个世界改过 → 采用它的新状态；
  - 旧版本在两个世界里各自新分配了同一个编号 → 后读到的那个世界里的物品改号；
  - 同一条记录在树里也被改过（冲突）→ 保留树里的，旧版本那份存为隔离记录，提示玩家。
- 旧版本里发生的跨世界搬枪错乱（旧版本本来就有的问题）回到新版时只按身份合并，**不保证修好**——如实写进发布说明。

## 6. 子世界模组适配的去留

- 同一棵树内的穿越：不再需要携带包、到达核对、编号映射，全部停用（物品编号在树内本来就通用）。
- 旧版本写下的携带包：读到时忽略（不再因为携带包里有坏枪拒绝整个世界——1.5.1 截图那类报错从根上消失）。
- 跨不同顶层世界搬枪（目前没有已知模组）：不支持；物品会显示“记录不存在”，原样保留，不拒绝加载。
