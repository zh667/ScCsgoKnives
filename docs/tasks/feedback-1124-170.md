## 1. 讨论记录（2026-11-24）

### 第 1 轮：玩家反馈 + 代码定位

用户转述的反馈（部分来自玩家，用户请我判断是否合理）：

1. 散弹枪：增加弹丸数；子弹远一点就消失 → 射程 +50%；末端最低伤害 30%；近距离对生物有击退。
2. 散弹枪换弹：等级高了弹仓变大，动画仍一发一发装，换弹时间特别长。
3. 装 C4 的匪从拿手枪改成举防爆盾（没掩体时像活靶子）；防爆盾耐久太高，削弱 50%；C4 爆炸要破坏补给箱并清空附近掉落物，否则玩家可以撤退后回来捡战利品。
4. 配件名拗口：握持组件→握把、精密机构→机械零件、光学组件→瞄准镜、金属胚件→胚件或金属件。
5. 把开箱模组 ScCsgoBox（https://github.com/zh667/ScCsgoBox）并入；能否动态获取其他模组物品并按稀有度设概率。

我在 main（1.6.0）代码里查到的事实：

- 射程：`gun_handling.json` 1 级射程 Nova 24 / XM1014 22 / MAG-7 20 / 截短 18 格，超过不算命中；`FalloffStart` 4~6、`MidDistance` 11~15（×0.4）、`FalloffFloor` 0.15。`ScGunGrowth.RangeScale` 每级 +25%，Lv10 起不限射程。枪械手感关闭时走 `ScSurvivalBalance.Falloff`：5 格内 1.0、15 格 0.4、25 格 0.15。
- 弹丸：`PelletPower = Power × Falloff / Pellets`，一枪总伤害平摊到弹丸上；弹丸数照 CS2（Nova 9、MAG-7/截短 8、XM1014 6）。加弹丸不加伤害，只让命中更稳。
- 击退：`ScSurvivalBalance.AttackWith` 子弹 `ImpulseFactor=0.6`（同一目标 0.8 s 冷却），刀 1.5。
- 换弹：管式装填只有 Nova/XM1014/截短（`ScReloadTransaction.IsTube`；MAG-7 是弹匣）。`BeginReload` 里 `shells = 容量 − 现有`，每发一个 `LoopLength`（Nova 0.433 s），`ShellTimes` 每个循环 `InsertShell()` 一发。`ScGunGrowth.Capacity` 到 Lv50 为 ×6.5（Nova 8 → 52 发 ≈ 22 s 以上）。开火可打断（`FinishReloadEarly`）。
- C4 匪：`TacticalRole.Demolition`，武器池是手枪（`TacticalEnemyState.Pools[4]`），五人队才有。敌方 C4 爆炸 `SubsystemTacticalBombs.Explode` 只伤人（有遮挡射线），不碰方块、不碰掉落物。
- 防爆盾：`ScTacticalShieldBlock.Life=2000`，磨损存在方块 data 里；`ScShieldProtection.Spend` 每次加 `ceil(伤害)`。敌人目前不能拿盾（盾判定读 `IInventory`，敌人装备在 `TacticalEnemyState`）。
- 配件名写死在 `ScWeaponMaterialBlock.Names`、`ScWeaponCrafting.Help`、`ScGunBlock`（维修提示）、`ScWeaponRepair` 注释、`SubsystemTacticalBombs`（拆弹奖励提示）、`tools/PackageCheck/SurvivalPackageIntegration.cs`、`tools/weapon_stats_report.py`、`tools/render_supply_review.py`。正确字是“坯”。
- ScCsgoBox：独立模组 0.3.5，约 930 行 C#，MIT（来源 Reclizer/CsgoBox），已有 `Assets/ScCsgoBox/Integrations/*.json` 联动机制（Stash 联动就是这么接的），奖池 33 条原版物品，**只支持单人**。

第 1 轮我的建议：射程 +50%、末端 30% 合理；不建议加弹丸（总伤平摊）；近距离击退只给散弹枪 5~6 格内，首领/大型生物设上限；换弹改成每循环装多发；匪举盾合理；耐久砍半最好改成“受到伤害 ×2”而不是改 2000 上限（旧存档磨损过半的盾不会读档就坏）；C4 清掉落物但不清玩家死亡掉落，空投箱按比例毁一部分而不是整箱消失；配件改名合理，和 #9 一起走语言文件；开箱可并入，其他模组物品不建议全自动（稀有度只能猜、可能抽到调试方块），建议联动文件 + 默认关闭的自动扫描。

### 第 2 轮：用户决定 + 新问题（铁太多）

用户决定：
- 防爆盾“一起”（匪的盾和玩家合成的盾都削弱），“那不如就改成受到的伤害 ×2”。
- 开箱“做成主包的一部分”。
- 1~4 条和开箱“一起做”（1.7.0）；“散弹枪，C4，配件改名都按照你的建议”；开箱加上 CS 武器的东西；“箱子的获取方式也得考虑好”。
- 新问题：玩家反馈配方用铁太多，只玩原版时铁比较少。

我查到的铁用量：金属坯件 = 8 铁锭 + 3 煤；精密机构 = 1 金属坯件 + 6 铜 + 2 锗（也等于 8 铁锭）。武器配方（`ScWeaponCrafting.Build`）按配件数折算：

| 物品 | 现在铁锭 | 建议后铁锭 |
|---|---|---|
| 新手手枪（格洛克等） | 32 | 14 |
| Nova / 截短 | 48 | 22 |
| AK / M4 | 88 | 34 |
| AWP | 104 | 42 |
| M249 / 内格夫 | 120 | 48 |
| 修满一把步枪（Lv0，Lv50 ×2） | 40（80） | 16（32） |
| 防爆盾（2 坯件 + 16 铁锭） | 32 | 24 |

第 2 轮我的建议：金属件 4 铁 + 2 煤；机械零件不再吃金属件，改 2 铁 + 4 铜 + 2 锗；匪/空投/开箱多给配件；钥匙改铜。开箱 CS 品质分档、传说档的枪按玩家等级过滤；获取：打匪 15%、普通生物 3%、空投必有 1 个、拆弹 1 个、升级 1 个（原 5）、坟墓/石堆保留。

## 2. 已确认设计（以用户确认为准）

### 2.1 散弹枪（玩家的散弹枪，生存规则）
- D1 射程 +50%，两条衰减路径都改：`gun_handling.json`（枪械手感开启）和 `ScSurvivalBalance.Falloff`（关闭）。
- D2 末端最低伤害 30%（原 15%）。
- D3 不加弹丸数，一枪总伤害不变。（散布收小 10~20% 是可选项，见待调参。）
- D4 5~6 格内对生物加击退；首领和大型生物有上限。

### 2.2 换弹
- D5 管式装填每个循环装 `ceil(当前容量 / 基础容量)` 发，最后一个循环只装剩下的；开火仍可打断。

### 2.3 C4 匪与防爆盾
- D6 装 C4 的匪（Demolition）拿防爆盾替代手枪，举盾推进放包。
- D7 防爆盾（匪的和玩家合成的）受到的伤害 ×2；不改 `Life=2000`，旧盾磨损值原样保留。
- D8 敌方 C4 爆炸清除范围内的掉落物，**玩家死亡掉落不清**。
- D9 范围内的空投补给箱按比例毁掉部分物资，不整箱消失。

### 2.4 配件改名（只改显示名，走语言文件，物品编号/数据值不变）
- D10 握持组件→握把，精密机构→机械零件，光学组件→瞄准镜，金属坯件→金属件；代码里所有写死这些名字的地方改从语言文件读。

### 2.5 铁用量
- D11 金属件 = 4 铁锭 + 2 煤。
- D12 机械零件 = 2 铁锭 + 4 铜锭 + 2 锗，不再消耗金属件。
- D13 匪掉落有概率直接掉金属件/机械零件；空投里放配件；开箱普通档放配件。
- D14 武器配方的配件数量不动。
- D15 开箱钥匙只用铜做。

### 2.6 开箱并入主包
- D16 开箱是 CS 主包（`zh667.ScCsgoKnives`，Full 和 Lite）的一部分，不做附加包。
- D17 奖励按 CS 品质分档：普通 = 配件、弹匣、霰弹、手雷；稀有 = 握把、瞄准镜、涂装材料、拆弹钳；史诗 = 枪械涂装模板、击杀计数器模板；传说 = 枪（**按玩家当前等级过滤，只给已能制作的枪**）；金色（约 0.5%）= 刀。原版奖励保留；联动文件机制（Stash）保留。
- D18 获取：打死匪 15%，打死普通生物 3%（只算玩家击杀、非创造），空投必有 1 个，拆弹成功 1 个，升级每级 1 个（原 5），坟墓/石堆保留。
- D19 钥匙铜制（同 D15）。
- D20 沿用独立版方块类名（`ScCaseBlock`、`ScCaseKeyBlock`）和子系统模板。独立 ScCsgoBox 没有公开发布过（用户 2026-11-24：“独立开箱模组我没公开发布，不用担心冲突问题”），所以**不做共存检测、不做独立版存档迁移**。独立仓库之后注明“已并入”（另行操作，不在本任务内）。
- D21 许可：并入 Reclizer 的 MIT 代码/资源要写进 `THIRD_PARTY_NOTICES.md` 和许可证文件。

### 2.7 首次做枪奖励
- D22 每玩家、每世界、每枪型首次在**武器装配台真正做出**时奖励 1 个箱子（取消、材料不足、失败都不给；创造模式不给）。
- D23 1.7.0 之前做过的枪，升级后第一次再做也算“首次”（每世界每玩家最多 35 个）。
- D24 所有枪都给 1 个，高级枪不多给。
- D25 背包满时掉在脚边（只掉一次）。
- D26 记录存在世界存档里，并在世界文件夹写一份副本（同 1.5.1 `ScGunRecordMirror` 的思路）；退出重进、卸载再装回都不重置、不重复。
- D27 联机由房主（服务器）记录和发放。
- D28 测试项：存档重进不重复；两个玩家各算各的；取消/失败不给；背包满只掉一次；卸载再装回记录还在。

## 3. 待确认 / 待调参（未经用户确认，不要当成已定）

数值（实现时放常量/数据表，便于调）：
- P1 散布收小 10~20%（可选，默认不改）。
- P2 射程 +50% 的范围：默认整条曲线（`Range`、`FalloffStart`、`MidDistance`）都 ×1.5，`MidMultiplier` 0.4 不变。
- P3 近距离击退：默认 ≤6 格、`ImpulseFactor` 1.5；上限条件默认“受 `ScProjectileDefense` 保护的首领”和 `ComponentBody.Mass ≥ 300` 的生物保持 0.6。
- P4 空投箱被 C4 波及时毁掉的比例：默认每格物品数 ×50% 向下取整（种子取自炸弹 ID，确定性）。
- P5 玩家死亡掉落保护：默认死亡点 4 格内、15 游戏分钟内的掉落物不清。
- P6 匪掉配件的概率：默认 50%（金属件 50% / 机械零件 30% / 握把或瞄准镜 20%）；原铁铜煤掉落保留。
- P7 空投固定加 1 份配件（金属件 2~3 + 机械零件 1），原随机资源表保留。

需要用户再定的小设计：
- Q1 防爆盾匪放完包后：默认收盾换手枪（用他原来的手枪变体）；盾打坏（磨损满）也换手枪。另一种是全程举盾不开枪。
- Q2 散弹枪改动是否也用于死亡竞赛：默认**只改生存**，死斗保持 CS2 原数值；敌方 NPC 散弹枪不变。
- Q3 C4 清掉落物只针对敌方 C4（`SubsystemTacticalBombs`），玩家自己放的 C4（`SubsystemScC4`）默认不变。
- Q4 箱子的九宫格合成配方（独立版 4 木板 + 4 铁锭 + 木箱）：默认保留但铁换成铜；也可以删掉只靠掉落。
- Q5 联机开箱：独立版只支持单人。默认 1.7.0 联机时箱子照常掉落/拾取，**开箱只在单人可用**，联机提示“联机暂不支持开箱”；做联机开箱需要另加网络协议。

## 4. 读代码时发现的冲突/风险

- R1 匪本来就有 40% 掉配件（70% 是金属坯件），空投资源表里也有金属坯件/配件；D13 是“提高并保证”，不是从无到有（P6/P7）。
- R2 敌人装备状态 `TacticalEnemyState` 用 JSON，1.6.0 读到新字段会忽略、存回时丢掉：盾的磨损在“1.7.0→1.6.0→1.7.0”往返后会回满。计划里让“有盾”由角色推出（Demolition 且还没放包），只多存一个磨损值，往返只丢磨损。旧存档里的 C4 匪升级后会举盾。
- R3 盾判定 `ScShieldProtection.Holding/Spend` 只认 `IInventory`；敌人举盾要加敌人分支，磨损写在敌人状态里（只服务器写），客户端靠 `PresentedValue` 画盾。
- R4 `gun_handling.json` 由 `tools/generate_gun_handling.py` 从 `docs/gun-handling-35-source-audit-2026-09-08.json` 生成，`tools/verify_gun_handling_release.py` 断言 `Range == proposal.maxRange`；直接改 json 会被校验拦下，要加一层 1.7.0 调整表。
- R5 一个模组只有一个 ModLoader（1.9.3.1 `ModEntity.Loader` 是单个）；独立版的 `OnCreatureDied/OnLevelUpdate/OnMinerDig/OnBlockDug` 要并进 `ScCsgoKnivesModLoader`。
- R6 ~~两个程序集同时定义 `Game.ScCaseBlock` 的共存问题~~：已取消，独立版未公开发布（见 D20）。
- R7 独立版升级奖励用内存记录上次等级（读档时只记录不发），没有持久化；1 个/级不变，但版本切换期间升的级在旧版里不发、回来也不补，符合“切换不额外发”。
