## 2. 交接提示中的设计（提议，非用户要求）与本轮取舍

交接提示提议：以 150 ms 区分点按/长按；按下后先进入“等待判断”、不播拉环；<150 ms 松键快投；≥150 ms 进入正常准备，“尚未准备完成就松键，沿用正常准备完成后的释放流程”；联机时携带时长/模式由服务器校验。

按 R3 核对本机 CS2 后**没有采用 150 ms 分类**，改用 CS2 自己的规则（证据见 §3）：

| 项 | 交接提示的提议 | 本轮实现 | 原因 |
|---|---|---|---|
| 判定 | 150 ms 阈值分两类 | **松键即投**：按下就开始拉环；任何时刻松键都立刻进入投掷；按住超过拉环时长才进入举手持握 | CS2 动画图里 `Throw` 是零过渡的全局过渡，数据里没有点按/长按阈值 |
| 按下后的画面 | 150 ms 内保持持物姿势，不播拉环 | 按下立即播拉环（与 CS2 相同）；点按只会看到拉环的头几帧就切到投掷 | 同上；也避免长按时动画整体晚 150 ms |
| 150–970 ms 之间松键 | 等完整拉环播完再投（最多再等约 0.8 s） | 松键时立刻投 | 用户要的是“点按秒投、长按有动画”，没有要求中等时长的按键补播拉环；CS2 也不补播 |
| 联机 | 传时长/模式，服务器判定点按或长按 | 服务器**不做**点按/长按判定：客户端在自己的投掷开始的那一帧告知服务器，服务器收到即投 | 没有分类就不存在“按消息间隔误判”的问题；线格式不变 |
| 力度/引信 | 不随按住时长变化 | 不变（已有检查） | 一致 |

如果实机后仍希望要“150 ms 内不显示拉环”或“中等时长按键补完拉环”的手感，是在 `ScGrenadePreparation` 上的小改动，请直接说。

## 4. 改动（实际）

- `ScGrenadePreparation`：松键后不再等 `ReadyAt`，当帧开始投掷（`Quick`）；`Pulled()` 给出拉环走到哪里；`EarliestThrowAt`：投掷物还在切出时就按下的，拉环照旧立刻开始，但出手不早于切出本应结束的时刻（也不晚于一次完整拉环）。
- `SubsystemScGrenades`：
  - 请求投掷时读取切出剩余时间（`KnifeAnimationController.GrenadeDrawRemaining`）交给时间线；
  - 拉环声改为归属拉环动作的声音（`ScPresentationSound.PlayHeld`），快投开始时 60 ms 淡出，不会“弹已出手还在响拉环”；出手声、点火后的燃烧瓶火焰显示不变；
  - 客户端发给服务器的“是否仍按住”改为“本端投掷是否已开始”（由本端输入与本端门禁决定），服务器收到即开始投掷；
  - 服务器：该客户端上一投已出手、只剩收手动作时到达的下一次开始，在其结束前 `ScNetGrenades.TailLead = 0.25 s` 内接受（两端各跑一遍同一个投掷，服务器晚一个链路延迟；否则早到一帧的开始会被拒绝，客户端显示投出而服务器没有生成）。
  - `ThrowPhase.Pull` 在投掷阶段保持“拉环结束时的进度”（完整拉环为 1，快投小于 1），供第三人称使用。
- `ScThirdPersonMotion.Throw`（原版人物两条刚性手臂）：快投从手臂当时的位置直接挥出，不先抬到举手位。CT/T 人物仍用 CS2 的世界片段（未改）。
- 提交、扣物、实体生成、轨迹、引信、伤害、投后切回、取消条件：未改，仍只走 `ScThrowTransaction`，每次动作至多提交一次。
- 线格式与协议号（6）不变；不同构建之间本来就由握手里的玩法构建标识互相拒绝，两端都要换成本候选。
- 物品说明与 README 一行文字改为“点按直接投出；按住则拉环准备”。

## 5. 交互规则（给玩家）

1. 手里拿着投掷物：**点一下**左键（强投）或右键（近抛）/手机的“强投”“轻投”按钮 → 松键的那一帧开始投掷，约 0–0.13 秒后出手（各投掷物投掷动作里自己的出手时刻）。
2. **按住** → 拉环/点火（约 1 秒）→ 举手持握，可一直瞄准，不会自动投出 → 松开才投。
3. 中途任何时刻松开都是立刻投，不补播剩下的拉环。
4. 刚切到投掷物就按：拉环马上开始，但最早在切出动作本应结束时出手。
5. 一次按键至多一颗；投出后要等投掷动作结束、下一颗拿到手上（或切回原武器）才能再投；力度、引信、数量规则都没有变。
